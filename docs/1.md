定价策略
适用于积分制 AI 视频生成产品的通用方法论

本文档用于说明如何为接入 Sora、Veo、Seedance、Wan 等模型的产品设计价格、积分和套餐结构。
目标不是给出唯一答案，而是提供一套可复用、可调整、可验证的定价框架。

如果你要把这套方法落到系统里，至少要同步检查以下几类配置：
- 价格与套餐配置
- 积分消耗规则
- 新用户赠送策略
- 支付与订阅配置

## 1. 定价前先回答三个问题

### 1.1 单次生成的真实成本是多少
不要只看模型 API 标价，还要把下面这些一起算进去：
- 模型调用成本
- 失败重试、超时重跑、队列重试
- 首尾帧、参考图、音频、字幕等附加能力
- 存储、CDN、审核、日志等平台可变成本
- 支付手续费、退款、风控损耗

建议先算出一个“单次真实成本”，再决定积分和售价。

### 1.2 用户为什么愿意为不同模型付不同价格
用户不是单纯为模型名称付费，而是为结果付费。影响用户支付意愿的核心因素通常包括：
- 生成质量
- 成功率和稳定性
- 出图或出视频速度
- 时长、分辨率、音频、可控性
- 是否适合商用或特定场景

### 1.3 当前阶段更需要利润还是增长
不同阶段，定价目标不同：

| 阶段 | 目标 | 定价倾向 |
| --- | --- | --- |
| 冷启动期 | 先验证转化和留存 | 可以适当保守毛利，降低尝试门槛 |
| 增长期 | 放大投放和订阅转化 | 保持可接受毛利，强调梯度和升级路径 |
| 稳定期 | 提高利润和 LTV | 控制优惠，优化高阶套餐结构 |

## 2. 成本与积分的基础公式

### 2.1 核心公式

```text
单次真实成本 = 模型成本 + 平台可变成本 + 支付/售后摊销 + 风险缓冲
目标售价 = 单次真实成本 / (1 - 目标毛利率)
积分消耗 = ceil(单次真实成本 / 每积分可承载成本)
```

其中：

```text
每积分可承载成本 = 基准模型成本 / 基准模型积分
```

### 2.2 风险缓冲建议
建议给真实成本额外加 5% - 15% 的缓冲，用来覆盖：
- 模型价格波动
- 失败重试
- 供应商计费误差
- 支付和退款损耗

### 2.3 毛利率参考区间
以下不是固定标准，而是常见参考：

| 产品类型 | 建议毛利率 |
| --- | --- |
| 一次性积分包 | 60% - 75% |
| 月付订阅 | 50% - 65% |
| 年付订阅 | 40% - 55% |
| 免费试用 | 可接受低毛利或视为获客成本 |

## 3. 模型分层方法

保留 Sora、Veo、Seedance、Wan 这些模型名称没有问题，但不要把定价逻辑绑死在某个网站或某个渠道报价上。更稳妥的做法是先给模型做定位，再根据你的真实进货成本映射到积分。

| 模型 | 常见定位 | 定价建议 |
| --- | --- | --- |
| Sora | 入门款、低门槛体验款 | 适合做试用、轻量任务或低价入口 |
| Veo | 标准主力款、默认推荐款 | 适合作为基准模型或主销模型 |
| Seedance | 灵活时长款、按秒变化款 | 不建议简单固定价，适合按秒或分段计费 |
| Wan | 高能力款、专业款 | 适合放到高阶套餐或高积分档位 |

注意两点：
- 模型名称可以保留，但实际积分必须以你的供应商报价和稳定性数据为准。
- 同一个模型在不同渠道、不同分辨率、不同功能组合下，真实成本可能差很多。

## 4. 积分系统怎么设计

### 4.1 先选一个基准模型
基准模型最好满足三个条件：
- 使用频率高
- 成本相对稳定
- 用户容易理解

很多产品会把 Veo 这一类“主销标准模型”当作基准，但不是必须。如果你当前的主销模型是 Sora 或其它模型，也可以按实际情况调整。

### 4.2 推荐的积分规则

| 场景 | 推荐计费方式 | 原因 |
| --- | --- | --- |
| 固定成本模型 | 固定积分 | 最容易理解，也方便营销 |
| 按秒计费模型 | 基础积分 + 每秒附加积分 | 避免短视频和长视频出现倒挂 |
| 高分辨率或附加音频 | 基础积分 × 系数，或单独加价 | 让高成本能力单独回收成本 |
| 图生视频、首尾帧、参考图 | 在基础积分上叠加附加积分 | 防止高级玩法被低价套利 |

### 4.3 不要把规则做得过于复杂
一个常见问题是积分系统太细，用户看不懂。建议：
- 前台最多展示 3 到 5 档核心差异
- 真正复杂的计费逻辑放在后台规则里
- 对用户只强调“效果差异”和“积分消耗差异”

## 5. 套餐结构怎么搭

推荐把产品拆成三层：
- 订阅：解决稳定复购和 LTV
- 积分包：解决临时需求和超额消耗
- 新用户赠送：解决首单转化门槛

### 5.1 月付订阅
月付通常是主转化产品，建议至少做三档：

| 档位 | 目标用户 | 设计原则 |
| --- | --- | --- |
| Basic | 轻度用户 | 单位积分价格最高，主要承担入门和转化作用 |
| Pro | 主力用户 | 作为主推档，单位积分价格比 Basic 低 10% - 15% |
| Ultimate / Max | 重度用户 | 强调最划算，但不要低到吃掉利润 |

### 5.2 年付订阅
年付的目标不是极限低价，而是提升现金流和留存。常见做法：
- 按月付的 10 倍定价，相当于送 2 个月
- 或直接给 15% - 20% 的年付折扣

如果你还在测试市场，年付不必一开始就压太低，否则后续调价空间会很小。

### 5.3 一次性积分包
积分包的原则应该是：
- 单位价格高于订阅
- 让不想订阅的用户也能下单
- 让订阅用户在积分不够时可以补充

常见建议：
- 积分包单价比对应订阅单价高 20% - 40%
- 小包面向新用户，高毛利
- 大包面向已付费用户，用于补量，而不是替代订阅

## 6. 把模型映射到套餐的思路

一个更稳妥的做法，不是直接问“某模型卖多少钱”，而是问“某模型应该落在哪一层价值带里”。

### 6.1 可以这样理解
- Sora：适合做低门槛入口、试用体验、轻量任务
- Veo：适合作为主销标准款，承担大部分生成需求
- Seedance：适合按秒、按时长计费，不建议硬塞进简单固定档位
- Wan：适合做高阶功能、专业场景或高客单价能力

### 6.2 一个简单的映射原则
- 低成本模型用于拉新和体验
- 中成本模型用于主销和订阅转化
- 高成本模型用于高阶档位和增购能力
- 波动成本模型尽量做动态计费，而不是死给固定积分

## 7. 新用户策略

新用户赠送不是越多越好，而是要让用户体验到价值，同时不把成本送穿。

### 7.1 赠送原则
- 优先赠送最低成本且成功率稳定的模型
- 控制有效期，避免长期沉淀负债
- 免费额度只解决“第一次成功体验”，不要覆盖完整生产需求

### 7.2 对模型的常见处理方式
- Sora：如果是你当前最低成本且稳定的入口模型，可以优先用于试用
- Veo：可以用于首单展示，但不建议默认大量赠送
- Seedance：如果按秒计费，试用时要严格限制时长
- Wan：通常不适合作为常规免费额度

### 7.3 赠送配置的思路
可以控制以下几个变量：
- 赠送积分数量
- 有效天数
- 可用模型范围
- 是否要求注册后领取
- 是否要求首单前使用

## 8. 调价与迭代流程

### 8.1 上线后重点监控的指标
- 实际模型成本与预估成本的偏差
- 各模型的使用分布
- 各套餐的毛利率
- 新用户到付费用户的转化率
- 积分消耗速度和退款率

### 8.2 触发调价的典型信号

| 情况 | 建议动作 |
| --- | --- |
| 实际毛利持续低于目标 | 提高价格或提高积分消耗 |
| 某模型用量暴涨且低利润 | 调高该模型积分，或限制低价套餐使用 |
| 用户普遍卡在低档套餐 | 重做中档套餐的价值感知 |
| 年付占比过低 | 优化年付折扣或补充年付权益 |
| 积分包替代了订阅 | 提高积分包单价或限制购买条件 |

### 8.3 不要直接改线上老产品
正确做法是：
- 创建新的套餐版本
- 新用户进入新版本
- 老用户保留原权益或引导升级
- 逐步迁移，而不是一次性硬切

## 9. 常见问题

### Q1：基准模型一定要选 Veo 吗？
不一定。Veo 常适合做基准，是因为它通常容易被理解为“标准主力款”。但如果你的主销模型不是 Veo，就应该选你的主销模型做基准。

### Q2：Seedance 这种按秒计费的模型怎么卖？
优先考虑“基础积分 + 时长增量”，或者按区间定价。不要让长视频和短视频共用同一口价，否则很容易亏损。

### Q3：Wan 这种高成本模型能不能放进基础订阅？
可以放，但不要无限制开放。更合理的方式是：
- 提高积分消耗
- 只对高档订阅开放
- 或作为单独增值能力收费

### Q4：年付折扣给多少合适？
大多数场景下，15% - 20% 是相对稳妥的区间。想简化表达时，也可以直接采用“月付 × 10”的规则。

### Q5：如何判断当前定价是否健康？
至少同时满足三点：
- 用户能看懂差异
- 主力套餐有明显升级理由
- 高成本模型不会被低价套餐套利

## 10. 落地清单

在真正配置价格前，建议逐项确认：
- 是否已经拿到 Sora、Veo、Seedance、Wan 的真实渠道成本
- 是否已经把失败重试、支付手续费和退款损耗算进去了
- 是否已经选定一个基准模型和基准积分
- 是否已经确定月付、年付、积分包之间的单价梯度
- 是否已经限制高成本模型的免费和低价使用方式
- 是否准备好后续调价时使用的新套餐版本号
