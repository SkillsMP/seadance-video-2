# 新增模型接入改动清单

## 结论

当前仓库已经落地了可信模型注册表，新增图片 / 视频模型时，默认只需要改两类地方：

1. 业务定价源：`docs/定价/3.本项目定价方案.md` 第 3 节「模型积分消耗表」。
2. 代码注册表：`src/config/ai/models.ts` 的 `MODELS`。

只有当新模型的供应商协议、请求字段、查询结果或可用性判断发生变化时，才继续改 provider adapter、AI service、环境配置或前台文案。前台套餐表和 pricing JSON 默认不改，因为套餐表只决定用户怎么买 Credits，模型表决定每次生成扣多少 Credits。

注意：`docs/定价/3.本项目定价方案.md` 第 3 节当前是「规划 wishlist + 实际配置」混合状态，真正已开放的模型以 `src/config/ai/models.ts` 中 `enabled: true` 的条目为准。如果定价文档里已经有对应 family，只需要校正该行并在注册表里落地；如果定价文档里没有，先补文档行，再补注册表。

---

## 当前代码事实

新增模型时先按当前代码事实判断，不要按旧文档里的三处手工同步方式操作：

| 能力 | 当前实现 |
|---|---|
| 模型选择源 | `src/config/ai/models.ts` |
| 图片生成器模型列表 | `src/shared/blocks/generator/image.tsx` 从 `MODELS` 过滤 |
| 视频生成器模型列表 | `src/shared/blocks/generator/video.tsx` 从 `MODELS` 过滤 |
| 扣费配置 | `src/config/ai/credit-costs.ts` 从 `MODELS` 派生 family override，并保留 scene fallback |
| 后端白名单校验 | `src/app/api/ai/generate/route.ts` 用 `findModel(mediaType, provider, family, scene, model)` 校验 candidates |
| 强制规格 | `MODELS[].enforced[scene]` 在后端合并，客户端不能覆盖 |
| 注册表自检 | `src/shared/services/ai.ts` 调用 `validateModels()` |
| 独立校验脚本 | `pnpm ai:validate-models` 会直接运行 `validateModels()` 并在错误时退出 1 |
| 生产环境自检 | `validateModels()` 在生产环境只 `console.error`，不阻断服务 |
| AI callback | `/api/ai/generate` 会传 `/api/ai/notify/[provider]`，但当前 AI notify 路由尚未实现 |

因此，图片 / 视频模型不要再分别手工维护 `MODEL_OPTIONS` 和 `credit-costs.ts` 的 family override。它们应该从 `models.ts` 自动得到。

## 新增前必须先定清楚

新增任何模型前，先把这些信息定下来：

| 字段 | 要求 |
|---|---|
| `mediaType` | `image` / `video` / `music` |
| `family` | 计费 SKU key，必须稳定；影响价格的规格要拆独立 family |
| `value` | 真实传给供应商 API 的 model id |
| `label` | 前台展示名 |
| `provider` | 当前 provider 名，如 `kie` |
| `scenes` | 支持的场景，如 `text-to-image`、`image-to-video` |
| `credits` | 每个 scene 的扣费，必须来自定价文档第 3 节 |
| `enforced` | 会影响成本或定价预期的强制参数，如 `resolution`、`duration`、`generate_audio` |
| `enabled` | 是否对前台和后端校验开放；可先 `false` 隐藏，确认后再切 `true` |
| 成本边界 | 是否低成本、是否可进免费额度、是否只给付费用户、是否需要白名单 |

核心规则：

- 影响价格的规格 = 新 family / 新 SKU。
- 不影响价格的用户选项 = 保留为普通 options。
- 高成本 route 不要塞进已有低价 family 的 fallback 链路。
- 同一个 `(mediaType, family, scene)` 下所有 provider 的 credits 必须一致。
- 同一个 family 内所有 candidate 的 `credits[scene]` 必须完全一致；后端扣费只读取第一个 candidate 的积分（这也是 `validateModels()` 校验同 family 同 scene credits 不能漂移的原因——它们本质上是同一个 SKU 价格）。
- `MODELS` 顺序会影响同 family 的展示名称和 fallback 优先级。同一个 family 下的多 provider entry，`label` 应保持一致；低成本、稳定 route 放前面，高成本 route 不要混入低价 family。

## 必改位置

### 1. 更新业务定价源

文件：

```text
docs/定价/3.本项目定价方案.md
```

只改第 3 节「模型积分消耗表」，新增一行或多行，明确：

- 媒体类型。
- 模型 / 能力名称。
- 代码 family key。
- 场景。
- 积分。
- 类型 / 定位。
- 保守参考成本。
- 标称价值。
- 说明，包括 provider route、固定规格、免费额度边界。

默认不改第 4 节「前台套餐表」。只有 Credits 售卖方案、套餐数量、套餐价格、发放周期变化时，才改前台套餐表和 pricing JSON。

如果第 3 节已经有对应模型行，先判断它是规划条目还是已上线条目。规划条目不等于代码可用；只有写入 `src/config/ai/models.ts` 且 `enabled: true` 后，前台和后端才会把它当作可用模型。

### 2. 更新可信模型注册表

文件：

```text
src/config/ai/models.ts
```

新增一个或多个 `ModelEntry`。同一个前台 family 支持多个真实 provider model 时，可以多条 entry 共用 family；不同 scene 扣费不同时，要分别在 `credits` 中写清楚。

示例：

```ts
{
  mediaType: 'video',
  family: 'new-video-720p',
  value: 'provider/new-video-model',
  label: 'New Video 720p',
  provider: 'kie',
  scenes: ['text-to-video'],
  enabled: true,
  credits: { 'text-to-video': 90 },
  enforced: {
    'text-to-video': {
      resolution: '720p',
      duration: 5,
      generate_audio: false,
    },
  },
}
```

`enforced` 只放成本敏感或定价敏感字段。比如分辨率、时长、是否原生音频应该放；单纯画幅比例通常不放。

如果 family key 或定价文档声明了固定分辨率、时长、音频开关，这些字段必须写入 `enforced`，并在 `ai_task.options` 中验收确认。不要把 provider adapter 默认值当作定价规格保证。

`enabled: false` 只能用于隐藏入口，不等于完整验证。因为当前 `validateModels()` 只校验 enabled 模型，所以切到 `enabled: true` 后必须在开发环境或 CI 跑一次 `pnpm ai:validate-models`。

当前 `label` 是硬编码英文，并直接显示在图片 / 视频生成器里。如果模型名需要多语言展示，需要另行扩展 i18n 方案，不要把翻译逻辑塞进 provider adapter。

## 按情况改的位置

### A. 已有 provider，但新模型协议完全相同

只需要改：

```text
docs/定价/3.本项目定价方案.md
src/config/ai/models.ts
```

然后验证前台模型下拉、扣费提示、生成请求和后台扣费。

### B. 已有 provider，但新模型请求字段不同

额外检查并可能修改：

```text
src/extensions/ai/kie.ts
src/extensions/ai/<provider>.ts
```

典型场景：

- 图片输入字段不同，如 `image_input` vs `image_urls`。
- 视频时长字段不同，如 `duration` vs `n_frames`。
- 视频输入字段不同，如 `image_urls` / `reference_video_urls`。
- 查询结果结构不同，需要调整 `queryImage` / `queryVideo` 的解析。
- 供应商要求某些固定参数，但这些参数属于 provider 私有协议。
- provider adapter 里按真实 model id 索引的映射表需要补值，例如 `KIE_IMAGE_FIELD`、`KIE_VIDEO_DURATION_FIELD`。

原则：provider 私有字段映射放在 provider adapter 内，不要污染通用模型注册表。注册表只放跨前后端都需要知道的模型、扣费、场景和强制规格。

### C. 新增全新 provider

除了业务定价源和注册表，还通常要改：

```text
src/extensions/ai/<provider>.ts
src/extensions/ai/index.ts
src/shared/services/ai.ts
src/app/api/ai/providers/route.ts
src/shared/services/settings.ts
.env.example
必要时补 admin settings 的 i18n 文案
```

需要完成：

- 实现 `AIProvider` 的 `generate()`。
- 如果 `generate()` 返回 pending / processing 异步任务，必须实现 `query()`；否则前端轮询 `/api/ai/query` 拿不到 `taskStatus`，任务无法完成。只有同步返回 `SUCCESS` 且前端不再轮询的模型，才可以不实现 `query()`。
- 注册 provider export。
- 在 `getAIManagerWithConfigs()` 中按配置初始化 provider。
- 在 `/api/ai/providers` 中返回可用 provider。
- 在 `src/shared/services/settings.ts` 增加 API key / custom storage 等配置项，确保 `getAllConfigs()` 能读取环境变量或后台配置。`getAllConfigs()` 通过 `getAllSettingNames()` 从 `settings.ts` 获取所有合法 config key 列表，再从环境变量中读取对应值；如果 `settings.ts` 里没有注册该 key，env var 不会被读入 `configs`，`getAIManagerWithConfigs()` 就拿不到 API key。
- 在 `.env.example` 增加对应环境变量；如果后台 settings 页面需要展示新配置项，补 admin settings 的 i18n 文案。
- 确认 callback URL、任务查询、结果解析、失败状态映射、文件转存都能跑通。

如果新 provider 的成本明显高于当前低价 route，不要沿用低价 family。优先拆独立 family。

当前 `src/app/api/ai/notify/[provider]/route.ts` 尚未实现。新增 provider 时必须先确认它是轮询 `query()` 路径还是强依赖 callback。如果 provider 强制 callback，需要先补 AI notify 路由；否则 provider 回调到 `/api/ai/notify/[provider]` 会 404。

### D. 新增 music 模型

当前 music 还没有完全纳入图片 / 视频的 candidates 注册表链路，前端也仍有固定扣费：

```text
src/shared/blocks/generator/music.tsx
```

新增 music 模型不要套用图片 / 视频的默认流程。当前 music 的实际状态是：

- 前端 `costCredits` 是硬编码。
- 前端请求走 `provider + model`，不传 `family + candidates`。
- 后端把 music scene 固定为 `text-to-music`，并走旧的 provider/model 路径。
- music 没有通过 `findModel()` 做注册表白名单校验。

因此新增 music 模型只有两条路：

1. 沿用旧路径：明确修改 music 前端 model、provider、`costCredits`，并确认后端 `provider + model` 可执行。
2. 先升级 music：把 music 纳入 `MODELS`、前端 cost 读取、后端 candidates 校验，再新增模型。

不要只在定价文档里加 music family 就认为已经接入。

### E. 新增全新 scene 类型

如果新增的是全新 scene，而不是现有 `text-to-image`、`image-to-image`、`text-to-video`、`image-to-video`、`video-to-video`、`text-to-music`，还需要同步检查：

```text
src/config/ai/credit-costs.ts
src/shared/blocks/generator/image.tsx
src/shared/blocks/generator/video.tsx
src/app/api/ai/generate/route.ts
```

至少要补：

- `GenerationScene` 类型。
- `DEFAULT_SCENE_CREDIT_COSTS` 兜底值。
- 前端 tab 类型、UI 分支、上传字段和请求参数。
- 后端 scene 校验和 provider options 映射。

没有兜底积分的 scene 不要上线。

## 默认不改的位置

新增模型时通常不要改这些地方：

| 文件 / 模块 | 原因 |
|---|---|
| `src/config/locale/messages/en/pages/pricing.json` | 套餐不因新增模型变化 |
| `src/config/locale/messages/zh/pages/pricing.json` | 同上 |
| `docs/定价/3.本项目定价方案.md` 第 4 节 | 前台套餐表只管买 Credits |
| 支付 checkout / webhook | 新模型不改变支付链路 |
| 积分账本模型 | 新模型只改变扣多少，不改变账本语义 |
| `src/config/ai/credit-costs.ts` | 图片 / 视频 family override 已从 `MODELS` 派生，除非改 scene fallback |
| 图片 / 视频生成器本地 `MODEL_OPTIONS` | 当前已经从 `MODELS` 读取 |

如果新增模型导致 pricing 页面要调整文案，只改产品化文案，不展示供应商、成本、毛利、route、fallback 或完整内部扣费矩阵。

## 落地步骤

1. 从供应商文档或实际报价确认真实 model id、输入输出协议、成本、规格限制。
2. 判断定价文档第 3 节是否已有对应 family：有则校正该行，没有则新增模型扣费行。
3. 在 `src/config/ai/models.ts` 新增 `ModelEntry`，确保 `family`、`scene`、`credits` 和文档一致。
4. 初次接入可以先 `enabled: false` 隐藏入口；准备联调时切 `enabled: true` 并跑注册表校验。
5. 如果有成本敏感规格，把它写入 `enforced`，不要只靠前端默认值。
6. 如果 provider 协议有差异，更新对应 `src/extensions/ai/<provider>.ts` 的字段映射或查询解析。
7. 检查 provider adapter 中按 model id 索引的映射表，新 `value` 是否需要新增映射。
8. 如果是新 provider，完成 provider 实现、导出、初始化、可用性接口和配置项。
9. 如果 provider 依赖 callback，先补 `/api/ai/notify/[provider]`；否则确认 `query()` 轮询链路可用。
10. 打开前台图片 / 视频生成器，确认新模型只在支持的 scene 和可用 provider 下出现。
11. 发起生成请求，确认请求体包含 `family + scene + candidates`，后端能通过 `findModel`。
12. 检查 `ai_task` 记录：`provider`、`model`、`scene`、`costCredits`、`options` 符合预期，`options` 应包含后端合并后的 `enforced`。
13. 运行 `pnpm ai:validate-models`、类型检查和 lint；不要依赖生产环境 `validateModels()` 自动阻断错误配置。

## 验收清单

| 检查项 | 通过标准 |
|---|---|
| 业务定价 | `docs/定价/3.本项目定价方案.md` 第 3 节已新增或调整模型行 |
| family key | 文档里的 `代码 family key` 和 `src/config/ai/models.ts` 完全一致 |
| 注册表校验 | `pnpm ai:validate-models` 通过；无缺失 credits、重复 entry、同 SKU 不同价 |
| 前台展示 | 图片 / 视频生成器能在正确 scene 展示模型，错误 scene 不展示 |
| 扣费提示 | 前台 cost 来自 `getGenerationCreditCost()`，不是硬编码 |
| 后端校验 | `/api/ai/generate` 对非法 `family + scene + candidate` 会拒绝 |
| 扣费记录 | `ai_task.costCredits` 等于注册表中对应 scene 的 credits |
| 强制规格 | 成本敏感参数由后端 `enforced` 合并，客户端不能绕过 |
| provider 协议 | 新模型请求字段、callback、query、失败状态、结果解析都通过 |
| 异步查询 | 异步 provider 已实现 `query()`，`/api/ai/query` 能拿到 `taskStatus` |
| callback 策略 | 如果 provider 强制 callback，已实现 `/api/ai/notify/[provider]`；否则确认轮询 query 可用 |
| provider 配置 | 新 provider 已补 `src/shared/services/settings.ts`、`.env.example`、`/api/ai/providers` 和 service 初始化 |
| 成本边界 | 高成本 route 没有混入低价 family fallback |
| scene 类型 | 新 scene 已补类型、兜底扣费、前端 UI 和后端映射 |
| pricing | 未误改套餐价格、支付 product id、checkout 或 webhook |

## 常见错误

- 用展示名猜 `family`，导致前后端 family 不一致。
- 只给 family 写了一个 credits，漏掉另一个 scene。
- 把 1080p、4K、长时长、原生音频当普通 option，低价 family 被高配请求打穿。
- 把高成本 provider 作为低价 family fallback。
- 手工改 `credit-costs.ts`，但忘记 `models.ts`，或反过来造成漂移。
- 前端传 `costCredits`，让客户端参与定价。
- provider 私有字段写进通用注册表，导致注册表变成 API 协议拼装器。
- 新 model value 没有补 provider adapter 的字段映射表，结果走了错误默认字段。
- 以为 `enabled: false` 已经经过注册表校验，实际当前校验只覆盖 enabled 模型。
- 以为生产环境会阻断错误注册表，实际生产只打 log。
- 只跑 `pnpm lint`，没有跑 `pnpm ai:validate-models`，注册表错误没有被提前发现。
- 忘记当前 AI notify 路由不存在，导致 provider callback 404。
- 把定价文档里的规划模型当成已接入模型，实际 `models.ts` 没有 enabled 条目。
- 同一个 family 下的多 provider entry 使用不同 `label`，前台展示名随顺序漂移。
- 把 provider adapter 默认值当作定价规格保证，导致实际请求没有锁定 720p / 480p / 5s / 无音频。
- 新增异步 provider 时没实现 `query()`，前端轮询一直无法完成。
- 新增 provider 时只改 `.env.example`，漏掉 `src/shared/services/settings.ts`，`getAllConfigs()` 读不到配置。
- 新增全新 scene 时只改文档和注册表，漏掉 `GenerationScene`、fallback、前端 tab 和后端映射。
- 新增 provider 时忘记 `/api/ai/providers`，前台认为 provider 不可用。
- 新增 provider 时忘记 `.env.example` 或后台配置，生产环境无法初始化。
