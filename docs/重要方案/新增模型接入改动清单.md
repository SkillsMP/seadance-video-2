# 新增模型接入改动清单

> 适用：Seadance / ShipAny Two，图片与视频生成主链路。  
> 修订：2026-10-09。代码核对基准（非最新提交保证）：`SkillsMP/seadance-video-2`，提交 `3fc37a094d361591acb5dc1f67cc553ae4d37a58`。  
> 定位：唯一的日常模型接入规范；不是生产上线证明，也不是架构重构任务书。  
> 使用：直接维护本文件；常规模型不再另写长篇接入方案。特殊能力确需方案时，在本文件保留入口。
> 配套：`docs/重要方案/项目技术风险与待办清单.md` 与本文**一起入库**，保持同目录，避免相对链接失效。文件和数据流看 [项目速览](./项目速览.md)。

## 0. 快速入口

**先复用，再适配；只开放已验证、已定价的能力。**

常规模型优先修改业务定价源与模型注册表；不是“强制只改两个文件”。协议、输入约束或测试有差异时，补最小必要改动。

**文档分工**：本文件只管“以后如何接入模型”；已有代码问题统一记录到 [项目技术风险与待办清单](./项目技术风险与待办清单.md)。**遗留风险不是每次新增模型的默认任务**；只有直接阻断本模型的协议、输入安全、计价或正常完成时才关联处理。

| 类型 | 判断 | 通常改动 |
|---|---|---|
| A：配置型 | 已有 Provider、已有场景，创建/查询协议与输入及计费模式均兼容 | 定价文档第 3 节 + `models.ts`；补必要测试 |
| B：适配型 | 已有 Provider，但字段、模式、结果或约束有差异 | A + 对应 adapter；必要时补 `options.ts` |
| C：能力扩展型 | 新 Provider、新 scene、新输入资产或新计费方式 | 先说明能力缺口，再局部扩展；不混入全面重构 |
| 特殊媒体 | Music / Speech 等未走相同主链路 | 单独核对真实入口、鉴权和扣费，不套用 A |

固定流程：

```text
读取当前代码与本文件
→ 按 scene 核对 API、输入限制与成本
→ 确认业务价格，写合法的禁用配置
→ 最小适配与隔离契约测试
→ 本地/测试环境临时启用，验证完整站内链路
→ 完成经授权的低成本真实生成与账单核对
→ 经授权启用生产、观察、保留回滚路径
```

**必须区分**：
- `enabled: false`：禁止普通入口和后端模型查找，不是测试白名单或完整灰度功能。
- Provider 脚本成功：只证明该脚本调用成功，不证明站内鉴权、审核、扣费、历史记录已接通。
- 代码启用：不等于已部署或生产验证通过。
- 文档与代码矛盾：记录差异，按最新协议和明确业务决策修正；不能把现有 bug 当规范。

## 1. 事实源与改动边界

| 信息 | 依据 |
|---|---|
| 当前实现 | 当前工作分支代码；先检查本地未提交/未 push 的变化 |
| 模型用户售价 | `docs/定价/3.本项目定价方案.md` 第 3 节 |
| 参数能力与供应商成本 | 目标 Provider 的最新官方文档、报价及授权实测；注明日期 |
| 实际运行 | 部署提交、环境配置、真实任务与账单 |
| 历史设计 | H3、Mini 旧方案及架构文档，只作背景参考 |

模型表决定“生成扣多少积分”；套餐表决定“用户怎么买积分”。常规接入不修改套餐价格、支付产品 ID、checkout、支付 webhook、积分账本结构。

不把供应商成本、API Key、完整原始请求日志放进前台配置。本站积分与供应商 credits 不是同一单位；本文件不重复维护价格表。

## 2. 每次接入的信息卡

信息卡写在当前任务说明/PR 中即可，不另建一套长期规范。**按 scene 分别填写真实 model ID、能力与价格，不能只填一个总 ID。** 以下是待填模板，不是可直接上线的配置。

```yaml
model_name: ""
family: ""                   # 稳定产品 key，不拼分辨率/时长
provider: ""
media_type: "video"
checked_at: ""
official_documentation: ""
v1_scope: ""
excluded_scope: ""
trial_credit_policy: ""       # 是否允许使用赠送/试用积分；业务决策，不自动新增权限系统
routes:
  - scene: "text-to-video"
    provider_model_id: ""
    defaults: {}
    allowed_controls: {}     # 分辨率、时长、画幅、音频等；保留精确类型和大小写
    input_constraints: {}    # 必填、模式、数量、格式、大小、时长和互斥规则
    payload_mapping: {}      # 业务字段 -> 上游字段
    forbidden_fields: []
    supplier_cost_basis: ""  # 输出/输入时长、音频、图片数等如何计费
    site_pricing_reference: "" # 定价文档第 3 节对应行
  - scene: "image-to-video"
    provider_model_id: ""    # 即使与文生相同，也明确写出
    defaults: {}
    allowed_controls: {}
    input_constraints: {}
    payload_mapping: {}
    forbidden_fields: []
    supplier_cost_basis: ""
    site_pricing_reference: ""
task_contract:
  create_endpoint: ""
  query_endpoint: ""
  provider_task_id_field: ""
  success_failure_mapping: ""
  result_url_field: ""
  callback_strategy: ""      # 不发送 / 有真实接收端；注明验证方式
verification:
  unresolved: []
  paid_test_authorization: "" # 环境、预算上限、测试账号；无授权不产生费用
  production_enable_authorized: false
```

删除不开放的 scene。未知参数保留在卡片中为“待核实”，**不要用旧模型价格、随便的秒数或 0 价格凑出 ModelEntry**。

## 3. 代码定位与字段职责

| 位置 | 职责 | 何时修改 |
|---|---|---|
| `src/config/ai/models.ts` | 模型、场景、控件、默认值、输入约束、价格 | 新增/调整模型 |
| `src/config/ai/options.ts` | 参数清洗、最终参数合并、图片模式与模型输入约束 | 现有输入语义不足时 |
| `src/config/ai/generation-pricing.ts` | `finalOptions + costCredits` 及候选一致性 | 计价流程变化时 |
| `src/config/ai/credit-costs.ts` | 根据 `pricing` 计算本站积分 | 新计费方式时，不维护第二份价格表 |
| `src/extensions/ai/<provider>.ts` | 请求构造、调用、状态/结果转换 | 上游协议不同 |
| `src/shared/blocks/generator/` | 模型选择、控件、素材输入、任务展示 | 新交互能力时 |
| `src/app/api/ai/generate/route.ts` | 鉴权、白名单、审核、创建与扣费编排 | 通用入口有真实缺口时 |
| `src/app/api/ai/query/route.ts` | 查询、输出审核、状态更新 | 通用任务链路变化时 |
| `src/shared/models/ai_task.ts` / `credit.ts` | 任务与积分事务、失败退款 | 独立可靠性修复，不随接模型重写 |
| `src/shared/services/ai.ts` / `settings.ts` | Provider 初始化、合法配置键 | 新 Provider 时 |

`family` 负责稳定的产品选择；`value` 是真实上游 model ID。不同 scene 使用不同上游 ID 时，拆成多条 entry，共用 family。

`controls` 规定允许选择的值；`defaults` 规定默认值；`enforced` 只表达确实锁定的策略。**影响价格不等于一律锁死**：可选分辨率/时长应由 `controls + pricing` 校验并计价。

`inputConstraints` 只具有当前代码实现的含义：
- `imageModes`、`imageInputRequired`、`promptRequired` 可参与服务端语义检查。
- `uploadMaxSizeMB` 主要用于上传 UI，不能证明任意外部 URL 的真实大小已由服务端验证。
- 图片数量目前由 `assertVideoImageInput()` 等实现；写一个不存在的配置字段不会自动生效。

`pricing` 是图片/视频执行扣费来源。`credits` 仍有兼容与配置校验用途，不能用它替代视频动态计价，也不要借接新模型顺手调整旧模型的兼容值。

分辨率可用性位于定价项内部，例如视频 `pricing[scene].byResolution[resolution].availability`、图片 `pricing[scene].byImageResolution[resolution].availability`，**不在 pricing 顶层**。`candidate/whitelist` 不会自动提供内部测试权限；当前计价路径仅接受 `enabled` 的规格，不要把状态名称当作已实现的白名单。

同一 `(mediaType, family, scene)` 的 fallback 候选须保持价格和公开输入契约一致；当前代码还校验 `controls/defaults/enforced/inputConstraints/pricing/skuAttributes`。高成本、不兼容 route 不塞进低价 family。

**候选顺序与展示**：`MODELS` 的条目顺序会影响前端默认候选顺序和展示；同 family 的候选保持一致 `label`。当前服务端按请求携带的 `candidates` 顺序尝试，**不会自动按供应商成本排序**。

## 4. 最小实施规则

### 4.1 注册与定价

先更新定价文档第 3 节，再同步注册表；优先复用相近的 catalog/factory，但逐项核实默认值与能力，不整段照抄。

当前普通视频计价是：

```text
本站积分 = finalOptions.duration × 当前 scene/分辨率的 creditsPerSecond
```

这里的 `duration` 是服务端确认的请求输出时长，**不是自动测量的实际生成时长，也不自动包含参考视频时长**。

必须核对输入视频、音频、图片附加费、输出数量、自动时长等成本。`inputBilling` 是场景元数据，不会自动测量素材或完成复杂计费。

若供应商按“输入视频时长 + 输出时长”收费，可选择：
- 在可验证的输入上限下制定足以覆盖成本的本站价格；
- 或取得可信输入时长后明确扩展计费；
- 尚未实现时不开放相关能力。不能信任客户端自报时长。

不必为所有成本差异都增加一个计费框架。合并售价也可以，但须有保守成本与套餐最低实际单积分售价的压力测试依据。

### 4.2 Provider 适配

先检查创建、查询、状态和结果是否兼容，再判断是否只需注册模型。

- 显式核对 `duration/n_frames`、图片字段、首尾帧顺序、参考字段互斥。
- 数值/字符串、分辨率大小写、`false` 都要原样正确映射。
- 只构造允许的上游字段，不将 `finalOptions` 整体展开进 payload。
- 网站内部字段、用户积分、供应商成本不发送给上游。
- 协议相同复用现有 builder；协议不同补小型专用 builder，不做跨 Provider 通用协议语言。
- 不在 adapter 私自更改客户选择、增加计费默认值或静默降配。
- “创建请求超时”可能只是未收到响应，不能等同于“上游肯定没创建”；没有幂等保障时不盲目重试付费 POST。

### 4.3 输入、安全与界面

前端呈现约束，后端再次校验，adapter 负责协议转换。不能只隐藏按钮。

新增资产类型时同步检查：scene 白名单、必填/数量/互斥、URL 安全、上传接口鉴权与容量限制、内容审核、Provider 映射。Prompt 不属于 options，必填和长度校验在相应入口处理。

复用 `generation-controls.ts`、图片输入组件与现有生成器；模型切换保留草稿，非法素材组合禁用提交。增加用户文案时同步 en/zh。

### 4.4 新 Provider / 新 scene / 特殊媒体

新 Provider 通常涉及：
`src/extensions/ai/<provider>.ts`、导出、`src/shared/services/ai.ts`、`src/shared/services/settings.ts`、`.env.example` 与 `src/app/api/ai/providers/route.ts`。

API Key 只补 env 不够；核对合法配置键是否被 `getAllConfigs()` 读取，并加入 `/api/ai/providers` 的可用性列表。**该接口当前只按配置键是否存在来判断，不能证明 Key 有效、余额充足或模型调用权限正常**。异步 Provider 必须有可用查询路径；同步结果也须符合当前任务 ID/存储/审核契约。

新 scene 补类型、输入与计费路径、UI、服务端验证和映射；**图片/视频未命中 pricing 必须拒绝，不新增 legacy 免费/固定积分兜底**。

Music 当前仍有独立的 `provider + model` 与固定积分路径。不要假定注册进 `MODELS` 就能完成接入，也不为本次图片/视频模型接入强行迁移 Music。

## 5. 测试与上线：按改动范围触发，不做全套专项验收

**核心规则：模型接入不等于项目架构整改。** 每次只测试本次变化和必须保证的主链路；全仓类型检查、lint 可以由已有 CI 执行，不要求为了接一个模型手工重做与本次无关的专项验证。

| 等级 | 本次改了什么 | 必须覆盖 | **不因本次接入而要求** |
|---|---|---|---|
| **T0 常规配置** | 定价文档 + `models.ts`，完全复用现有协议 | 注册表校验、当前模型的价格/参数断言、所开放 scene 的最小真实生成与账单核对 | 并发退款测试、新建独立数据库、开发 callback/后台结算 |
| **T1 模型适配** | 额外修改 Provider 请求 builder、字段映射或结果解析 | T0 + 新 ID 的 payload 契约、输入边界、必要的 query/结果测试 | 修改无关 Provider 或整个账本 |
| **T2 共享链路** | 实际修改任务状态、积分、重试、上传、审核、callback、数据库事务等 | **保留本次模型基础验收**，再对被修改模块补幂等、并发、失败恢复、鉴权等专项测试；涉及事务时在隔离的目标数据库验证 | 每个新模型都重复做一遍 T2 |

这里的 T0/T1/T2 是**测试等级**，不同于第 0 节的 A/B/C 接入类型。**T2 是追加测试，不是替代基础验证**：涉及共享链路时，仍保留本次模型的基础验收，再追加对应专项测试。即使新增了新 Provider，也只针对它实际触及的通用模块追加测试，不自动要求“全面重构后台”。

### 5.1 最小接入步骤

1. **先核对**工作分支、相近模型、官方协议、收费规格。列出必改文件；与本次无关的历史问题不顺手修。
2. **先禁用**新增 entry（`enabled: false`），更新定价与最小代码；该状态仍会执行结构校验，但不会出现在普通模型入口，且 `findModel()` 不会接受它。
3. **离线验证**：运行 `pnpm ai:validate-models` 和该模型价格/字段映射的定向测试。**生产环境的注册表自检当前仅 `console.error`，不阻断启动，不能替代上线前校验。** 视频可以复用 `pnpm test:video-contract` 的相关检查；新协议须补针对**真实 model ID** 的 payload 断言。类型检查与 lint 由本地或 CI 完成。
4. **本地或现有测试环境临时启用**新模型，使用测试账号做站内冒烟。正常 T0/T1 不要求为**每个模型重新创建独立数据库**；但不得把可能修改真实用户余额的数据测试直接指向生产。若无可用隔离环境，先做受控 Provider 冒烟，并明确“站内链路未验证”。
5. **在预算授权范围内**，每个实际开放的 scene 做至少一次低成本真实生成，核对请求、结果、积分及供应商账单。昂贵的规格边界优先使用 mock + 报价证明；是否额外付费实测按成本与风险决定。
6. **生产启用另行授权**。再次验证配置，观察真实任务；回滚只关新任务入口，不能破坏已提交任务的查询与结果。

### 5.2 普通模型的最小放行清单（T0/T1）

- [ ] 每接入一个新模型，按开放的 scene 模拟生成一次，拦截最终发给供应商的 JSON，核对字段、类型和值是否符合官方文档；不发送真实付费请求，不引入复杂测试框架。页面正常显示不能替代此检查。
- [ ] 按 scene 的上游 ID、必填/禁止字段、分辨率和时长准确。
- [ ] **图片/视频服务端负向验收**：非法 `mediaType/provider/family/scene/model` 组合被拒绝；客户端自带的积分或价格绝不参与最终计价。优先复用现有用例，勿因此扩大为全仓安全重测。
- [ ] 每个**开放**的规格有合法控制项与明确的本站积分；前端预估与后端计算一致。
- [ ] 上传/素材输入只使用现有已验证的合法模式；新增输入能力时额外验证约束与服务端检查。
- [ ] 新模型 payload 断言通过；若改了 adapter，则验证相关旧模型未回归。
- [ ] 实际创建和查询可完成；记录 `ai_task` 的 provider、model、scene、options、costCredits；一次正常扣费，拿到可用结果。
- [ ] 所公开的成本维度有报价或真实账单依据，未知附加费不擅自开放。
- [ ] 有明确部署与禁用回滚办法。

**专项验收只按触发条件追加**：

- 改 `credit.ts`、`ai_task.ts` 或数据库事务 → 做目标数据库的并发扣退、余额一致性、幂等测试。
- 改 `generate/route.ts` 的创建/重试、或共享任务刷新逻辑 → 补异常重试、状态不明、重复提交与终态测试。
- 改上传入口或新增资产类型 → 补鉴权、格式、大小、数量和 URL 安全测试。
- 新 Provider 只能依赖 callback，或本次修改了 callback/后台结算 → 才验收接收端、归属校验、幂等、后台补偿。
- 改内容审核/结果审核 → 再跑 `pnpm test:ai-moderation` 及相关异常路径。

**例外：**如果某项既有风险会直接导致**本次模型**错误计价、错误协议、可绕过安全检查或无法查询结果，则应先解决、限制该能力，或明确阻止本次上线；不能仅以“是历史问题”为由忽略。其他项目风险继续在独立待办中跟踪。

## 6. 任务、退款与 Callback：理解边界，不代表每次都要改造

本节说明**现有主链路应当如何被复用**，不是接新模型的强制开发任务：

- **普通 T0/T1**：沿用当前 `/api/ai/generate`、`/api/ai/query` 与积分账本；确认新模型能正常创建、查询结果和单次扣费即可。**不要求为它新建 callback、队列、定时结算或并发退款系统。**
- **响应超时不等于上游失败**：创建请求状态不明时不能盲目再次发送可能付费的 POST；页面关闭或前端等待超时不等于真实任务终态。
- **退款政策不是模型字段映射**：现有 `ai_task.ts` 的自动退款主要发生在 `FAILED + creditId`；`CANCELED`、`MODERATION_BLOCKED`、`MODERATION_FAILED` 不应默认为同一种退款行为。普通接入不擅自改账本政策。
- **可选 callback**：当前若没有可用接收端，不能把“已传 URL”当作通知已生效。共享旧代码的治理单独排期；新模型沿用可工作的轮询，不因此强制建设后台系统。
- **只有能力需要时才扩展**：新供应商强制 callback、没有可用 `query()`、或改变了任务/退款状态语义，才把对应通用能力纳入**此次接入范围**，按 T2 执行。

后台补偿、任务统一刷新和退款并发治理属于 [项目技术风险与待办清单](./项目技术风险与待办清单.md) 的项目级工作，**不是每次接新模型的前置条件**。若直接影响本次上线安全，遵守第 5 节的例外规则。

## 7. 可复用经验（历史风险另存）

### H3：协议不同，专用 builder 合理

`minimax-h3` 的文生/图生对应不同真实 ID，当前用独立 builder；图生只开放首帧/首尾帧。旧方案“不传 resolution”已不代表当前代码，后续核对现行 controls、pricing 和 API。不把 H3 加进 Seedance 专用模型集合。

### Mini：优先复用，但不照搬默认能力

Mini 使用独立 `seedance-2-mini` family，复用 Seedance catalog 与图片映射；不能作为 Fast 的同价 fallback。图生通过 `imageInputRequired` 收紧输入，参考图当前为 2–3 张的产品限制，不等同全部上游能力。

Fast、Standard、Mini 的音频开关均应核对成本；未知成本的公开选项需要限制、定价或有明确风险接受依据。不要只核对 Mini，也不要因共有 factory 就默认所有型号相同。

### 历史风险不加入日常接入步骤

Standard 时长映射、视频参考成本、无效 callback、扣退积分、上传等问题，**统一放在** [项目技术风险与待办清单](./项目技术风险与待办清单.md)。该清单有独立优先级和修复计划，不代表已经修好，也不因为新增无关模型而整体触发。仅本次使用相同风险代码路径时，按第 5 节规则评估是否阻断上线。
