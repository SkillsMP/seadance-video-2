# 项目速览

> 用这一页看清重要文件、数据结构和两条主数据流。接入新模型的步骤看 [新增模型接入改动清单](./新增模型接入改动清单.md)。已有代码问题看 [项目技术风险与待办清单](./项目技术风险与待办清单.md)。

Seadance Video 是 ShipAny Two 上的 AI 视频站。用户买的是积分，生成时按模型注册表扣积分。图片和视频的模型名单、控件、扣费都从 `src/config/ai/models.ts` 来，不在页面里再写一份。

## 1. 重要文件

```text
浏览器
  |
  |  页面在 src/app/[locale]/
  |    (landing)/     首页、定价、生成器、我的任务
  |    (auth)/        登录注册
  |    (admin)/       后台用户、订单、积分、任务
  |
  +-- 生成器界面
  |     src/shared/blocks/generator/video.tsx
  |     src/shared/blocks/generator/image.tsx
  |     src/shared/blocks/generator/generation-controls.ts
  |
  +-- 两个接口
        src/app/api/ai/generate/route.ts    创建任务
        src/app/api/ai/query/route.ts       轮询结果

创建任务时往下走：

  models.ts              这是什么模型、什么场景、多少钱
       |
  options.ts             把用户参数收成 finalOptions
       |
  credit-costs.ts        按 finalOptions 算出积分
       |
  generation-pricing.ts  把上面两步合成一次快照
       |
  extensions/ai/kie.ts   把 finalOptions 翻成上游请求
       |
  shared/models/ai_task.ts
       写入 ai_task，并调用 credit.ts 扣积分
       任务变成 FAILED 时，在这里退款

旁边两条线，不参与「选模型和算价格」：

  shared/services/ai.ts + settings.ts   用配置里的 Key 创建 Provider
  config/db/schema.postgres.ts          表结构。mysql / sqlite 有对应文件
  docs/定价/3.本项目定价方案.md 第 3 节  业务售价。代码价格要和这里一致
```

Music 不走上面这条。它仍用 `music.tsx` 里的固定积分，请求只带 `provider + model`。

营销页文案在 `src/config/locale/messages/{en,zh}/`，和模型注册表不是同一份数据。

## 2. 重要数据结构

用户选的是产品名，发给上游的是另一套 ID。

```text
用户看到的          代码里的 family              发给 Kie 的 value
Seedance 2.0 Fast   seedance-2-fast             bytedance/seedance-2-fast
Seedance 2.0        seedance-2-standard         bytedance/seedance-2
Seedance 2.0 Mini   seedance-2-mini             bytedance/seedance-2-mini
```

文生、图生如果上游 ID 不同，就写成多行 `ModelEntry`，共用一个 `family`。MiniMax H3 就是这样。

```text
ModelEntry                         一行 = 一个上游模型在若干场景下怎么卖
  mediaType                        image | video | music
  family                           产品 key。同产品同场景必须同价
  provider                         谁去调。当前是 kie
  value                            上游真实 model ID
  label                            界面上的名字
  scenes                           text-to-video、image-to-video ...
  enabled                          false 时普通入口和 findModel() 都不收
  |
  +-- 以下都按 scene 分开写
  |
  controls                         用户能选什么
  defaults                         没选时用什么
  enforced                         服务端锁死、客户端改不了的值
  inputConstraints                 要不要图、图的模式、提示词是否必填
  pricing                          真正扣费用这个
  |     image: 固定积分
  |     video: 输出时长 x 该分辨率每秒积分
  credits                          旧的兼容数字。视频最终扣费不看它
  skuAttributes                    附注，例如有没有参考视频。不会自动加价
```

一次生成在进上游之前，会收成这一份快照。客户端自己带的积分不算数。

```text
GenerationPricingSnapshot
  finalOptions     默认值 <- 用户参数 <- 模型规格 <- enforced
                   只留下这个模型这个场景允许的字段
  costCredits      由 finalOptions + ModelEntry.pricing 算出来
```

落库后主要看两张表。`ai_task.options` 和 `ai_task.costCredits` 保存的就是上面这份快照。

```text
ai_task
  id            本站任务 ID。查询接口用这个
  userId
  mediaType / scene / provider
  model         实际用掉的上游 value
  prompt
  options       finalOptions 的 JSON
  costCredits   本次扣除的本站积分
  creditId      指向下面那条消费记录
  taskId        上游任务 ID。轮询用这个
  status        进行中，或 SUCCESS / FAILED / CANCELED /
                MODERATION_BLOCKED / MODERATION_FAILED
  taskInfo      上游状态 JSON
  taskResult    结果 JSON，里面有成片地址

credit          积分流水，不是用户余额字段
  transactionType   grant 发放，consume 消费
  credits           发放为正，消费为负
  remainingCredits  这一笔发放还剩多少。扣费从这里减
  status            ACTIVE，退款后消费记录改为 DELETED
  consumedDetail    这次消费动了哪些发放记录
  orderNo           购买来的积分才有。赠送积分可以没有
```

用户的「还剩多少积分」是把未过期的 grant 的 `remainingCredits` 加起来，不是 `user` 表上的一个数字。

## 3. 生成数据流

图片和视频走这条。扣费发生在上游已经返回任务之后；候选全部失败时不建任务、不扣积分。

```text
video.tsx / image.tsx
  从 MODELS 里取出 enabled 的模型
  用户选择 family、scene、控件、素材
        |
        |  POST /api/ai/generate
        |  family + scene + candidates + prompt + options
        v
generate/route.ts
  1. 必须登录
  2. findModel(mediaType, provider, family, scene, value)
     对不上、或 enabled=false：拒绝
  3. 用第一个候选算出 GenerationPricingSnapshot
     其余候选必须算出同一份价格和 finalOptions
  4. 检查素材 URL、图片模式和张数、提示词
  5. 余额不够就停
  6. 审核输入
  7. 按 candidates 的顺序调 Provider
     一个成功就停。全部失败则到此结束，不扣费
        |
        |  kie.ts 只做字段翻译
        |  duration 或 n_frames、图片字段、画幅、分辨率
        |  不把 finalOptions 整包转发
        v
  上游返回 taskId、状态、可能已有的结果
        |
        v
  审核输出
        |
        v
  createAITask
     插入 ai_task
     consumeCredits：从 grant 记录里扣 costCredits
     把消费记录 id 写回 ai_task.creditId
        |
        v
浏览器拿着本站 task.id 轮询
  POST /api/ai/query     body 里的 taskId 是本站 id，不是上游 id
        |
        v
  已是终态：直接返回
  否则用 ai_task.taskId 调 Provider.query
  再审核输出，写回 status / taskInfo / taskResult
        |
        +-- status = FAILED 且有 creditId
        |     把扣掉的积分加回原来的 grant
        |     消费记录标成 DELETED
        |
        +-- SUCCESS：taskResult 里是可下载的结果
```

关着页面不会有人在后台继续查。结果要等用户或历史页再调 `/api/ai/query`。创建请求会带一个 `/api/ai/notify/[provider]` 地址，但当前没有这个接收接口；实际完成靠上面的轮询。

`CANCELED`、`MODERATION_BLOCKED`、`MODERATION_FAILED` 不会走上面那段自动退款。自动退款只认 `FAILED`。

## 4. 积分从哪来

套餐决定怎么买积分，模型表决定一次生成扣多少。加一个模型不改套餐。

```text
定价页 pricing.json
  用户看到套餐和价格
        |
        v
支付 checkout
  Stripe / PayPal / Creem
        |
        v
支付 webhook
  src/app/api/payment/notify/[provider]/route.ts
        |
        v
order 表记下这笔订单
        |
        v
credit 表插入一条 grant
  credits = 套餐积分
  remainingCredits 从这里开始减
        |
        v
生成成功后的 consume
  减掉若干 grant 的 remainingCredits
  再插入一条 consume，ai_task.creditId 指向它
```

## 5. 看代码时的顺序

1. `models.ts` 里的 `ModelEntry` 和 `MODELS`：站上现在有哪些模型。
2. `video.tsx`：这些模型怎么出现在界面上。
3. `generate/route.ts`：请求怎么被拒绝或放行。
4. `options.ts` 然后 `credit-costs.ts`：参数和价格怎么定下来。
5. `kie.ts`：定下来的参数怎么变成上游字段。
6. `ai_task.ts`：任务和扣费、失败退款怎么落库。
7. `query/route.ts`：结果怎么写回来。
