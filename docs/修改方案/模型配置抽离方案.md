# 模型配置抽离方案

现在状态可以这样重新梳理：

```text
已完成：
阶段 1：pricing + credit-costs 基建
scene fallback 已调高
```

接下来不要再纠结旧的 `6 / 8 / 10` 低兜底问题，重点变成：**模型配置、扣费配置、规格参数之间如何不脱节。**

当前最重要的原则是：

```text
MODEL_OPTIONS 里出现的每一个 family + scene，
都必须在 src/config/ai/credit-costs.ts 里有明确扣费。
```

`scene fallback` 只作为安全兜底，不作为主定价。只要一个模型能在前台被选中，就不能长期依赖 fallback 扣费。

## 本次 KIE 模型配置评审

整体方向是对的：以后不能每新增一个 KIE 模型就在 `src/extensions/ai/kie.ts` 里追加一个 `if (params.model === 'xxx')`。当前 `google/nano-banana-edit` 报 `image_urls is required`，已经证明 KIE 内部不同模型的入参协议不完全统一，单靠更换 `model id` 不可靠。

合理的部分：

- **配置文件 + adapter profile** 是当前最合适的抽象粒度。新增同协议模型只改配置；新增不同协议时才补一个 adapter profile。
- **先修真实 bug** 是正确顺序。`google/nano-banana-edit` 需要把前端通用的 `image_input` 转成 KIE 的 `image_urls`，这个问题不应该等大重构。
- **`defaultOptions` 放配置里** 是对的。`seedance-2-fast-480p-video-input` 的 `resolution=480p`、`duration=5`、`aspect_ratio=16:9`、`generate_audio=false` 不应该长期硬编码在 `video.tsx`。
- **adapter 按协议分组，不按模型名分组** 是对的。`kie-image-input`、`kie-image-urls` 这类命名比一堆模型名判断更可维护。

需要调整的部分：

- **前端不要直接只消费 `KIE_MODEL_SPECS`**。当前系统已经有 provider fallback 设计，`MODEL_OPTIONS` 表达的是“provider 具体候选项”。如果前端只从 KIE 配置筛选，后续 Replicate / Fal / Gemini 候选会被架构性排除。更稳的做法是抽一个统一的 `src/config/ai/model-options.ts`，其中 KIE 候选带 `adapter` 和 `defaultOptions`。
- **不能只靠 `model id` 查 adapter**。例如 `bytedance/seedance-2-fast` 同时用于 `seedance-2-fast-720p` 和 `seedance-2-fast-480p-video-input`，只按 model id 会歧义。后端 provider 至少要拿到 `family + scene + model`，或者 candidate 本身带一个稳定配置 key。
- **`kie-seedance-2-video` 这种 adapter 名可以接受，但要明确它是协议 profile，不是模型白名单**。如果后面发现别的视频模型也使用同一套 `first_frame_url / reference_video_urls / duration / resolution` 协议，就应该复用同一个 adapter。
- **adapter profile 不是完整 specs 系统**。当前先解决 provider 入参映射和默认固定参数；4K、1080p、音频、可选时长、web search 这类用户可选规格，仍然放到后面的 `model-specs.ts / creditKey` 阶段处理。

结论：

```text
新增模型：
优先改统一模型注册表。

新增 KIE 参数协议：
才改一次 KIE adapter profile。

KIE Provider 主流程：
只负责查 profile、构造 payload、发请求，尽量不再塞模型名判断。
```

## 1. 先补文档 3 的模型积分消耗表

先在 `docs/定价/3.本项目定价方案.md` 的「模型积分消耗表」里明确要上线模型的积分。这里要写确定值，不要写范围。

当前建议先明确这些锚点：

```text
nano-banana = 5 credits
nano-banana-2 = 15 credits
nano-banana-pro = 20 credits

seedance-2-fast-720p = 90 credits
seedance-2-fast-480p-video-input = 45 credits
sora-2-lite = 30 credits
```

注意：

- 文档里的 `代码 family key` 必须和前端真实传给后端的 `family` 字符串一致。
- 如果最终代码使用的是 `nano-banana-basic`，文档就写 `nano-banana-basic`；如果代码使用 `nano-banana`，文档就写 `nano-banana`。
- 不允许只按展示名猜 key。
- Seedance 2.0 不要只写一个泛化的 `seedance-2.0` 价格，必须按实际开放规格拆档，例如 `seedance-2-fast-480p`、`seedance-2-fast-720p`、`seedance-2-standard-720p`。

本期先上 KIE.ai，当前模型 id 固定为：

```text
nano-banana text-to-image：google/nano-banana
nano-banana image-to-image：google/nano-banana-edit
nano-banana-2：nano-banana-2
nano-banana-pro：nano-banana-pro
seedance-2-fast-720p：bytedance/seedance-2-fast
seedance-2-fast-480p-video-input：bytedance/seedance-2-fast，固定 reference_video_urls + resolution=480p + duration=5
sora-2-lite text-to-video：sora-2-text-to-video
sora-2-pro text-to-video：sora-2-pro-text-to-video
sora-2-pro image-to-video：sora-2-pro-image-to-video
```

注意：`sora-2-lite` 当前只作为低成本测试入口。如果 KIE 返回 `This interface is temporarily paused.`，不要把它自动 fallback 到 `sora-2-pro-*`，否则会出现 30 credits 扣费实际跑 90 credits 模型的成本错配。应先确认 KIE 可用的 stable model id，再替换 `MODEL_OPTIONS.value`。

# 阶段 1.7：先修当前 KIE 字段问题

当前真实 bug 是：

```text
google/nano-banana-edit 需要 image_urls
但 KieProvider.generateImage 只会把 options.image_input 透传为 input.image_input
```

因此第一步不是大改注册表，而是先让 KIE 图像 adapter 能把通用前端 options 映射成供应商需要的字段。

最小修复原则：

```text
前端仍然传通用 options.image_input
后端 KIE provider 根据 adapter profile 转成 image_input 或 image_urls
不在 video.tsx / image.tsx 里写 KIE 专属字段名
```

这一步可以先只覆盖当前两个图像协议：

```ts
export type KieAdapterProfile = 'kie-image-input' | 'kie-image-urls';
```

示例映射：

```text
kie-image-input:
options.image_input -> input.image_input
options.aspect_ratio -> input.aspect_ratio

kie-image-urls:
options.image_input -> input.image_urls
options.aspect_ratio -> input.image_size
```

阶段 1.7 的验收标准：

```text
google/nano-banana-edit 的 image-to-image 不再报 image_urls is required。
前端仍只传通用 image_input，不感知 KIE 私有字段。
kie.ts 中不新增一串按模型名判断的 if。
```

# 阶段 2：抽统一模型注册表 + KIE adapter profile

等当前 `MODEL_OPTIONS` 补完整并验证后，再新增：

```text
src/config/ai/model-options.ts
```

把现在散在：

```text
src/shared/blocks/generator/image.tsx
src/shared/blocks/generator/video.tsx
```

里的 `MODEL_OPTIONS` 抽出来。

这份注册表要继续服务当前的 provider fallback 设计，所以不要让前端直接只依赖 `KIE_MODEL_SPECS`。更合适的结构是统一模型候选表，KIE 候选再额外带 KIE adapter 信息。

建议类型：

```ts
export type AIModelMediaType = 'image' | 'video';

export type AIModelScene =
  | 'text-to-image'
  | 'image-to-image'
  | 'text-to-video'
  | 'image-to-video'
  | 'video-to-video';

export type KieAdapterProfile =
  | 'kie-image-input'
  | 'kie-image-urls'
  | 'kie-seedance-2-video'
  | 'kie-sora-video';

export interface AIModelOption {
  mediaType: AIModelMediaType;
  family: string;
  value: string;
  label: string;
  provider: string;
  scenes: AIModelScene[];
  enabled: boolean;
  defaultOptions?: Record<string, unknown>;
  adapter?: KieAdapterProfile;
}
```

示例配置：

```ts
export const IMAGE_MODEL_OPTIONS: AIModelOption[] = [
  {
    mediaType: 'image',
    family: 'nano-banana',
    value: 'google/nano-banana',
    label: 'Nano Banana',
    provider: 'kie',
    scenes: ['text-to-image'],
    enabled: true,
    adapter: 'kie-image-input',
  },
  {
    mediaType: 'image',
    family: 'nano-banana',
    value: 'google/nano-banana-edit',
    label: 'Nano Banana',
    provider: 'kie',
    scenes: ['image-to-image'],
    enabled: true,
    adapter: 'kie-image-urls',
  },
  {
    mediaType: 'image',
    family: 'nano-banana-pro',
    value: 'nano-banana-pro',
    label: 'Nano Banana Pro',
    provider: 'kie',
    scenes: ['text-to-image', 'image-to-image'],
    enabled: true,
    adapter: 'kie-image-input',
  },
];

export const VIDEO_MODEL_OPTIONS: AIModelOption[] = [
  {
    mediaType: 'video',
    family: 'seedance-2-fast-480p-video-input',
    value: 'bytedance/seedance-2-fast',
    label: 'Seedance 2.0 Fast 480p',
    provider: 'kie',
    scenes: ['video-to-video'],
    enabled: true,
    adapter: 'kie-seedance-2-video',
    defaultOptions: {
      resolution: '480p',
      duration: 5,
      aspect_ratio: '16:9',
      generate_audio: false,
    },
  },
];

export const AI_MODEL_OPTIONS = [
  ...IMAGE_MODEL_OPTIONS,
  ...VIDEO_MODEL_OPTIONS,
];
```

如果想把 KIE 配置单独拆文件，也可以新增：

```text
src/config/ai/kie-models.ts
```

但它应该作为 `model-options.ts` 的 KIE 子集或数据来源，而不是让生成器组件直接只 import `KIE_MODEL_SPECS`。生成器组件仍然只关心统一模型候选表：

```ts
const MODEL_OPTIONS = AI_MODEL_OPTIONS
  .filter((option) => option.mediaType === 'video')
  .filter((option) => option.enabled);
```

KIE provider 查 adapter 时不能只按 `model id`。至少要使用：

```text
provider + family + scene + model
```

原因是 `bytedance/seedance-2-fast` 这种 model id 可以对应不同 family、不同 scene 和不同默认规格。如果 `/api/ai/generate` 传给 provider 的 `AIGenerateParams` 里没有 `family` / `scene`，就需要先补齐：

```ts
export interface AIGenerateParams {
  mediaType: AIMediaType;
  prompt: string;
  model?: string;
  family?: string;
  scene?: string;
  options?: any;
  callbackUrl?: string;
}
```

然后 `/api/ai/generate` 在调用 provider 时把 `family`、`scene` 一起传进去。

`image.tsx / video.tsx` 的变化：

```text
只 import 统一模型注册表。
按 mediaType / scenes / enabled / availableProviders 筛选。
生成 options 时先合并 selectedModelSpec.defaultOptions，再合并用户输入。
不再在组件里维护 MODEL_OPTIONS，也不再写 selectedFamily === 'xxx' 的默认参数判断。
```

阶段 2 的目标是解决：

```text
模型加了，但积分没配
模型散落在组件里，不知道哪里是权威来源
模型参数协议散落在 kie.ts 和组件里
同一个 model id 因 family / scene 不同产生 adapter 歧义
```

阶段 2 的验收标准：

```text
新增模型时，不再去组件里到处找 MODEL_OPTIONS。
模型注册统一在 src/config/ai/model-options.ts。
生成器组件只消费模型配置，不再定义模型配置。
KIE 候选都有明确 adapter profile。
defaultOptions 从配置合并，不再写在组件 if 里。
KieProvider 可以基于 family + scene + model 找到正确 adapter。
```

# 阶段 4：抽模型规格参数

阶段 2 的 `defaultOptions` 只处理“某个候选项固定必须携带的 provider 参数”，例如 `seedance-2-fast-480p-video-input` 固定 480p / 5s。再下一步才处理用户可选规格：

```text
4K
1080p
duration
audio
reference image 数量
web search
```

新增：

```text
src/config/ai/model-specs.ts
```

例如：

```ts
export const MODEL_SPECS = {
  'nano-banana-pro': {
    resolutions: [
      {
        value: '1k-2k',
        label: '1K / 2K',
        creditKey: 'nano-banana-pro',
        default: true,
      },
      {
        value: '4k',
        label: '4K',
        creditKey: 'nano-banana-pro-4k',
      },
    ],
  },
};
```

这一阶段的关键是引入：

```text
creditKey
```

因为同一个 family 下面可能有不同规格：

```text
Nano Banana Pro 1K / 2K = 20 credits
Nano Banana Pro 4K = 30 credits
```

如果只靠 family，就区分不了。

阶段 4 的验收标准：

```text
规格选择不再硬编码在 UI 里。
同一模型的不同规格可以映射到不同 creditKey。
低成本标准规格和高成本规格不会混用同一个扣费 key。
```

# 阶段 5：让扣费支持 creditKey / options

现在扣费主要是：

```text
family + scene -> credits
```

以后要升级成：

```text
creditKey + scene -> credits
family + scene -> credits
scene fallback
```

优先级：

```text
1. creditKey override
2. family override
3. scene fallback
```

这样选择 4K 时，可以扣：

```text
nano-banana-pro-4k + text-to-image = 30
```

而不是误用：

```text
nano-banana-pro + text-to-image = 20
```
