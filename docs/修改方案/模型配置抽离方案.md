# 可信模型注册表与计费 SKU 闸门方案

本方案不再只是“模型配置抽离”。本期 P0 是修复 `/api/ai/generate` 中 **`family` 扣费与 `candidates` 实际执行模型可错配** 的漏洞；P1 才是抽离前端模型配置、减少硬编码和后续漂移。

当前风险在于：

```ts
const costCredits = getGenerationCreditCost({
  mediaType,
  scene,
  family: requestBody.family,
  model,
});

for (const candidate of candidates) {
  result = await createProviderTask(candidate.provider, candidate.model);
}
```

扣费信任客户端传入的 `family`，执行却使用客户端传入的 `candidate.model`，二者没有交叉验证。恶意请求可以用低价 `family` 搭配高价 `candidate.model`：

```json
{
  "mediaType": "image",
  "scene": "text-to-image",
  "family": "nano-banana",
  "candidates": [
    { "provider": "kie", "model": "nano-banana-pro" }
  ]
}
```

因此，阶段 2B 的第一目标不是 adapter 重构，而是服务端建立可信模型注册表和计费 SKU 闸门。

---

## 核心原则

```text
1. family 是稳定的计费 SKU 标识，不是模型族血缘名称。
2. image/video 的 candidates 必须由服务端 resolver 反查注册表后才能执行。
3. scene fallback 只作为异常兜底，不作为前台可选模型的主定价。
4. defaultOptions 是用户可覆盖的默认值。
5. enforcedOptions 是和成本、规格、定价表绑定的强制值。
6. 服务端是 options 合并的唯一权威。
7. Provider 不反查注册表，只消费 route.ts 注入的 resolved 信息。
```

`family` 的语义必须写进 `model-options.ts` 和 `credit-costs.ts` 文件头注释：

```text
family is a stable billing SKU identifier surfaced as a product choice,
not a model lineage tag.
```

例如 `seedance-2-fast-480p-video-input` 不是纯“模型族”，而是一个产品选择和计费档位。未来如果需要表达真正的模型族，可以再加 `baseFamily`、`specKey` 或 `creditKey`，但本期不要提前引入规格系统。

## 阶段 2A + 3：可信模型注册表与一致性校验

新增：

```text
src/config/ai/model-options.ts
src/config/ai/validate-config.ts
```

`model-options.ts` 是 image/video 可选模型的权威来源。生成器组件只消费它，不再定义自己的 `MODEL_OPTIONS`。

建议类型：

```ts
export type AIModelMediaType = 'image' | 'video';

export type AIModelScene =
  | 'text-to-image'
  | 'image-to-image'
  | 'text-to-video'
  | 'image-to-video'
  | 'video-to-video';

export type KieAdapterProfile =
  | 'kie-image-input'
  | 'kie-image-urls'
  | 'kie-video-duration-seconds'
  | 'kie-video-n-frames';

export interface AIModelOption {
  mediaType: AIModelMediaType;
  family: string;
  value: string;
  label: string;
  provider: string;
  scenes: AIModelScene[];
  enabled: boolean;

  // 用户可覆盖的默认值，例如不影响成本的 aspect_ratio。
  defaultOptions?: Record<string, unknown>;

  // 服务端强制规格。改它会改变成本，或偏离定价表预期。
  enforcedOptions?: Record<string, unknown>;

  providerOptions?: {
    kie?: {
      adapterProfile?: KieAdapterProfile;
    };
  };
}
```

`enabled` 规则：

```text
Resolver 只匹配 enabled: true 的条目。
enabled: false 等同于不存在。
当前 enabled 是代码级开关，仍需要发版。
后续若要运维即时停用，需要迁移到 DB、远程配置、环境配置或后台管理。
```

示例配置：

```ts
export const VIDEO_MODEL_OPTIONS: AIModelOption[] = [
  {
    mediaType: 'video',
    family: 'seedance-2-fast-480p-video-input',
    value: 'bytedance/seedance-2-fast',
    label: 'Seedance 2.0 Fast 480p',
    provider: 'kie',
    scenes: ['video-to-video'],
    enabled: true,
    defaultOptions: {
      aspect_ratio: '16:9',
    },
    enforcedOptions: {
      resolution: '480p',
      duration: 5,
      generate_audio: false,
    },
    providerOptions: {
      kie: {
        adapterProfile: 'kie-video-duration-seconds',
      },
    },
  },
];
```

字段归属规则：

```text
如果改这个字段会改变 credits cost，或让产物偏离定价表预期，它属于 enforcedOptions。
否则属于 defaultOptions。
```

例如：

| 字段 | 位置 | 理由 |
|---|---|---|
| `resolution: '480p'` | `enforcedOptions` | 绑定计费档 |
| `duration: 5` | `enforcedOptions` | 影响成本 |
| `generate_audio: false` | `enforcedOptions` | 防止低价档偷用音轨 |
| `aspect_ratio: '16:9'` | `defaultOptions` | 一般不影响成本，用户应可改 |

一致性校验放在 `validate-config.ts`。阶段 2A 抽配置时同步完成，不要拖到后续阶段。

校验项：

```text
1. 每个 enabled option 的每个 scene 都必须命中 credit-costs.ts 中的 family + scene 明确扣费。
2. (mediaType, provider, family, scene, value) 必须唯一。
3. provider === 'kie' 且 enabled: true 时，必须声明 providerOptions.kie.adapterProfile。
4. defaultOptions 和 enforcedOptions 不允许出现同名 key。
5. enabled: false 的条目不参与 resolver 匹配和前端可选列表。
```

缺失时，开发环境先 warning，成熟后再让 CI 失败：

```text
Missing credit cost override: family=nano-banana-2 scene=text-to-image
Missing KIE adapter profile: family=nano-banana model=google/nano-banana-edit scene=image-to-image
Duplicate model option: mediaType=image provider=kie family=nano-banana scene=text-to-image value=google/nano-banana
```

## 阶段 2B-1：服务端 resolver + SKU 闸门

新增纯函数，放在 `src/config/ai/`，不依赖请求运行时状态：

```ts
export function resolveModelOption(input: {
  mediaType: string;
  provider: string;
  model: string;
  family: string;
  scene: string;
}): AIModelOption;
```

匹配规则：

```text
必须全维度命中：
mediaType
provider
family
scene in option.scenes
model === option.value
enabled === true
```

失败模式：

```text
lookup miss 必须 reject。
禁止 warn-and-continue。
禁止 fallback 到按 model 名判断。
禁止退回 scene fallback 扣费后继续执行。
```

### 请求入口矩阵

| 入口形态 | 处理 |
|---|---|
| 有 `candidates` + 有 `family` + 有 `scene` | 强校验。每个 candidate 必须反查到 enabled registry 条目，mismatch 立即 reject |
| 有 `candidates` 但缺 `family` 或 `scene` | 直接 reject。这是新契约，不允许残缺组合 |
| 无 `candidates`，有 `provider + model`，且 `mediaType === music` | 暂时走旧路径。music 本期不纳入强 resolver |
| 无 `candidates`，有 `provider + model`，且 `mediaType` 是 image/video | soft warn 灰度，短期按旧路径走；确认日志无未知调用方后切强制 reject |
| 无 `candidates` 也无 `provider + model` | 沿用现有 `invalid params` |

注意：`candidates` 残缺组合不能进入 legacy 路径，否则等于重新打开绕过 SKU 闸门的口子。

### 服务端权威合并 options

客户端只发送：

```text
clientOptions（用户原始输入）
family
scene
candidates
prompt
mediaType
```

客户端可以本地合并一份配置做 UX 预览，但那份预览不上行。服务端必须从 registry 读取 `defaultOptions` 和 `enforcedOptions`，并权威合并：

```ts
const conflictKeys = Object.keys(clientOptions).filter(
  (key) => key in enforcedOptions
);

if (conflictKeys.length > 0) {
  console.warn('client tried to override enforced options', {
    family,
    scene,
    conflictKeys,
    userId,
  });
}

const sanitizedClientOptions = omitKeys(
  clientOptions,
  Object.keys(enforcedOptions)
);

const finalOptions = {
  ...defaultOptions,
  ...sanitizedClientOptions,
  ...enforcedOptions,
};
```

合并优先级：

```text
defaultOptions < clientOptions < enforcedOptions
```

`ai_task.options` 建议保存实际执行的 `finalOptions`，方便后续审计和问题排查。客户端试图覆盖 enforced 字段的情况靠日志留痕。

### 传给 Provider 的 resolved 信息

Provider 不应该 import registry，也不应该自己再次反查。`route.ts` 解析成功后，把权威信息注入 `AIGenerateParams.resolved`：

```ts
export interface AIGenerateParams {
  mediaType: AIMediaType;
  prompt: string;
  model?: string;
  options?: any;
  callbackUrl?: string;
  resolved?: {
    family: string;
    scene: string;
    adapterProfile?: string;
  };
}
```

`resolved` 表示“服务端 resolver 权威解析后的字段”，不是客户端原始输入。image/video 路径的 provider 可以断言它存在；music 路径暂时可缺省。

## 阶段 2B-2：KIE adapter profile

接入 adapter profile 时，profile 名称必须按 payload 结构命名，不按模型名命名。

起步 profile：

```ts
export type KieAdapterProfile =
  | 'kie-image-input'
  | 'kie-image-urls'
  | 'kie-video-duration-seconds'
  | 'kie-video-n-frames';
```

含义：

```text
kie-image-input:
  options.image_input -> input.image_input
  options.aspect_ratio -> input.aspect_ratio

kie-image-urls:
  options.image_input -> input.image_urls
  options.aspect_ratio -> input.image_size

kie-video-duration-seconds:
  options.duration -> input.duration
  不使用 n_frames / size

kie-video-n-frames:
  options.duration -> input.n_frames
  可继续使用 size
```

不要一开始定义 `kie-seedance-video`、`kie-sora-video` 这类模型命名 profile。Seedance 和 Sora 不是协议边界，payload 形状才是协议边界。

`kie.ts` 中读取：

```ts
const profile = params.resolved?.adapterProfile;
```

如果 KIE enabled 模型缺少 `adapterProfile`，应该在 validate-config 阶段被发现；运行时仍应 fail-closed，不能隐式回退到按模型名判断。

## 前端生成器改造边界

`image.tsx / video.tsx` 后续只做三件事：

```text
1. import 统一模型注册表。
2. 按 mediaType / scenes / enabled / availableProviders 筛选可选项。
3. 发送用户原始 clientOptions + family + scene + candidates。
```

组件不再：

```text
定义自己的 MODEL_OPTIONS。
维护 selectedFamily === 'xxx' 的 provider 默认参数 if。
上送 defaultOptions。
上送 enforcedOptions。
写 KIE 私有字段名。
```

`dedupeModelFamilies` 必须保留注册表顺序，只去重，不排序。数组顺序同时承载默认展示顺序和 fallback 优先级。

## credit-costs.ts 规则

`MODEL_OPTIONS` 中每一个 enabled option 的每一个 scene，都必须有明确扣费：

```text
option.family + scene
必须命中 FAMILY_CREDIT_COST_OVERRIDES[family][scene]
```

示例：

```ts
'nano-banana': {
  'text-to-image': 5,
  'image-to-image': 5,
},

'nano-banana-pro': {
  'text-to-image': 20,
  'image-to-image': 20,
},

'seedance-2-fast-480p-video-input': {
  'video-to-video': 45,
},

'seedance-2-fast-720p': {
  'text-to-video': 90,
},
```

不要提前写尚未开放、没有验证 route 的 scene。`credit-costs.ts` 应反映真实可用能力，不是愿望清单。

## 阶段 4/5：远期方向

本期不要实现规格系统，也不要提前写具体类型。

远期如果需要支持同一 SKU 下的规格差异，例如 4K、1080p、音频、长时长、web search，再引入：

```text
model-specs.ts
creditKey
options-aware pricing
```

届时扣费优先级可以扩展为：

```text
1. creditKey + scene
2. family + scene
3. scene fallback
```

但这不是本期目标。当前阶段只保证：

```text
前台可选模型不会漏配扣费。
客户端不能用低价 family 跑高价 candidate。
服务端强制执行和计费绑定的规格。
Provider payload 映射由 adapter profile 收敛。
```

## 最终验收标准

```text
阶段 1.7：
google/nano-banana-edit 字段映射 bug 修复，前端仍只传 image_input。

阶段 2A + 3：
模型配置统一在 model-options.ts。
family 被明确注释为 billing SKU。
enabled: false 不会出现在前台列表，也不会被 resolver 匹配。
family + scene 漏配扣费会在开发期暴露。
KIE enabled 模型漏配 adapterProfile 会在开发期暴露。
(mediaType, provider, family, scene, value) 重复会在开发期暴露。

阶段 2B-1：
image/video candidates 必须经 resolver 反查 registry。
有 candidates 但缺 family/scene 直接 reject。
候选者错配低价 family 时直接 reject。
服务端执行 defaultOptions < clientOptions < enforcedOptions 合并。
客户端试图覆盖 enforcedOptions 会被 warn 记录。
Provider 收到的是 finalOptions 和 resolved 信息。

阶段 2B-2：
KIE provider 基于 params.resolved.adapterProfile 构造 payload。
不再新增按模型名堆叠的 if。
adapter profile 按协议形状命名，不按模型名命名。
```

一句话：本方案的核心不是“把数组搬到配置文件”，而是建立 **服务端可信注册表 + 计费 SKU 闸门**，先堵住 `family` 与 `candidates` 错配，再逐步收敛模型配置和 provider payload 映射。
