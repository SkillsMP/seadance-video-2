# Flow 主题精修方案（修订版）

> 日期：2026-10-22  
> 状态：生产候选主题为 `flow`（`.env.development` 已切 `flow + dark`）。  
> 目标：把「半套 Flow + 半套本站」收成可接受的成品站，**不**追求整页克隆参考站，**不**改动登录 / 积分 / 支付 / `VideoGenerator` 内部逻辑。

**实施边界**：改动优先且默认仅限 `src/themes/flow/`；不碰 `dynamic-page`、共用 generator、locale、core/theme。参考 videofly 结构时**禁止**跨主题 import。P2（token / 删 queue）默认不做，除非单独立项。

**工程平衡**：小 diff、主题内聚；能用 CSS / 现有 block 解决的，不新建抽象层。

---

## 1. 结论：选 Flow 对不对？

**对。** Flow 有独立的琥珀色 token、`.flow-*` 组件类、暗/浅双套样式，符合偏好简单组件与黄边的方向。实际性能需测量，不能仅凭组件或动效数量断言比 videofly 更快。

维护说明：`reference-notes` / 源码 diff 是**移植验收依据**，不是日常维护流程。定版后按普通主题改文案、颜色、间距即可；只有主动同步上游参考仓时才再对照。

当前半成品感来自**接缝**，不是「主题选错」：

- 真实生成器仍由 `page.tsx` 注入，默认外壳插在 Flow Hero 与 Flow 区块之间  
- 模型页部分 block 回退 `default`（specs / use-case-cards / model-faq / related）  
- 视频墙 CSS 固定三列，与 JSON 里 `columns: 2`、4 条素材不一致

## 2. 工程事实（改之前先记住）

| 事实 | 含义 |
|------|------|
| 渲染顺序 = `sections` **对象键顺序** | `Object.keys(page.sections)` |
| `show_sections` **只过滤显隐，不排序** | 改数组顺序**不会**改变页面区块顺序 |
| `index.json` / `seedance-2-0.json` **多主题共用** | 改 `sections` 键顺序会影响 default / video / videofly / flow |
| 首页 `sections` 键现状 | 已是 `hero → generator → showcases → …` |
| Showcase 素材 | 首页 / 模型页均为 **4 条** `video.src`（webm）+ poster；JSON 已有 `columns: 2` |
| Flow 视频墙实现 | `FlowShowcase` 写死 `flow-video-grid`；CSS 桌面 **三列** → 4 卡末行空两格 |
| Hero / CTA 主按钮 | 类名 `flow-generate`，背景 **`--flow-gradient`（紫粉）**，不是 `--primary` |

完成线：

> 首页 + `/seedance-2-0`：Flow 外壳连贯；生成器不突兀；Use Cases 有卡片+关键词；specs/FAQ 不丑即可。  
> **不**要求整页像素级等同 flowaivideo.lol。

## 3. P0：立刻做（按顺序）

### 3.1 生成器衔接（最优先）

**问题**：Hero 只有标题+按钮；紧随其后的生成器使用 ShipAny 默认外观，需要协调两者的边框、背景与间距。

**首选做法——纯 CSS，零改 TSX**：`#generator` 在 `.flow-shell` 内，在 [`flow.css`](../../src/themes/flow/styles/flow.css) 加规则。以下数值仅作起点，需在桌面和手机实测；不强制负边距，不覆盖生成器内部已有网格。

DOM：

```text
#generator
  └── <section class="py-8 md:py-10 …">   ← 根是 section，不是 div
```

```css
.flow-shell #generator {
  width: 100%;
  max-width: var(--flow-shell-max);
  margin-inline: auto;
  margin-block: 0 3rem;
  padding-inline: 1rem;
}

.flow-shell #generator > section {
  /* 视觉对齐 .flow-card，单列全宽 */
  border: 1px solid var(--border);
  border-radius: var(--radius);
  background: color-mix(in oklab, var(--card) 92%, transparent);
  box-shadow: 0 24px 60px -40px rgba(0, 0, 0, 0.9);
}
```

**禁止**：

- 给 `#generator` 添加或外包 **`.flow-studio`**：桌面是 **7:5 双列网格**，只放一个生成器会占左列、右侧空白。  
- 使用 `#generator > div`（选不中）。  
- 改 `VideoGenerator` 内部逻辑。

**仅 CSS 不够时**：先说明具体限制与所需修改范围，不直接修改 `page.tsx`。如确认需要增加外壳，也必须是**单列全宽**，不使用 `flow-studio`。

---

### 3.2 视频墙：尊重现有 4 卡 + `columns: 2`

**问题**：三列网格 + 4 条案例 → 末行空两格。

**范围**：只动 **`block: showcases`** 的 `FlowShowcase` 视频网格。模型页 JSON 里其它区块也可能带 `columns`（例如 `features` 的 `columns: 4`），由各自 block 负责，**不在本项改 layout**。

**做法（不补 6 条、不改共用 JSON）**：

1. [`showcases.tsx`](../../src/themes/flow/blocks/showcases.tsx) 把 locale 里的 **`section.columns`** 传给 [`FlowShowcase`](../../src/themes/flow/components/site.tsx)（当前适配层只映射 `items`，会丢 `columns`，需补上这一字段）。  
2. `FlowShowcase` 在 `columns === 2` 时为网格加修饰 class（如 `flow-video-grid--cols-2`）。  
3. [`flow.css`](../../src/themes/flow/styles/flow.css) 在现有 `min-width: 768px` 断点内，仅对该修饰 class 设置 `grid-template-columns: repeat(2, minmax(0, 1fr))`，规则置于原三列规则之后。  
4. 手机保持单列；未指定 `columns: 2` 的 `flow-video-grid` 仍走默认三列（桌面），不全局改写所有网格。

首页、模型页 `examples` 保持现有 4 条素材即可（均已 `columns: 2`）。

## 4. P1：模型页局部协调

新增 [`src/themes/flow/blocks/use-case-cards.tsx`](../../src/themes/flow/blocks/use-case-cards.tsx)：

- **视觉**用 Flow 的 `.flow-card` / amber，**不要** MagicCard / BlurFade / framer-motion（除非后续实测确需极轻交互）。  
- 优先 **Server Component**；无客户端状态时不必加 `'use client'`。

### 4.2 specs / model-faq / related

**不要**再包一层 Flow section 标题（易重复）。仅用 `.flow-shell` 内的**局部 CSS** 调间距、背景；业务块继续 default 实现，保留已有标题、内容、模型 FAQ 的纯文本答案，以及 related-resources 中的链接。

default 块已在根 `<section>` 上输出 JSON 里的 **`id`**，可直接挂选择器，例如（`/seedance-2-0`）：

| 区块 | 建议 CSS 锚点 |
|------|----------------|
| model-specs | `.flow-shell #specifications` |

首页 Flow FAQ 的 `id` 也是 `faq`，且带有 `.flow-section`；模型页 FAQ 必须使用上述排除选择器，避免同时修改首页 FAQ。

只改 padding、背景、与上下区块间距；**不要**用 CSS 隐藏或重写已有 `h2` 标题。

## 5. P2：配色与清理（不改善首屏时不必抢跑）

### 5.1 Token：区分 `--primary` 与主按钮渐变

**事实**：

- Hero / CTA 主按钮 → `.flow-generate` → **`background: var(--flow-gradient)`**（紫粉，原站设计）。  
- 改一行浅色 `--primary` **不会**把主 CTA 改成琥珀。  
- 浅色 `--primary` 仍是紫（277）时，会影响 Tailwind/shadcn 等用 `--color-primary` 的控件，并与 `--flow-amber`（序号、FAQ 等）可能不一致。

**默认策略（保原站）**：**保留 `--flow-gradient` 主按钮，也先保留现有浅色 `--primary`。** 紫色与琥珀色并存不直接视为 bug；先看浅色实际效果，再决定是否需要统一。

浅色配色调整（可选，需明确决定后再改，单独验收）：

- 若浅色实测确认需要统一非渐变控件：调整 `--primary`，同时核对 `--primary-foreground`、`--ring`、文字对比度和焦点状态。  
- 若要求 **主按钮也统一琥珀**：单独立项改 `.flow-generate` / `--flow-gradient`（及 hover/disabled），并检查文字、焦点和对比度；不能假设改 `--primary` 即可。

### 5.2 清理无用 queue CSS

先检索确认没有运行时引用，再按选择器清理无用的 `.flow-queue`、`.flow-queue-bar` 等 queue 样式，不按固定行号整段删除。未命中的 CSS 本身不会呈现假队列，此项仅是 P2 清理。**保留** `.flow-studio` / `.flow-card` / `.flow-generate` 定义；**不要**整段删 studio 区块。
