# 同行方案迁移建议

可以适当参考同行项目，不直接照搬，看同行的对应页面/局部组件有没有可借鉴的写法，然后按当前项目结构落地。 
同行项目：D:\project3\shipany-2\shipany-template-nano-banana1

## 总体判断

当前项目不要再按“功能块”吸收同行改动，应改为按“小补丁”吸收。

核心判断：

- 当前 `bananapro-org` 的生成主链路已经比同行方案更适合本项目。
- 同行的任务调度、dispatch、showcase 大扩展属于另一条架构路线，不能混入当前项目。
- 可以吸收 UI、i18n、即时失败态这类低耦合补丁。
- 不碰核心生图主链，不碰定价和积分账本。

## /activity/ai-tasks 迁移建议

`/activity/ai-tasks` 可以借鉴，但不要整页直接替换。当前项目已经有可用的任务列表、单任务刷新、音频结果展示和图片结果展示；同行方案真正值得迁移的是展示体验，而不是任务架构。

第一阶段原则：

```text
只增强 /activity/ai-tasks 的展示体验；
不改任务生命周期；
不改任务调度；
不改 ai_task schema；
不改 showcase；
不改生成链路；
不改全局表格抽象，除非后续确认复用。
```

### 当前项目状态

当前相关文件：

```text
src/app/[locale]/(landing)/activity/ai-tasks/page.tsx
src/app/[locale]/(landing)/activity/ai-tasks/[id]/refresh/page.tsx
src/app/[locale]/(landing)/activity/layout.tsx
src/shared/blocks/table/index.tsx
src/shared/blocks/table/dropdown.tsx
src/shared/services/moderation.ts
```

现状判断：

- `ai-tasks/page.tsx` 是 Server Component，负责取数和组装表格；需要交互的预览、复制、左右切换应下沉到局部 client component。
- 当前 prompt 列使用 `type: 'copy'`，全局 `Table` 会自动包一层 `Copy`。如果新增 `PromptEllipsis`，prompt 列应改用 `callback`，不要再叠加 `type: 'copy'`。
- result 列现在直接在页面里 `JSON.parse(item.taskInfo)`，并内联处理 failed / music / image，后续应该抽到纯 helper + 局部 cell 组件。
- 当前输出审核只信任规范化后的 `taskInfo.images[].imageUrl` 和 `taskInfo.videos[].videoUrl`。展示 helper 不应递归扫描 raw `taskResult` 里的任意 URL，避免把输入图、缩略图或 provider 内部字段误当成最终结果。
- `table/dropdown.tsx` 和 `NavItem` 是全局抽象，后台、设置页、活动页都在用。第一阶段不要为了图片下载扩展 `downloads/taskId`。
- 用户侧 `ai-tasks` 目前没有 provider 列，所以“image 隐藏 provider”不是修复项；如果后续要做，应理解为“非 image 类型增加 provider 列”，第一阶段可不做。

### task result helper

新增：

```text
src/app/[locale]/(landing)/activity/ai-tasks/_lib/ai-task-result.ts
```

只负责展示层读取结果：

```text
安全解析 taskInfo / taskResult
提取 imageUrls / audioUrls / videoUrls
判断是否有结果
```

建议规则：

- 优先读取规范化 `taskInfo`。
- image 只读 `taskInfo.images[].imageUrl`。
- video 只读 `taskInfo.videos[].videoUrl`。
- music/audio 读 `taskInfo.songs[].audioUrl`。
- `taskResult` 只做已确认结构的浅层 fallback，不做递归 URL 扫描。
- 返回去重后的 http/https URL。
- JSON 解析失败时返回空结果，不让页面崩溃。

不要把它扩展成生成链路工具：

```text
不判断模型价格
不判断模型能力
不判断模型是否单图
不替换 provider 结果解析
不参与 moderation / generate / query
```

这些仍然归 `models.ts`、provider adapter 和生成链路负责。

### task error helper

新增：

```text
src/app/[locale]/(landing)/activity/ai-tasks/_lib/ai-task-error.ts
```

保持非常薄：

```text
errorMessage / errorCode / status -> user-facing i18n key + fallback
```

建议返回结构：

```ts
type AITaskErrorDisplay = {
  key: string;
  fallback: string;
};
```

它不直接调用 `next-intl`，由页面或组件负责 `t(key)`。也不要和 `/api/ai/generate` 里的 candidate error 分类强绑定；一个是任务历史展示，一个是生成时错误聚合，相关但不应耦合。

注意：如果对应 i18n key 暂时不存在，组件层应能回退到 `fallback`，不要让缺翻译影响任务列表渲染。

### TaskResultCell

新增：

```text
src/app/[locale]/(landing)/activity/ai-tasks/_components/task-result-cell.tsx
```

职责：

- 接收 `taskInfo` / `taskResult` / `mediaType` / `status`。
- 调用 `ai-task-result.ts` 解析结果。
- failed / moderation_blocked / moderation_failed 使用 `ai-task-error.ts` 显示稳定文案。
- image 交给 `TaskImageGallery`。
- music/audio 保留现有 `AudioPlayer` + download link 展示。
- video 首阶段可先显示下载链接或简洁 URL，不强行做完整播放器。
- 无结果显示 `-`。

这样 `ai-tasks/page.tsx` 的 result column 只负责传值，不再内联多套 JSON 解析。

### 第二阶段再评估

以下内容放到第二阶段或第三阶段：

- 图片批量下载菜单。
- 如果多个页面都需要下载，再考虑扩展全局 `Dropdown` 或新建更通用 action renderer。
- 页面顶部刷新按钮；如果只是刷新当前列表，优先做 client `router.refresh()`，不要混入单任务 provider query。
- 如果 Works 产品定位确定，再改 sidebar、用户菜单和 `ConsoleLayout hideSidebar`。
- 如果 pending / processing 问题明显，再单独评估 task lifecycle，不要从展示页迁移进去。
- 如果 admin ai-tasks 也要复用，再把局部 `_components` / `_lib` 提升到 shared。

### 不建议迁移的部分

不要把同行的任务调度体系合进来：

- `ai_task_dispatch`
- channel claim / lease / recover
- async showcase sync
- queued task lifecycle

原因：当前项目的任务链路是 `/api/ai/generate` 创建任务，前端轮询 `/api/ai/query` 查询 provider 状态；同行方案是另一套队列化架构。为了改善 `/activity/ai-tasks` 展示，不需要动这条主链路。

也不建议顺手迁移 showcase schema。作品列表页面只需要读取 `ai_task` 的 `taskInfo/taskResult`，与 showcase 表结构无关。

### 验收点

- `/activity/ai-tasks?type=image` 图片任务显示为缩略图，不撑高表格。
- 点击缩略图可以放大预览，多图可左右切换，Esc 可关闭。
- prompt 长文本不会撑宽表格，复制按钮可用，复制的是完整 prompt。
- failed / moderation_blocked / moderation_failed 任务显示用户可理解的失败原因，不直接暴露 provider 原始错误。
- pending / processing 任务仍可 refresh。
- music / video / text 类型筛选不受影响。
- 不修改 `ai_task` schema。
- 不修改生成、查询、调度、审核链路。
- 不修改全局 `table/dropdown.tsx` 和 `NavItem` 类型。
