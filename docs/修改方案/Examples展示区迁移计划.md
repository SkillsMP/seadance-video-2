## 1. 目标与推荐方案

改善 Seadance 首页 Examples 的排版、视频展示和预览体验，复用 Video Lite 已有实现中适合当前项目的部分。

**推荐第一期采用“精选四宫格 + 视频预览弹窗”，素材充足后再升级瀑布流。**

第一期沿用首页现有四条视频，桌面端两列、移动端单列。卡片统一 `16:9`：实测四条都是横版，现有 `3:4` / `9:16` 会把左右裁掉大半。借鉴 Video Lite 的视频卡片、轻量遮罩和预览弹窗，使用 Seadance 当前主题与国际化机制。不新增依赖，不整体搬迁源项目框架。

第一期真正新增的是可见标题、明确播放入口、预览弹窗、复制提示词，以及关闭后停止播放。两列布局和桌面悬停静音预览在现有实现里已经具备雏形，不要当成全新能力重做。点卡片改为打开预览后，弹窗需保留“去生成器”入口，避免 Examples 从引导创作变成只看片。

这是一份待实施计划。本文中的文件、字段和组件名称属于拟定方案；实施时先检查当时的工作区和调用关系，再确定最小变更。

- 本地开发、生产环境文件中的 `NEXT_PUBLIC_THEME` 均配置为 `flow`；线上实际部署配置尚未核验。
- 首页通过 `page.sections.showcases` 提供内容，英文和中文 JSON 各配置四条示例，当前 `columns` 为 `3`。

- `/seedance-2-0` 通过 `block: showcases`、`id: examples` 复用同一套四条视频。第一期只切换首页 Block，该页将继续使用旧展示。

## 4. 第一期交付内容

### 4.1 精选视频画廊

- 保留首页区块位置、`showcases` 数据键和 `#showcases` 锚点。
- 桌面两列，移动端单列；间距、容器宽度与当前页面统一。新 Block 按两列实现；首页 JSON 的 `columns` 同步改为 `2`，避免留下失效配置。
- 使用现有四条视频和封面，不复制重复素材凑数量。
- 新卡片容器统一 `aspect-ratio: 16 / 9`，桌面和手机相同。封面与视频都 `object-cover` 居中。不要复用 `.flow-video-card` 的 `9:16` / `3:4`。
- 卡片使用克制的圆角、轻量底部遮罩、短标题和播放入口；标题与播放入口默认可见。提示词长文放入弹窗，不在卡片上堆完整段落。
- 桌面端延续现有策略：仅当前悬停或聚焦的卡片静音预览，离开后暂停。保持 `preload="none"`，不把 Video Lite 的进视口自动播放搬过来。
- 键盘聚焦提供清楚的可操作状态。移动端点击进入播放器，不依赖 hover 才能发现操作。
- 遵守 `prefers-reduced-motion`；减少动态效果时保留静态封面和主动播放入口，不强制预览播放，也不使用明显的放大动画。

### 4.2 视频预览弹窗

- 借鉴 Video Lite 的播放器与信息区布局。从 `@/shared/components/ui/dialog` 引入 `Dialog`、`DialogContent`、`DialogTitle`，并以 `task-image-gallery.tsx` 的宽弹窗覆盖方式为本地参考。不安装新版本覆盖现有 Dialog。
- 全屏或接近全屏的影院风是目标；若覆盖成本过高，允许先做成克制的宽弹窗，但必须保证播放器、关闭按钮、提示词和去生成器入口都可见。不要落成默认小卡片里塞播放器。
- 桌面端视频与提示词分区，移动端上下排列，保证播放器与关闭操作可见。
- 提供视频播放控件、标题、参考提示词、上一条、下一条、复制提示词，以及“去生成器”按钮（锚到 `#generator`）。第一期仍不自动填入 prompt，也不把示例视频写入生成器。
- 支持 Escape 关闭、焦点约束、关闭后焦点返回卡片，以及弹窗内容滚动。若使用受控 `open` 而不是 `DialogTrigger`，需自行保证焦点返回。
- 关闭或切换示例时停止旧视频，避免后台播放与声音叠加。
- 复制提示词用按钮本地状态，不调用 sonner。根布局里的 `Toaster` 已经存在，这里不用它，是为了反馈留在按钮上，不和生成器、登录的 toast 抢位置。点击后图标从 Copy 变为 Check，文案变为“已复制”，约 2 秒后恢复。复制失败也走同一颗按钮，短暂显示“复制失败”，不要一半内联、一半 toast。播放失败仍用弹窗内的可见回退文案。这些文案提供中英文版本。
- 模型、分辨率等附加信息只在来源可靠时展示。

第一期不接入“一键填入生成器”“使用视频作参考”，也不默认增加下载入口。它们不是完成本轮视觉改善的必要条件。去掉卡片直达生成器后，弹窗里的“去生成器”是保留转化路径的最低要求。

### 4.3 画框规则

媒体实测已完成，第一期画框定为统一 `16:9`。桌面和手机都用这个比例，不再按真实比例逐卡混排，也不为 `showcase-1` 单独留边。

- `showcase-2`、`showcase-3`、`showcase-4` 在 `16:9` 容器里用 `object-cover`，画面与画框对齐，左右不再被裁。
- `showcase-1` 是 `3:2`。放进 `16:9` 再 `cover`，上下大约还会切掉 16%。这比现在的左右大裁轻得多，第一期接受，不为它改成 letterbox，也不把四张卡拉成不同高度。
- 四张封面都是 `1024 × 1024`。在 `16:9` 容器里 `object-cover` 居中时，上下会被裁。封面只是起播前的占位，构图保持居中即可；视频起播后由视频比例接管。
- 新卡片写自己的 `16:9` 规则，不修改、不复用全站 `.flow-video-card`。
- 弹窗播放器按视频原始比例完整显示，用 `object-contain`，不要再套卡片上的裁切。

- [ ] 卡片在桌面和手机都是 `16:9`，不再使用 `3:4` / `9:16`。三条 16:9 视频左右不再被裁；`showcase-1` 仅有轻微上下裁切。封面加载时不发生明显布局跳动。
- [ ] 每张卡片有默认可见的标题及播放入口，点击打开预览，不再直接跳到生成器。
- [ ] 弹窗播放、前后切换、关闭可用；复制提示词后按钮变为已复制并在约 2 秒后恢复，失败也显示在同一按钮上。关闭或切换后旧视频停止。弹窗内视频按原始比例完整显示。
- [ ] 弹窗提供回到 `#generator` 的入口；第一期不自动填入 prompt。
- [ ] 键盘可以进入和退出弹窗，焦点不会丢失；触屏操作无需 hover。
- [ ] 减少动态效果时不会强制预览播放，播放失败有合理回退。
- [ ] 英文、中文和明暗主题均可读，长提示词不会挤出主要操作。
- [ ] 中英文四条媒体文件顺序与地址一一对应。
- [ ] `#showcases` 导航继续有效，首页区块顺序保持不变。
- [ ] 视频 JSON-LD 使用的原有元数据仍完整，内容与页面展示对应。
- [ ] `/seedance-2-0` 及其他页面继续使用原有展示实现；该页视觉落后不记为本轮缺陷。
- [ ] 生成、计费和登录流程没有接入新逻辑。
- [ ] 没有新增依赖、无关格式化或超出范围的重构。

验证优先使用项目现有的定向 ESLint、Prettier 检查和 `pnpm build`。不为纯布局改动新增测试框架；已有历史检查错误应与本次引入的问题区分记录，不夸大通过范围。

## 11. 回退与风险

- **回退：**将首页中英文 `showcases.block` 恢复为 `showcases`，即可重新使用旧展示。保持 `id: showcases` 不变。通过 Git 按本次提交范围回退新增文件和内容字段，不依赖数据库操作。
- **素材风险：**四条素材的题材与构图会限制画廊丰富度；第一期改善不能等同于 17 条混合比例素材的完整效果。统一 `16:9` 后，`showcase-1`（3:2）上下仍有约 16% 裁切，封面（1:1）在起播前上下也会被裁。这是已接受的取舍，不为此拆开画框。
- **弹窗适配风险：**Video Lite 是自定义全屏播放器，本仓库 Dialog 默认是小卡片。这是第一期最大的实现风险。优先做可用的宽弹窗播放器，再视覆盖成本决定是否接近全屏影院风。
- **转化风险：**去掉卡片直达生成器后，若弹窗没有“去生成器”，Examples 会失去创作引导。第一期用锚点按钮保住路径，不做自动填入。
- **性能风险：**多个视频同时准备预览会增加网络和解码负担。第一期限制为封面优先、仅当前卡预览，不引入进视口自动播放。
- **兼容风险：**WebM 在目标设备上的实际播放表现需验收，但这是存量地址上的既有风险。如需备用编码，单独确认素材处理范围，不并入本轮。
- **页面不一致：**首页升级后，`/seedance-2-0` 的 `#examples` 会继续使用旧四宫格直达生成器。这是范围隔离的结果，实施记录中写明即可。
- **迁移风险：**源项目的国际化、模型名称与回调接口不能直接复制，按本计划在展示层适配。
- **当前验证边界：**画框比例已用 ffprobe 核实。计划尚未实施，浏览器视觉对比、构建和设备上的 WebM 播放验收仍未做。
