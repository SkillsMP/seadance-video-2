## 2026-06-07 AI 生成候选失败错误可观测性优化

### 修改范围

- `src/extensions/ai/kie.ts`
- `src/app/api/ai/generate/route.ts`

### 修改目的

- 修复前端只看到 `All model candidates failed` 的泛化错误问题。
- 增强 KIE provider 请求失败时的服务端日志，方便定位网络超时、HTTP 400/401/403/429 等问题。
- 保持最小入侵：不改模型配置、定价、checkout、webhook、积分账本、前端 generator，也不引入代理或全局错误框架。

### 主要改动

- 在 `kie.ts` 新增本地 `fetchKie()` helper：
  - `fetch` 网络错误记录 `apiUrl`、`model`、`taskId`、`inputKeys`、`error.name`、`error.message`、`error.cause`。
  - HTTP 非 2xx 响应记录 `status`、`statusText`、截断后的 `bodySnippet`。
  - 删除原有 `console.log('kie input', apiUrl, payload)`，避免打印完整 prompt、图片 URL、视频 URL。
- 在 `generate/route.ts` 将 `candidateErrors` 从字符串数组改为结构化对象数组。
- 新增局部错误分类：
  - 网络超时、连接重置、DNS 错误、连接拒绝。
  - HTTP 400/401/403/429。
  - provider 余额类错误。
- 所有候选模型失败时：
  - 服务端日志记录完整结构化 `candidateErrors`。
  - 前端只返回安全、可理解的用户提示。
  - 错误类型混杂或未知时回退到通用提示。

### 验证结果

- `pnpm lint` 通过。
  - 仍存在仓库原有 15 个 React Hooks warning，与本次改动无关。
- `npx tsc --noEmit` 通过。
- `git diff --check` 无 whitespace 错误。

### 注意事项

- 本次没有加入 `ProxyAgent` 或代理能力。后续只有在线上日志确认持续出现网络连接问题时，再单独评估代理支持。
- 本次没有新增 `ProviderError` 类或全局错误系统，避免过度设计。
