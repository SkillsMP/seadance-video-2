# 价格配置抽离方案

现在状态可以这样重新梳理：

```text
已完成：
阶段 1：pricing + credit-costs 基建
scene fallback 已调高
```

接下来不要再纠结旧的 `6 / 8 / 10` 低兜底问题，重点变成：**模型配置、扣费配置、规格参数之间如何不脱节。**

当前最重要的原则是：

```text
MODEL_OPTIONS 里出现的每一个 family + scene，
都必须在 src/config/ai/credit-costs.ts 里有明确扣费。
```

`scene fallback` 只作为安全兜底，不作为主定价。只要一个模型能在前台被选中，就不能长期依赖 fallback 扣费。

---

## 阶段顺序

```text
阶段 1：pricing + credit-costs 基建
已完成。

阶段 1.5：补齐当前想要上线 / 测试的 MODEL_OPTIONS
先把 nano-banana / nano-banana-2 / nano-banana-pro / seedance 2.0 等当前要验证的模型补进 image.tsx / video.tsx。先上 KIE.ai 这个厂商。

阶段 1.6：同步 credit-costs.ts
每个新增 family + scene 都要有明确扣费。

阶段 2：再抽 src/config/ai/model-options.ts
把已经验证过的 MODEL_OPTIONS 抽出来。

阶段 3：加模型和扣费一致性校验
防止以后新增模型时漏配积分。

阶段 4：再做 model-specs.ts
处理 4K / duration / audio / reference image / web search 等规格参数。

阶段 5：让扣费支持 creditKey / options
用于同一个 family 下不同规格的差异化扣费。
```

一句话：**先把模型清单补完整，再抽配置；不要先抽一个半成品。**

---

# 阶段 1.5：补齐当前 MODEL_OPTIONS

在抽 `model-options.ts` 之前，先把当前真正想要上线或测试的模型补进现有组件：

```text
图片模型：
src/shared/blocks/generator/image.tsx

视频模型：
src/shared/blocks/generator/video.tsx
```

原因很简单：如果现在先抽配置，只是在抽一份“不完整的模型列表”。后续再补模型时，仍然会遇到模型清单、扣费配置、规格参数不同步的问题。

## 1. 先补文档 3 的模型积分消耗表

先在 `docs/定价/3.本项目定价方案.md` 的「模型积分消耗表」里明确要上线模型的积分。这里要写确定值，不要写范围。

当前建议先明确这些锚点：

```text
nano-banana = 5 credits
nano-banana-2 = 15 credits
nano-banana-pro = 20 credits

seedance-2-fast-720p = 90 credits
```

注意：

- 文档里的 `代码 family key` 必须和前端真实传给后端的 `family` 字符串一致。
- 如果最终代码使用的是 `nano-banana-basic`，文档就写 `nano-banana-basic`；如果代码使用 `nano-banana`，文档就写 `nano-banana`。
- 不允许只按展示名猜 key。
- Seedance 2.0 不要只写一个泛化的 `seedance-2.0` 价格，必须按实际开放规格拆档，例如 `seedance-2-fast-480p`、`seedance-2-fast-720p`、`seedance-2-standard-720p`。

本期先上 KIE.ai，当前模型 id 固定为：

```text
nano-banana text-to-image：google/nano-banana
nano-banana image-to-image：google/nano-banana-edit
nano-banana-2：nano-banana-2
nano-banana-pro：nano-banana-pro
seedance-2-fast-720p：bytedance/seedance-2-fast
sora-2-pro text-to-video：sora-2-pro-text-to-video
sora-2-pro image-to-video：sora-2-pro-image-to-video
```

## 2. 再补当前代码里的 MODEL_OPTIONS

图片模型放在：

```text
src/shared/blocks/generator/image.tsx
```

视频模型放在：

```text
src/shared/blocks/generator/video.tsx
```

图片模型示例：

```ts
{
  family: 'nano-banana',
  value: 'google/nano-banana',
  label: 'Nano Banana',
  provider: 'kie',
  scenes: ['text-to-image'],
},
{
  family: 'nano-banana',
  value: 'google/nano-banana-edit',
  label: 'Nano Banana',
  provider: 'kie',
  scenes: ['image-to-image'],
},
{
  family: 'nano-banana-2',
  value: 'nano-banana-2',
  label: 'Nano Banana 2',
  provider: 'kie',
  scenes: ['text-to-image', 'image-to-image'],
},
{
  family: 'nano-banana-pro',
  value: 'nano-banana-pro',
  label: 'Nano Banana Pro',
  provider: 'kie',
  scenes: ['text-to-image', 'image-to-image'],
}
```

这里的 `value` 必须按厂商 API 文档或当前 provider 实际支持的 model id 填，不能凭模型名称猜。暂时不能确认真实 model id 的模型，不要直接开放到可选列表，可以先留 TODO 或注释。

视频模型同理：

```ts
{
  family: 'seedance-2-fast-720p',
  value: 'bytedance/seedance-2-fast',
  label: 'Seedance 2.0 Fast 720p',
  provider: 'kie',
  scenes: ['text-to-video'],
}
```

如果本期只开放 `text-to-video`，`scenes` 就只写 `text-to-video`。不要提前把 `image-to-video` 写进 `MODEL_OPTIONS`，除非后端参数、扣费和实际 provider route 都已经准备好。

## 3. 当前先不要混入 specs

这一阶段只处理模型清单和基础扣费，不处理：

```text
4K
1080p
duration
audio
reference image 数量
web search
```

第一版只开放标准规格，例如：

```text
图片：1K / 2K 标准档
视频：720p 或固定短时长标准档
```

4K / 1080p / 音频 / 时长选择，等 `model-specs.ts` 阶段再做。否则现在会同时碰到模型列表、积分扣费、规格参数、provider 参数、UI 选择器和后端 options 扣费，复杂度会过早放大。

阶段 1.5 的验收标准：

```text
当前要上线 / 测试的模型，已经出现在对应生成器 MODEL_OPTIONS 中。
每个 option 的 family、value、provider、scenes 都是明确的。
value 使用真实 provider model id，不使用猜测值。
```

# 阶段 1.6：同步 credit-costs.ts

补完 `MODEL_OPTIONS` 后，立即同步：

```text
src/config/ai/credit-costs.ts
```

规则是：

```text
MODEL_OPTIONS.family + MODEL_OPTIONS.scenes[n]
必须能命中 FAMILY_CREDIT_COST_OVERRIDES[family][scene]
```

图片模型示例：

```ts
'nano-banana': {
  'text-to-image': 5,
  'image-to-image': 5,
},

'nano-banana-2': {
  'text-to-image': 15,
  'image-to-image': 15,
},

'nano-banana-pro': {
  'text-to-image': 20,
  'image-to-image': 20,
},
```

视频模型要按实际 scene 写，不要只写 family：

```ts
'seedance-2-fast-480p': {
  'text-to-video': 45,
},

'seedance-2-fast-720p': {
  'text-to-video': 90,
},

'seedance-2-standard-720p': {
  'text-to-video': 150,
},
```

如果后面开放图生视频，再补对应 scene：

```ts
'seedance-2-fast-720p': {
  'text-to-video': 90,
  'image-to-video': 120,
},
```

但不要提前写一个还没有开放、没有验证 route 的 scene。`credit-costs.ts` 应该反映真实可用能力，而不是愿望清单。

阶段 1.6 的验收标准：

```text
每一个前台可选模型，都有明确 family + scene 扣费。
fallback 只在未知模型或异常输入时兜底。
新增模型不会因为漏配 family override 而走 scene fallback。
```

# 阶段 2：抽出模型注册表

等当前 `MODEL_OPTIONS` 补完整并验证后，再新增：

```text
src/config/ai/model-options.ts
```

把现在散在：

```text
src/shared/blocks/generator/image.tsx
src/shared/blocks/generator/video.tsx
```

里的 `MODEL_OPTIONS` 抽出来。

建议结构：

```ts
export const IMAGE_MODEL_OPTIONS = [
  {
    mediaType: 'image',
    family: 'nano-banana-pro',
    value: 'nano-banana-pro',
    label: 'Nano Banana Pro',
    provider: 'kie',
    scenes: ['text-to-image', 'image-to-image'],
  },
];

export const VIDEO_MODEL_OPTIONS = [
  {
    mediaType: 'video',
    family: 'sora-2-pro',
    value: 'sora-2-pro-text-to-video',
    label: 'Sora 2 Pro',
    provider: 'kie',
    scenes: ['text-to-video'],
  },
];
```

然后 `image.tsx / video.tsx` 只 import，不再自己维护模型表。

阶段 2 的目标是解决：

```text
模型加了，但积分没配
模型散落在组件里，不知道哪里是权威来源
```

阶段 2 的验收标准：

```text
新增模型时，不再去组件里到处找 MODEL_OPTIONS。
模型注册统一在 src/config/ai/model-options.ts。
生成器组件只消费模型配置，不再定义模型配置。
```

# 阶段 3：加模型和扣费一致性校验

新增：

```text
src/config/ai/validate-config.ts
```

校验逻辑：

```text
遍历 IMAGE_MODEL_OPTIONS 和 VIDEO_MODEL_OPTIONS
对每一个 option.scenes 里的 scene
检查 credit-costs.ts 是否存在 option.family + scene 的明确扣费
```

缺失时，开发环境先 warning：

```text
Missing credit cost override: family=nano-banana-2 scene=text-to-image
```

后面成熟后可以让 CI 失败。

这个阶段能防止以后再次出现：

```text
Sora 2 Pro text-to-video 漏配
结果走 fallback
```

即使 fallback 已调高，也不应该长期依赖 fallback。

阶段 3 的验收标准：

```text
本地开发时可以直接发现 MODEL_OPTIONS 和 credit-costs.ts 不一致。
新增模型漏配积分时，有明确报错或 warning。
```

# 阶段 4：抽模型规格参数

再下一步才处理：

```text
4K
1080p
duration
audio
reference image 数量
web search
```

新增：

```text
src/config/ai/model-specs.ts
```

例如：

```ts
export const MODEL_SPECS = {
  'nano-banana-pro': {
    resolutions: [
      {
        value: '1k-2k',
        label: '1K / 2K',
        creditKey: 'nano-banana-pro',
        default: true,
      },
      {
        value: '4k',
        label: '4K',
        creditKey: 'nano-banana-pro-4k',
      },
    ],
  },
};
```

这一阶段的关键是引入：

```text
creditKey
```

因为同一个 family 下面可能有不同规格：

```text
Nano Banana Pro 1K / 2K = 20 credits
Nano Banana Pro 4K = 30 credits
```

如果只靠 family，就区分不了。

阶段 4 的验收标准：

```text
规格选择不再硬编码在 UI 里。
同一模型的不同规格可以映射到不同 creditKey。
低成本标准规格和高成本规格不会混用同一个扣费 key。
```

---

# 阶段 5：让扣费支持 creditKey / options

现在扣费主要是：

```text
family + scene -> credits
```

以后要升级成：

```text
creditKey + scene -> credits
family + scene -> credits
scene fallback
```

优先级：

```text
1. creditKey override
2. family override
3. scene fallback
```

这样选择 4K 时，可以扣：

```text
nano-banana-pro-4k + text-to-image = 30
```

而不是误用：

```text
nano-banana-pro + text-to-image = 20
```

这个阶段需要改 `/api/ai/generate`，让后端扣费能拿到 `options` 或 `creditKey`。

阶段 5 的验收标准：

```text
后端扣费能识别同一 family 下的不同规格。
4K / 1080p / audio / duration 等高成本选项可以独立扣费。
family fallback 仍然保留，但不再承担规格差异扣费。
```
