# 排版与字体最小改动方案

## 目标

参考同门项目 `D:\project3\shipany-2\bananapro-org-balanced` 的字体观感和页面排列，在不大范围复制组件、不改变业务逻辑的前提下，改善当前项目的页面密度、文字换行和内容排列。

本文仅记录讨论结论，暂不修改代码。

## 对比结论

两个项目的以下部分基本一致：

- `global.css`
- `theme.css`
- Header
- Hero
- Landing Layout
- 全局 `.container` 宽度
- 首页文案及大部分区块配置

因此，balanced 项目看起来更协调，并不是因为全站重新设置了字号或容器，而主要来自：

1. 全站字体不同。
2. 首页生成器上下间距更紧凑。
3. Create 页面减少了生成器前的重复内容。
4. Prompts 页面使用规则网格，而不是瀑布流。

## 一、优先修复全站字体

### 当前问题

当前项目在 `src/app/layout.tsx` 中将 `Noto_Sans_Mono` 绑定到了全局 `--font-sans`：

```tsx
import { JetBrains_Mono, Merriweather, Noto_Sans_Mono } from 'next/font/google';

const notoSansMono = Noto_Sans_Mono({
  subsets: ['latin'],
  variable: '--font-sans',
  display: 'swap',
  preload: true,
});
```

并在 `<html>` 上加载：

```tsx
className={`${notoSansMono.variable} ${merriweather.variable} ${jetbrainsMono.variable}`}
```

而 `global.css` 的 `body` 使用了 `font-sans`，所以正文、导航、按钮和标题实际都继承了等宽字体。

等宽字体会造成：

- 英文字符整体偏宽。
- 长标题更容易换行。
- 导航和按钮看起来拥挤。
- 卡片文字占用更多高度。
- 页面在视觉上像是字号偏大。

balanced 项目取消了该覆盖，使用 `theme.css` 中定义的系统无衬线字体栈。

### 最小修改建议

在 `src/app/layout.tsx` 中：

1. 从 import 中移除 `Noto_Sans_Mono`。
2. 删除 `notoSansMono` 初始化代码。
3. 从 `<html>` 的 `className` 中移除 `notoSansMono.variable`。
4. 保留 `Merriweather` 和 `JetBrains_Mono`，避免影响衬线字体和代码字体。

示意：

```tsx
import { JetBrains_Mono, Merriweather } from 'next/font/google';

className={`${merriweather.variable} ${jetbrainsMono.variable}`}
```

### 预期效果

这是优先级最高、影响范围最大、代码改动最小的一项。修复后即使不调整字号，也会明显改善：

- 字宽
- 标题换行
- 导航密度
- 按钮宽度
- 卡片高度
- 中英文混排

不建议先在 `global.css` 中强制降低基础字号。当前主要问题是字体类型，而不是 `16px` 的默认字号。

## 二、收紧首页生成器间距

### 当前情况

当前图片生成器的默认外层间距是：

```tsx
py-16 md:py-24
```

balanced 首页模式使用：

```tsx
py-8 md:py-10
```

这会让 Hero 和生成器之间的衔接更紧凑，首屏的信息密度更合理。

### 最小修改建议

当前 `ImageGenerator` 已支持 `className`，不需要复制 balanced 项目的 `variant="home"` 及附加导航卡片。

只需在：

`src/app/[locale]/(landing)/page.tsx`

将生成器改成：

```tsx
<ImageGenerator
  className="py-8 md:py-10"
  srOnlyTitle={t.raw('generator.title')}
/>
```

### 不建议照搬的内容

balanced 项目的首页模式还增加了：

- 圆角引导卡片
- Text to Image 按钮
- Image to Image 按钮
- Prompts 按钮
- 英文说明文字

这些并不是解决基础排版所必需的，而且会增加组件复杂度和本地化工作量。

## 三、简化 Create 页面排列

### 当前情况

当前 Create 页面在生成器前渲染了一个 `custom-features` 区块：

```tsx
"features": {
  "block": "custom-features",
  title: t.raw('page.title'),
  description: t.raw('page.description'),
},
```

随后才渲染生成器。

这会让工具页顶部出现一段重复介绍，用户需要继续向下滚动才能进入核心操作区域。

balanced 项目删除了该区块，直接展示生成器。

### 最小修改建议

在：

`src/app/[locale]/(landing)/create/page.tsx`

执行以下调整：

1. 删除 `features` 区块。
2. 给生成器传入较紧凑的页面间距。

示意：

```tsx
const page: DynamicPage = {
  sections: {
    generator: {
      component: (
        <ImageGenerator
          className="py-8 md:py-12"
          srOnlyTitle={t.raw('generator.title')}
          promptKey={promptKey}
        />
      ),
    },
  },
};
```

### 不建议照搬的内容

balanced 项目还给 Create 页面增加了完整工具侧栏，包括：

- Text to Image
- Image to Image
- AI Video
- Prompts
- AI Tasks
- Credits
- 移动端 Sheet 菜单

这部分涉及大量组件代码和硬编码英文，不属于最小排版调整。除非后续明确要把 Create 页面改成完整工作台，否则不建议复制。

## 四、Prompts 页面改为规则网格

### 当前情况

当前 Prompts 列表使用 CSS columns：

```tsx
columns-1 gap-5 md:columns-2 xl:columns-3
```

CSS columns 属于瀑布流排列，项目顺序是从上到下再进入下一列。不同卡片高度会造成页面左右边界和阅读顺序不够稳定。

balanced 项目改用了普通 Grid：

```tsx
grid gap-6 md:grid-cols-2 xl:grid-cols-3
```

这种排列更整齐，卡片按行阅读，也更符合工具库页面。

### 最小修改建议

在：

`src/themes/default/blocks/prompt-library.tsx`

将列表容器从：

```tsx
<div className="mt-10 columns-1 gap-5 md:columns-2 xl:columns-3">
```

修改为：

```tsx
<div className="mt-10 grid gap-6 md:grid-cols-2 xl:grid-cols-3">
```

卡片当前包含：

```tsx
mb-5 break-inside-avoid rounded-lg
```

改为 Grid 后可删除：

```tsx
mb-5 break-inside-avoid
```

如果希望更接近 balanced 的视觉，可以再把：

```tsx
rounded-lg
```

改为：

```tsx
rounded-3xl
```

圆角调整属于可选项，不影响核心排列。

### 不建议整文件复制

balanced 的 `PromptLibrary` 不只是样式变化，还包含：

- 将服务端数据查询改为客户端 `/api/prompts` 请求。
- 调整加载状态和错误处理。
- 修改分享链接逻辑。
- 修改 Breadcrumb 生成方式。
- 增加部分硬编码英文。
- 改变卡片信息和操作按钮布局。

这些改动会扩大行为风险。当前只需要复制 Grid 和少量 className，不应覆盖整个文件。

## 推荐实施顺序

### 第一阶段

只修改全站字体。

修改文件：

- `src/app/layout.tsx`

完成后检查：

- Header 是否更紧凑。
- Hero 标题换行是否减少。
- 按钮宽度是否正常。
- 生成器表单标签是否更易读。
- 中文页面是否保持正常。

### 第二阶段

调整首页和 Create 页面间距。

修改文件：

- `src/app/[locale]/(landing)/page.tsx`
- `src/app/[locale]/(landing)/create/page.tsx`

### 第三阶段

调整 Prompts 页面排列。

修改文件：

- `src/themes/default/blocks/prompt-library.tsx`

## 最小改动清单

| 优先级 | 修改 | 文件 | 风险 |
| --- | --- | --- | --- |
| P0 | 取消全站等宽字体 | `src/app/layout.tsx` | 低 |
| P1 | 首页生成器改为紧凑间距 | `src/app/[locale]/(landing)/page.tsx` | 低 |
| P1 | 删除 Create 页重复介绍区 | `src/app/[locale]/(landing)/create/page.tsx` | 低 |
| P2 | Prompts 瀑布流改 Grid | `src/themes/default/blocks/prompt-library.tsx` | 低 |
| 可选 | Prompts 卡片改大圆角 | `src/themes/default/blocks/prompt-library.tsx` | 低 |

## 最终建议

先只执行字体修改并观察效果。当前项目“字号偏大、页面较挤”的主要原因，很可能是把等宽字体误用为全站普通字体。

字体修复后，再决定是否需要调整首页间距和 Prompts 网格。不要直接复制 balanced 项目的完整生成器或 PromptLibrary，因为其中混入了功能、请求方式和本地化方面的变化，不符合最小改动原则。
