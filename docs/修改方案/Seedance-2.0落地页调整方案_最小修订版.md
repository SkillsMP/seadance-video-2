# Seedance 2.0 落地页调整初稿

日期：2026-10-14  
目标页面：https://seadance.video/seedance-2-0  
状态：讨论初稿，尚未实施。

## 1. 第一阶段目标

先把页面模块搭起来，形成一个完整、可复用的模型落地页样板。后续项目可以沿用模块结构，再替换模型、能力、参数、价格和案例。

参考 Seevio 的语义分层，以及 HuMo 的“输入支持 → 输出规格 → 积分消耗”组织方法：

- https://seevio.ai/
- https://www.humoai.co/seedance-2

这一阶段采用“标准 Block + 模型页样板”，保留现有视觉风格和生成器，重点是模块完整、顺序合理、桌面和手机可用。可复用的是模块结构、标题槽位和规格数据来源，不是本页的 Seedance 文案或参数。精细关键词布局、段落润色、补充案例素材和转化优化放到第二阶段。

H2 槽位固定，显示文案由语言 JSON 配置，结合模型名和用户问题自然命名，例如 `Seedance 2.0 Video Examples`、`Seedance 2.0 Features & Workflows`、`Seedance 2.0 Specifications & Credits`、`How to Use Seedance 2.0`。不把所有 H2 固定成裸词，也不要求每个标题机械重复模型名；标题或相邻导语应清楚交代所属模型与工作流。

原有长提示词示例不再单独占一个大模块：教程中保留一个短例子，完整内容链接到现有提示词指南。

可复用的是下面这 10 段结构约定，不是本页 JSON 全文。换模型页时：沿用 `page.tsx` 的生成器注入方式，替换语言 JSON 文案，给规格块换模型族过滤。不要复制 Seedance 的分辨率、时长、积分或能力声明。

| 顺序 | section key | block | 数据 |
|---|---|---|---|
| 1 | `hero` | `hero` | 文案 JSON；全页一个 H1；平台身份 tip |
| 2 | `generator` | 页面注入 `component` | 沿用现 `seedance-2-0/page.tsx` 模式 |
| 3 | `examples` | `showcases` | 无合格素材则 `disabled: true` |
| 4 | `capabilities` | `features` | 只写本页模型族真实工作流 |
| 5 | `specifications` | `model-specs`（新增服务端块） | JSON 配模型范围及标题等；规格、费率和成本来自注册表与现有计费函数 |
| 6 | `useCases` | `features` | 4 张卡：场景标题 + 具体任务 + 建议工作流 |
| 7 | `howTo` | `features` 或 `features-step` | 三步；完整 prompt 外链 |
| 8 | `faq` | `faq` | 与规格同源；继续输出 FAQ JSON-LD |
| 9 | `related` | 支持链接的列表块，必要时新增 `related-resources` | 只链已存在且意图匹配的 URL；不用不渲染链接的 `features` 代替 |
| 10 | `cta` | `cta` | `#generator` + `/pricing` |

JSON 的 `sections` 必须按上表键名和顺序书写。How-to 若需要步骤样式，优先 `features-step`，避免与 Features 视觉完全重复。

### 模板复用边界

- 第一阶段完成标准 Block、Seedance 2.0 样板配置和简短复用说明，不建设通用页面引擎。
- 规格块使用 `mediaType`、明确的 `modelFamilies` 列表及可选 `scenes` 选择展示范围。本站 Seedance 2.0 使用 `seedance-2-fast`、`seedance-2-standard`、`seedance-2-mini`，不使用不存在的 `seedance-2` family 或名称前缀猜测。
- 视频按秒计费时显示每秒积分与合法时长实例；未来图片模型按次计费时显示每张/每次积分，不套用“积分/秒、10 秒”列。
- 输入数量、格式等不能从注册表完整推导的信息，采用现有校验约束或已核实的补充说明，不自动猜测。
- Use Cases 复用 `features`，增加可选列数配置支持本页桌面四列，未配置时保持既有三列行为；其他模型的场景数量由真实内容决定。
- 后续首页、Image to Video 等功能页复用 Block，但分别组织信息结构，不强套模型页的十段顺序。本轮不改造这些页面。

## 3. 第一阶段搭建要求

### 规格与计费模块

一个模块内分为四个小标题：

1. **Input Support**：能输入什么，采用哪种输入方式。
2. **Output Specifications**：按型号和工作流展示时长、分辨率、画幅。
3. **Limits**：该型号/工作流不支持什么。至少写明 Mini 无视频转视频、Fast/Mini 无 1080p、视频转视频时长仅配置中的选项（当前为 5s/10s）。配置启用 ≠ Provider 当时可生成。
4. **Credit Consumption**：按型号 × 工作流 × 分辨率展示每秒积分，以及该行真实可选时长的成本实例（默认 10 秒；若该组合没有 10 秒，改用该行实际可选时长，不硬乘 10）。

先完成表格结构与真实基础数据，不增加价格计算器或复杂交互。由服务端从 `src/config/ai/models.ts` 读取已启用的型号、场景与规格，成本复用现有计费函数，不在语言 JSON 中手填价格或另写计费规则。不要复用 `comparison-table`（它是前端对比块，且依赖 JSON 格子）。规格块作为独立的 `model-specs` Block 接入现有主题加载机制，JSON 配置模型范围和展示文案，无需每个模型页重复编写规格注入逻辑。

布局采用“输入与限制紧凑列表 + 输出与计费表格”：桌面端 Input Support 与 Limits 可并列，手机端纵向排列；支持或限制状态必须配文字，不能只靠颜色或图标表达。输出与计费使用原生 `<table>`、`<thead>`、`<tbody>`、`<tr>`、`<th>`、`<td>`，表头标明单位和对应关系，不用纯 `<div>` 模拟表格。宽表格只在模块内横向滚动。

### 价格展示要求

第一阶段加入价格信息，放在“规格与计费”模块内，不另建套餐模块。

- 积分价格表覆盖当前已启用的 Fast、Standard、Mini 组合。同一型号、同一分辨率在文生/图生与视频转视频下积分不同，必须分行，不能写成型号统一价。
- 表格列固定为：型号、工作流、分辨率、积分/秒、示例时长、该时长所需积分。
- 仅展示配置中已启用的型号、工作流及分辨率；不出现 Mini 的视频转视频行，也不出现 Fast/Mini 的 1080p 行。
- 表格下放“查看套餐 / View Plans”按钮，链接到 `/pricing`。订阅套餐、积分包和美元价格由价格页统一维护。
- 补充简短说明：浏览和配置生成器无需先登录，提交生成需要账户和足够积分；提交前可在生成器确认积分预估。
- 页面表格、生成器预估和涉及费用的 FAQ 使用同一配置与计费结果，避免手填价格造成不一致。

### 案例与场景模块

- 案例可复用现有支持视频的 Showcases 组件，但素材须先确认确由 Seedance 2.0 生成，不补写未知型号和参数。
- 本地预览可保留待补素材位置；生产页没有合格素材时隐藏案例模块及相应按钮，不发布空卡片。
- 案例模块统一使用 `id="examples"`。页面组装时用同一次可见性判断处理素材为空、`disabled: true` 或模块未选中的状态，同步隐藏本页 Hero、导航、底部指向 `#examples` 的链接。
- 场景卡片采用“场景标题 + 具体任务 + 建议工作流”，先用简短文字搭建，不强制新增图片。
- 功能声明与本站实际开放能力一致，不从竞品复制参数或支持承诺。

### 组件与布局

- 沿用现有动态页面和语言 JSON。渲染顺序等于 `page.sections` 的键插入顺序，必须按第 2 节物理重排 JSON 键；只改文案不会改变模块顺序。新增模块须正确指定 `block`，否则该段不会渲染。
- 优先复用 Hero、Showcases、Features、FAQ、CTA 和已有 UI Table。
- 新增组件限于规格与计费，以及必要的资源链接展示；通过标准 Block 复用，不引入新框架与依赖。
- 相关资源先用现有列表或卡片布局，只链接真实存在、且属于 Seedance 2.0 意图的页面。
- 保持生成器靠前；手机端纵向排列，宽表格只在模块内部横向滚动。
- Hero 不设置整屏最小高度，压缩上下留白。在桌面 1440×900、默认缩放下，首屏同时看到 H1 和生成器顶部工作流/模型控件；手机端保持正常阅读与触控空间，不强塞全部控件。
- 规格、计费、FAQ 答案和内链优先随服务端 HTML 输出；验收检查渲染后的 HTML，不只检查页面可见性或 JSON-LD。
- 同步维护已有英文、中文对应内容，不因此新增语言路由；当前 `locales = ['en']`，中文页面上线不列入第一阶段验收。

### SEO 与语义要求

- 全页唯一 H1 放在 Hero；Generator、Showcases 不额外输出 H1。主要模块使用 H2，工作流、输入、输出、限制和计费等子概念使用 H3 或对应的语义列表。
- 模型页承接 Seedance 2.0 在线生成和型号决策；教程、提示词与功能详解以摘要加内链承接，不在模型页完整重复。是否意图重叠取决于内容与用户需求，不把跨模型内链直接等同于关键词蚕食。
- FAQ 回答与规格同源，已有 JSON-LD 与页面可见内容一致。FAQ 用于回答真实问题，不把结构化数据作为排名、精选摘要或 AI 引用保证。
- 截至本稿日期，Google 已停止展示 FAQ 富媒体搜索结果；保留现有 JSON-LD 不以获得该展示为验收目标。参考：[Google Search Central 更新记录](https://developers.google.com/search/updates)。SSR、原生表格和清晰标题用于提升可访问性、可抓取性与可理解性，不承诺搜索收益；参考：[Google AI 搜索功能说明](https://developers.google.com/search/docs/appearance/ai-features)。

### 本阶段边界

第一阶段不修改生成器交互、模型筛选、生成请求、积分扣减、登录、支付或 Provider。当前生成器还包含其他视频模型，本阶段保留，但应提示用户选择 Seedance 2.0；第二阶段再处理模型页专属筛选。

不新建教程或场景页，不增加评价、用户数量、效果排名或未经验证的能力声明。

## 4. 完成标准与第二阶段

第一阶段验收：

- [ ] 模块按上述顺序出现，既有生成器正常工作。
- [ ] 规格模块包含输入、输出、限制、积分四个部分，已展示的内容与现有配置一致（含 Mini/V2V/1080p 差异）。
- [ ] 积分价格表按型号 × 工作流 × 分辨率分行，示例成本与现有计费函数一致，“查看套餐”按钮指向 `/pricing`。
- [ ] FAQ 对时长、分辨率、竖屏、型号差异和费用给出与规格表一致的短答案，并写入 FAQ 结构化数据。
- [ ] 四个应用场景、三步教程、FAQ、相关资源和 CTA 完整可见。
- [ ] 案例位置可复用；没有合格素材时，生产页隐藏模块且没有失效锚点。
- [ ] 分别检查案例有素材、无素材、`disabled: true` 三种状态，模块与所有 `#examples` 链接同步。
- [ ] 页面只有一个 H1，H2/H3 层级合理；检查规格表、FAQ 答案和内链在渲染 HTML 中可读取，FAQ 与结构化数据一致。
- [ ] 输出与计费在 HTML 中为原生表格，含表头、单位；标题或导语明确关联模型与工作流。
- [ ] 1440×900 桌面首屏可见 H1 和生成器顶部控件；手机端输入/限制列表与表格无页面级横向溢出。
- [ ] 规格块按明确的模型范围取数；用现有图片模型配置验证按次计费展示，不必新增公开页面；相关资源链接实际可点击，列数扩展不影响旧页面。
- [ ] 桌面和手机无布局溢出，表格可读，按钮与内链可用。
- [ ] 检查相关类型、构建和 diff，无无关代码改动。

第二阶段再完善：关键词分组与段落润色、真实案例和参数记录、模型筛选、Title/Description，以及上线后的搜索和转化观察。FAQ 数字在第一阶段已与配置对齐，第二阶段只改表述。

后续复用原则：模型页沿用第 2 节的结构约定，首页和功能页复用模块并分别组织结构；替换真实产品数据，不直接复用 Seedance 的参数、价格和能力声明。
