| 类型 | 文件 |

## 2. Pricing SKU 配置

`pricing.json` 是套餐配置源。英文和中文 pricing JSON 的结构字段必须一致，只翻译文案。

当前已落地 SKU：

| product_id | 产品线 | 档位 | interval | amount | currency | credits | valid_days | 备注 |
|---|---|---|---|---:|---|---:|---:|---|
| `credits_starter` | 一次性积分包 | Starter | `one-time` | 1490 | USD | 400 | 365 | 可上线 |
| `credits_growth` | 一次性积分包 | Growth | `one-time` | 3990 | USD | 1200 | 365 | 可上线 |
| `credits_scale` | 一次性积分包 | Scale | `one-time` | 9990 | USD | 3600 | 365 | 可上线 |
| `monthly_basic` | 月付订阅 | Basic | `month` | 990 | USD | 360 | 30 | 可上线 |
| `monthly_pro` | 月付订阅 | Pro | `month` | 2990 | USD | 1200 | 30 | 主推 |
| `monthly_ultimate` | 月付订阅 | Ultimate | `month` | 7990 | USD | 3600 | 30 | 可上线 |
| `annual_basic` | 年付订阅 | Basic | `year` | 9900 | USD | 4320 | 365 | 年付开放，一次性发全年积分 |
| `annual_pro` | 年付订阅 | Pro | `year` | 29900 | USD | 14400 | 365 | 年付开放，一次性发全年积分，主推 |
| `annual_ultimate` | 年付订阅 | Ultimate | `year` | 79900 | USD | 43200 | 365 | 年付开放，一次性发全年积分 |

配置规则：

- `amount` 使用美元最小单位，`$14.90` 写 `1490`。
- `product_id`、`interval`、`group`、`amount`、`currency`、`credits`、`valid_days` 在 en / zh 中必须完全一致。
- 只翻译 `title`、`description`、`features`、`tip`、`button.title`、FAQ。
- 不要翻译或改写 `product_id`。
- `payment_product_id` 不确定时不要填假值；要么填真实支付 Price ID，要么确认当前动态价格模式可用。

当前分组：

```json
[
  { "name": "one-time", "title": "Pay as you go" },
  { "name": "monthly", "title": "Monthly", "is_featured": true },
  { "name": "yearly", "title": "Annual", "label": "Pay 10 months, get 12" }
]
```

每个 group 下当前放 3 个 item。Pricing 组件会按当前 group 过滤并展示该组卡片，并已使用静态 `md:grid-cols-*` class 做 3 卡片布局兜底。后续不要为了 SKU 数量再重构 pricing 组件。

`group` 和 `interval` 的职责不要混用：

- `group` 控制前台 Pricing Tab 分组，当前组件按 `item.group === group.name` 过滤。
- `interval` 控制支付周期，当前可用值为 `one-time`、`month`、`year`。
- 当前映射关系是：一次性积分包 `group=one-time / interval=one-time`，月付订阅 `group=monthly / interval=month`，年付订阅 `group=yearly / interval=year`。

## 3. 生成扣费配置

扣费配置文件：

```text
src/config/ai/credit-costs.ts
```

当前默认 scene 价格必须保留为 fallback：

| mediaType | scene | fallback credits |
|---|---|---:|
| image | text-to-image | 4 |
| image | image-to-image | 6 |
| video | text-to-video | 6 |
| video | image-to-video | 8 |
| video | video-to-video | 10 |
| music | text-to-music | 10 |

当前 `credit-costs.ts` 仍只按 `mediaType + scene` 返回 fallback 扣费。`family` override 是下一步落地目标；在代码没有实现 override 查找前，不要把下面的示例当成已生效配置。

后续新定价优先用 `family` override，不要直接按具体 provider `model` 定价。

原因：

- 当前图片 / 视频前端传的是 `family + candidates`。
- 后端在 provider fallback 选出 `finalModel` 之前就要做余额校验。
- 如果同一个 `family` 下不同 provider candidate 价格一致，按 `family` 定价最轻、最稳。

推荐查找顺序：

```text
family override
scene fallback
```

只有在单独处理了 `candidates` 最高价预校验和 `finalModel` 实际扣费记录后，才考虑 `model override`。

示例结构，具体 credits 以后续最终扣费表为准：

```ts
const FAMILY_CREDIT_COST_OVERRIDES: Record<
  string,
  Partial<Record<string, number>>
> = {
  'nano-banana-pro': {
    'text-to-image': 20,
    'image-to-image': 20,
  },
  'veo-3': {
    'text-to-video': 45,
  },
};
```

配置前先按实际代码整理当前可用 `family -> credits` 映射表。以生成器里的真实 `family` 字符串为准，不要凭模型展示名猜 key。

当前生成器里已启用的 `family` key 如下。此表只用于整理最终扣费配置，不代表当前已生效扣费：

| family | mediaType | scenes | credits 状态 |
|---|---|---|---|
| `nano-banana-pro` | image | `text-to-image` / `image-to-image` | 待最终确认 |
| `seedream-4` | image | `text-to-image` / `image-to-image` | 待最终确认 |
| `z-image-turbo` | image | `text-to-image` | 待最终确认 |
| `flux-2-flex` | image | `text-to-image` | 待最终确认 |
| `gemini-3-pro-image-preview` | image | `text-to-image` / `image-to-image` | 待最终确认 |
| `sora-2-pro` | video | `text-to-video` / `image-to-video` | 待最终确认 |
| `veo-3` | video | `text-to-video` | 待最终确认 |
| `wan-pro` | video | `image-to-video` | 待最终确认 |
| `kling-video-o1` | video | `video-to-video` | 待最终确认 |

实现约束：

- 文件必须保持纯 TypeScript。
- 不 import 数据库。
- 不 import env。
- 不 import `server-only`。
- 不从 `src/config/index.ts` 重新导出。
- 判断价格是否存在时用 `typeof cost !== 'number'`，不要用 `if (!cost)`。
- 前端余额不足只是体验提示，最终以后端校验为准。

## 4. 注意事项

### 4.1 支付配置

`product_id` 是 checkout、订单、支付 provider 映射的核心字段。en / zh 必须完全一致。

`payment_product_id` 处理规则：

- 如果当前支付通道支持动态价格创建，可以不填 `payment_product_id`。
- 当前 Stripe / PayPal 代码路径支持按服务端 pricing item 动态创建价格。
- 当前 Creem 代码路径要求 `productId`，生产使用 Creem 时必须通过 pricing item、`currencies[]` 或后台 `creem_product_ids` 映射提供真实产品 ID。
- 如果后续其它支付通道依赖固定 Price ID，必须填真实 ID。
- 不要填假的 `payment_product_id`。
- 多币种时，币种级 `currencies[].payment_product_id` 优先于 item 级 `payment_product_id`。

checkout 仍由服务端按 `product_id` 查 pricing item，再取 `amount`、`currency`、`credits`、`valid_days`。不要让前端传金额或积分。

### 4.2 前台展示和 Credits 说明

不要在本文档维护完整的能力档位表，具体扣费以 `src/config/ai/credit-costs.ts` 为准。前台只做产品化说明，避免把供应商、成本、route 或完整扣费矩阵暴露成页面文案。

可以展示：

- 套餐名称、售价、Credits 数量。
- Credits 有效期 / 发放方式。
- 图片和视频共用 Credits。
- 高质量图片和视频会消耗更多 Credits。
- 免费额度只适合 Basic Image 体验。
- 高阶视频 / 自定义视频需要更多 Credits 或联系团队。

必要时只保留少量稳定用量锚点：

- `Basic Image` 约 `5 Credits`，用于免费额度体验。
- `Pro Image` 约 `20 Credits`，用于主销图片估算。
- `Fast Video` 约 `45 Credits`，用于主销视频估算。

禁止展示：

- 供应商名称。
- API 成本、供应商报价、成本快照。
- 毛利率、利润、安全线。
- route、fallback、高波动 route。
- 内部积分价值。
- 图片倍数、视频倍数、fallback 倍数。
- 完整模型扣费表或完整能力档位矩阵。

### 4.3 免费额度约束

建议环境配置：

```text
INITIAL_CREDITS_ENABLED=true
INITIAL_CREDITS_AMOUNT=5
INITIAL_CREDITS_VALID_DAYS=7
INITIAL_CREDITS_DESCRIPTION=initial free credits
```

配置价格时必须满足：

- `5 credits` 只覆盖 Basic Image 量级。
- 不要给视频设置低于 `15 credits` 的扣费。
- 不要把 Pro Image、4K Image、Advanced Video 映射到 `5 credits`。
- 不做 `initial_free` ledger。
- 不做 paid credits / free credits 分账。
- 不改 `consumeCredits` 的 FIFO 语义。

## 5. AI 修改步骤

让 AI 改价格和积分时，按这个顺序执行：

1. 读取 en / zh pricing JSON，确认当前仍是 9 个 SKU 且字段结构一致。
2. 读取 `src/config/ai/credit-costs.ts`，确认当前是仅有 scene fallback，还是已经实现 `family` override。
3. 修改 en / zh pricing JSON，保持非翻译字段完全一致。
4. 修改 `credit-costs.ts` 时，优先采用 `family override -> scene fallback`；如果 override 尚未落地，先实现该查找顺序，再填真实 family key。
5. 如涉及前台文案，只调整产品化说明，不新增完整扣费档位表。
6. 扫描确认前端没有传 `costCredits`。
7. 如果改了 TypeScript，运行 `pnpm lint` 和 `npx tsc --noEmit`。

不要在这个任务里顺手做：

- 新增 `plans.ts`。
- 新增 `credit-policy.ts`。
- 改支付 webhook / checkout。
- 改积分账本模型。
- 做年付按月发放计划任务。
- 做 provider/model 全量白名单系统。
- 做根据 fallback 成功结果动态二次计费。

## 6. 验收清单

| 检查项 | 通过标准 |
|---|---|
| Pricing 配置源 | 套餐仍以 `pricing.json` 为配置源 |
| en / zh 一致性 | `product_id`、`interval`、`group`、`amount`、`currency`、`credits`、`valid_days` 完全一致 |
| 金额 | `amount` 使用最小货币单位 |
| SKU 展示 | 9 个 SKU 按 `item.group` 匹配 `groups[].name`，分为 one-time / monthly / yearly 展示 |
| Pricing 布局 | 每个 group 下 3 张卡片正常展示，组件继续使用静态 `md:grid-cols-*` class |
| 年付 | 年付开放，全年积分一次性发放，`valid_days = 365` |
| Checkout | 服务端仍按 pricing item 取金额和积分 |
| 支付通道 | Stripe / PayPal 动态价格可用；如使用 Creem，已配置真实产品 ID 映射 |
| 扣费配置 | 后端和图片 / 视频前端都使用 `@/config/ai/credit-costs`，scene fallback 保留 |
| family key | 如果启用 family override，key 必须来自生成器真实 `family` 字符串 |
| 扣费权威 | 前端不传 `costCredits`，后端计算并写入 `ai_task.costCredits` |
| 免费额度 | `5 credits` 只能覆盖 Basic Image 量级 |
| 前台文案 | 不展示供应商、成本、毛利、route、fallback，不维护完整扣费矩阵 |
| 改动范围 | 没有新增 plans、creditPolicy、ledger、cron 等架构改造 |
