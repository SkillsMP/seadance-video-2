> 生成 pricing 页面时，优先使用第 4 节「前台套餐表」作为套餐卡片数据，使用第 3.0 节「积分消耗规则总览」作为 Credits 使用说明数据。第 5 节供应商成本与毛利压力只作为内部参考，不应直接展示到前台页面。

适用范围：当前项目以 `Nano Banana Pro / Nano Banana 2` 图片能力为主，同时把 `Sora 2 / Veo 3.1 / Seedance 2.0` 纳入统一积分体系；前台保留 `一次性积分包 + 月付 + 年付` 这 3 条产品线，每条各 3 档，共 9 个付费 SKU。

一句话结论：

> 最终方案直接采用“统一积分 + 3 条产品线 × 3 档 + 模型分档扣费”。图片和视频共用一套积分，但视频只卖固定档位，不卖无限量，也不把高成本 route 混进低价套餐。

## 1. 最终方案

- 图片和视频共用同一个积分余额
- 免费额度仍然只给低成本图片，不默认开放免费视频
- 前台只卖标准化视频档位，不暴露供应商 route；时长、音频、分辨率只开放少量可控选项，并映射到更高积分档。

这套方案适合当前项目，原因很简单：

- 图片依然负责拉新和主转化
- 视频负责提升客单价和消耗速度
- 只要高成本视频不被低价套餐套利，这套模型是能跑通的

## 2. 统一积分锚点

### 2.1 内部积分价值

内部统一按：

```text
1 积分 = $0.035
```

说明：

- 这是内部核算锚点，不是前台套餐的实际出售单价
- 一次性积分包的有效单价可以更高
- 月付和年付通过“送积分”做出更低的有效单价

### 2.2 统一计算公式

统一按这两条逻辑推积分：

```text
图片建议积分 = ceil((保守参考成本 × 4) ÷ 0.035)
视频建议积分 = ceil((稳定交付成本 × 5) ÷ 0.035)
```

其中：

- `保守参考成本`：优先取公开价格里较高但稳定的成本，不拿最便宜 route 当基准
- `4x`：用于稳定图片，保持图片转化和用量感知
- `5x`：用于稳定视频，给 Bonus Credits、失败重试和 route 波动留更多空间
- `6x`：用于高波动 route / fallback，当前不作为公开低档价格
- `最终积分`：向上取整后，尽量靠拢 `5 / 10 / 15 / 20 / 30 / 45 / 60 / 90 / 120 / 150 / 180`

### 2.3 核心定价原则

- 对外按贵的稳定成本卖
- 图片卖标准化，视频卖固定档位
- 不让高成本功能在低价套餐里被大量白嫖

### 3.3 视频附加规则

为了避免视频成本失控，前台再加这几条硬规则：

- `图生视频`：在对应基础档位上至少 `+15 积分`，或直接进入下一档
- `视频转视频`：在对应基础档位上至少 `+20 积分`，或直接进入 `90 积分` 以上
- `1080p / 原生音频`：直接归入 `90 / 120 积分` 或更高档，不和低档混卖
- `长时长`：一期只公开卖 `5-6 秒` 标准模板，更长时长先不公开
- `极高成本 route`：不在前台开放，只做白名单或人工报价

这一步很重要。视频最怕的不是模型贵，而是：

- 同模型不同 route 差价极大
- 多 2-3 秒时长就会明显抬高成本
- 一旦把 `1080p / 音频 / 长时长` 混进低价套餐，毛利会瞬间塌

## 5. 供应商成本口径与套餐毛利压力

这一节用于解决一个现实问题：如果最终只接一个供应商，当前套餐价格和积分是否还能扛住。

说明：

- 本节基于 `2.四平台对比成本价格.md` 中 2026-04-15 已整理的公开报价，不代表实时供应商报价。
- 这里不是新的执行方案，而是成本敏感性分析；最终执行仍以前面的套餐矩阵为准。
- 表里的“建议积分”按图片 `4x`、视频 `5x` 计算后，再向上靠拢到标准档位；高波动 fallback 可按 `6x` 或人工报价处理。
- `0.035` 是本站前台积分价值锚点，不是任何一家供应商的 credit 单价。
- `Sora 2 Lite` 没有纳入主表，因为当前四平台对比文档没有给出 KIE / EvoLink / WaveSpeed / Replicate 的可比公开价，需要单独核价。

### 5.1 五套口径定义

| 口径 | 含义 | 用途 | 风险 |
| --- | --- | --- | --- |
| KIE 口径 | 假设后台优先走 KIE 的低价稳定 route | 判断最低成本交付下的利润空间 | 供应商不可用或 route 改价时会失真 |
| EvoLink 口径 | 假设后台优先走 EvoLink 当前公开 route | 判断统一路由平台下的中间成本 | EvoLink 页面口径有新旧价格差异 |
| WaveSpeed 口径 | 假设后台优先走 WaveSpeed 明确美元报价 route | 判断美元直显平台下的交付成本 | 同模型不同 route 差价很大 |
| Replicate 口径 | 假设后台走 Replicate 的公开模型 API | 判断开发者生态平台下的补位成本 | 视频整体偏贵，且多按运行时间计费 |
| 保守混合口径 | 在 KIE / EvoLink / WaveSpeed / Replicate 里取偏高但稳定的公开成本 | 做最终定价安全线 | 会牺牲部分转化和用量感知 |

建议使用方式：

- 对外定价参考 `保守混合口径`
- 对内交付优先走 `KIE` 或明确低价 route
- `Replicate` 更适合作为开发者生态、特殊模型或兜底补位，不适合默认承接低积分视频档
- 如果某个 route 只能走 `WaveSpeed` / `Replicate` 高价档，不应继续沿用低积分档

### 5.3 只接一个供应商时的套餐毛利表

这一节把当前 9 个套餐分别按 `KIE`、`EvoLink`、`WaveSpeed`、`Replicate` 的代表性单位积分成本重算一遍。

计算口径：

- 供应商单位积分成本 = 该供应商公开核心能力的 `API 成本 ÷ 当前积分` 的均值
- 这里只用于套餐层面的粗略压力测试，不等于真实账单；真实毛利仍取决于用户实际消耗了哪些模型
- 极高成本 route、带音频标准视频、长时长视频不放进均值，应该走 `90 / 120 / 150` 或人工报价
- 如果用户大量集中消耗视频，应该优先看每个供应商下面的单次模型毛利压力，不要只看套餐平均表

### 5.5 对当前方案的影响

- 不建议改 `1 积分 = $0.035`
- 不建议改图片档位
- 不建议重做 9 个套餐价格

当前建议改：

- 图片继续按 `4x`，视频统一改为按 `5x` 靠档
- 把视频后台扣费从 `10 / 20 / 35 / 60` 调整为 `15 / 30 / 45 / 60 / 90 / 120 / 150 / 180`
- `240 / 360+` 这类高成本 route 不进公开价格页，只做白名单或人工报价
- `Veo 3.1 Fast` 只有 KIE 固定档可卖 `45`；非 KIE route 应动态升档
- `Seedance 2.0` 必须按 `resolution + seconds + input type` 拆扣费
- `WaveSpeed` / `Replicate` 高价视频 route 不能作为低积分档 fallback
- `Sora 2 Lite` 需要单独核供应商价；如果真实成本高于 `$0.105`，`15 积分` 就不再满足 `5x` 安全线

一句话结论：

> 当前的 `0.035` 作为平台锚点可以继续保留；图片按 `4x` 保持转化，视频按 `5x` 提高安全线，真正需要加强的是“按供应商 route 动态映射积分档”，不要让 WaveSpeed、Replicate 或其他高价 fallback 吃掉低积分档的毛利。

## 6. 最终套餐边界

这部分必须写死，不然视频模型会把整套定价吃穿。

### 必须执行

- 免费用户默认只开放低成本图片
- 所有高成本视频模型都要求登录后付费使用
- `90 积分` 及以上的视频档只对付费用户开放
- 长时长、1080p、音频默认不在公开价格页展示
- 前台主展示 `15 / 30 / 45 / 90` 这 4 个视频价格锚点，后台保留 `60 / 120 / 150 / 180`

### 不建议做

- 不要做“视频不限量”
- 不要把所有视频 route 混进同一个月付里却不给差异化扣费
- 不要免费送 `Veo Fast / Seedance Standard / Wan` 这类高成本视频
- 不要在前台暴露太多视频细分规格，用户看不懂，你也难控毛利

| 第 4 节「前台套餐表」 | 产品线、档位、售价、积分、有效期 / 发放、代表性用量、定位 | 生成套餐卡片、套餐 tab、购买按钮旁说明 |
| 第 3.0 节「积分消耗规则总览」 | 类型、执行档位、代表模型 / 能力 | 生成 Credits 使用说明、模型消耗示例 |
| 第 6 节「最终套餐边界」 | 免费额度边界、高阶视频边界、公开展示边界 | 生成 FAQ 和限制说明 |

第 4 节中的 `单积分售价` 只建议用于内部排序和转化判断，默认不在前台展示；`保守毛利率` 不允许出现在前台。

### 7.2 禁止展示的信息

前台 pricing 页面、FAQ、tooltip、套餐卡片和模型说明里，禁止展示或暗示下面这些内部信息：

- 供应商名称：`KIE`、`Replicate`、`EvoLink`、`WaveSpeed`
- API 成本、供应商报价、credit 成本、成本快照
- 毛利率、利润、安全线、套餐毛利压力
- `route`、`fallback`、`高波动 route`、`高成本保护档`
- 内部积分价值 `$0.035`
- 图片 `4x`、视频 `5x`、fallback `6x`
- 第 5 节供应商成本口径、毛利表、单次模型毛利压力表

如果 AI 需要生成页面，只喂给第 4 节、第 3.0 节和本节，不要把第 5 节原样作为页面上下文。

### 7.3 前台表达转换

| 内部表达 | 前台表达 |
| --- | --- |
| 只适合 KIE 这类 `$0.15` 稳定成本 route | Standard 720p short video |
| 非 KIE route 升到 45 积分 | Higher-quality options may use more credits |
| 高价 route 必须动态升档 | Advanced settings require higher credit tiers |
| 高成本保护档 | Advanced video tier |
| 极高成本 route | Custom or advanced generation |
| 白名单或人工报价 | Contact us for custom generation |
| fallback | 不在前台展示 |

前台表达重点：

- Credits work across image and video generation.
- Higher-quality image and video models use more credits.
- Monthly and yearly plans are better value than one-time credit packs.
- New users get limited trial credits for low-cost image generation only.

## 8. 后台路由建议

### 8.1 图片

- `Nano Banana 基础版`：KIE.ai 优先，WaveSpeed / EvoLink 备选，Replicate 最后兜底
- `Nano Banana Pro`：KIE.ai 优先，EvoLink 次之，WaveSpeed 只在 route 明确时使用，Replicate 保底
- `Nano Banana 2`：WaveSpeed Fast 或 KIE 优先，EvoLink / Replicate 补位
- `Seedream 5.0 Lite`：KIE.ai 优先，EvoLink 次之

### 8.2 视频

- `Sora 2 Lite / Pro`：优先走成本稳定的固定档渠道，避免临时切到高价 route
- `Veo 3.1`：优先 KIE 这类固定档或成本可控渠道，WaveSpeed / EvoLink 只在 route 明确时开放
- `Seedance 2.0`：优先低价且稳定的 `Fast 480p / 720p` 档，不开放高波动 route
- `Wan / 其他高阶 I2V`：只在定价足够高时开启，不放进低价默认入口

后台原则还是一句话：

> 对外卖固定档位，对内按最低稳定成本交付。

## 9. 落地时必须同步改的地方

如果按这版执行，文档之外还必须同步这几个点：

### 9.1 价格页配置

需要同步 `src/config/locale/messages/en/pages/pricing.json` 和 `src/config/locale/messages/zh/pages/pricing.json`：

- 一次性积分包：`Starter $14.90 / 400`、`Growth $39.90 / 1200`、`Scale $99.90 / 3600`
- 月付订阅：`Basic $9.90 / 360`、`Pro $29.90 / 1200`、`Ultimate $79.90 / 3600`
- 年付订阅：`Basic $99 / 4320`、`Pro $299 / 14400`、`Ultimate $799 / 43200`
- 前端展示建议按 `Basic / Pro / Ultimate` 三列切换月付 / 年付，一次性积分包单独做补充区块
- Pricing 页面生成时必须按第 7 节过滤内部字段，不展示供应商、成本、毛利率、route 或 fallback 信息

### 9.2 后端扣费规则

需要改 `src/app/api/ai/generate/route.ts`。

当前代码还是：

- 图片按场景固定 `4 / 6`
- 视频按场景固定 `6 / 8 / 10`

这不适合最终方案。最终应该改成：

```text
按 provider + model + scene + 档位 配置表扣费
```

也就是至少要区分：

- 图片模型家族
- 视频模型家族
- 文生视频 / 图生视频 / 视频转视频
- 720p / 1080p / 是否音频

### 9.3 前端价格提示

需要改 `src/shared/blocks/generator/video.tsx`。

当前前端显示的积分仍然是：

- 文生视频：6
- 图生视频：8
- 视频转视频：10

最终要改成按模型联动显示，比如：

- `Sora 2 Lite` 显示 `15 积分`
- `Veo 3.1 Lite` 显示 `30 积分`
- `Veo 3.1 Fast` 显示 `45 / 60 积分`
- `高阶视频档` 显示 `90 积分起`

### 9.4 新用户赠送

当前 `.env.production` 里免费积分是关闭的，最终如果要开启，建议按：

```text
INITIAL_CREDITS_ENABLED=true
INITIAL_CREDITS_AMOUNT=5
INITIAL_CREDITS_VALID_DAYS=7
```

但前提是后台也要保证免费视频默认不可用。

## 10. 最终建议

如果现在就定版，我建议直接按下面这版执行：

### 统一积分

- `1 积分 = $0.035`
- 图片和视频共用积分
- 视频不单独做第二套订阅体系

### 模型价格锚点

- 图片：`5 / 15 / 20 / 30`
- 视频：`15 / 30 / 45 / 60 / 90 / 120 / 150 / 180`

### 前台 SKU

- 免费赠送：`5 积分 / 7 天`，仅限低成本图片
- 一次性积分包：`Starter $14.90 / 400`、`Growth $39.90 / 1200`、`Scale $99.90 / 3600`
- 月付订阅：`Basic $9.90 / 360`、`Pro $29.90 / 1200`、`Ultimate $79.90 / 3600`
- 年付订阅：`Basic $99 / 4320`、`Pro $299 / 14400`、`Ultimate $799 / 43200`

### 执行边界

- 默认不送视频免费额度
- 默认不公开长时长、1080p、音频视频
- 高成本视频只走高积分档
- 前台只卖固定视频档位，不卖所有 route

这就是当前项目最稳、最容易上线、也最容易控利润的最终方案。
