# 本项目定价方案（最终执行版）

> 生成 pricing 页面时，优先使用第 4 节「前台套餐表」作为套餐卡片数据，使用第 3 节「模型积分消耗表」作为 Credits 使用说明数据。附录 A 成本压力分析只作为内部参考，不应直接展示到前台页面。

适用范围：当前项目以 `Nano Banana`、`GPT Image 2` 图片系列和 `Seedance 2.0` 视频系列为主；`Veo / Sora / Seedream / Wan` 等未上线候选模型只进入归档备查，不进入当前主模型扣费表。前台保留 `一次性积分包 + 月付 + 年付` 这 3 条产品线，每条各 3 档，共 9 个付费 SKU。

一句话结论：

> 最终方案直接采用“统一积分 + 3 条产品线 × 3 档 + 模型分档扣费”。图片和视频共用一套积分；视频不卖无限量，按 `模型 / 分辨率 / 输入口径 / 每秒积分` 线性扣费，并且不把高成本 route 混进低价套餐。

>  倍数（图片 4x / 视频 5x）＝利润结构

> credit 值（0.035）＝产品体验 + 定价表达

| 倍数 | 示例成本 | 售价 | 毛利率 |
|------|----------|------|--------|
| 10x  | $0.14    | $1.40 | 90%   |
| 5x   | $0.14    | $0.70 | 80%   |
| 2.5x | $0.14    | $0.35 | 60%   |

- 稳定图片：4x
- 稳定视频：5x
- 高波动 route / fallback：6x（当前不进公开低档价格）
- Bonus Credits：优先用于一次性充值包；订阅不叠加或只小额叠加（目前阶段先不用 Bonus Credits）

## 1. 最终方案

- 图片和视频共用同一个积分余额
- 免费额度仍然只给低成本图片，不默认开放免费视频
- 前台只卖标准化视频能力，不暴露供应商 route；分辨率、时长、音频只开放可控选项。时长按秒线性扣费，分辨率和输入类型决定每秒积分。

这套方案适合当前项目，原因很简单：

- 图片依然负责拉新和主转化
- 视频负责提升客单价和消耗速度
- 只要高成本视频不被低价套餐套利，这套模型是能跑通的

## 2. 统一积分锚点

### 2.1 内部积分价值

内部统一按：

```text
1 积分 = $0.035
```

说明：

- 这是内部核算锚点，不是前台套餐的实际出售单价
- 一次性积分包的有效单价可以更高
- 月付和年付通过“送积分”做出更低的有效单价
- $0.035 本质上就是为了让主销图片模型落在 10、20、30 积分 这种档位

### 2.2 统一计算公式

统一按这两条逻辑推积分：

```text
图片建议积分 = ceil((保守参考成本 × 4) ÷ 0.035)
视频建议积分 = ceil((稳定交付成本 × 5) ÷ 0.035)
视频实际扣费 = durationSeconds × creditsPerSecond
```

其中：

- `保守参考成本`：优先取公开价格里较高但稳定的成本，不拿最便宜 route 当基准
- `4x`：用于稳定图片，保持图片转化和用量感知
- `5x`：用于稳定视频，给 Bonus Credits、失败重试和 route 波动留更多空间
- `6x`：用于高波动 route / fallback，当前不作为公开低档价格
- `creditsPerSecond`：按模型、分辨率和输入类型确定；时长本身只是 `1s` 倍数，不单独做复杂阶梯。
- `duration capability`：按模型声明，Seedance 当前 `text-to-video` / `image-to-video` 为 `4-15s`，`video-to-video` 为 `5s / 10s`；未来其他视频模型必须单独声明自己的范围或枚举。
- `最终积分`：图片按单次生成靠档；视频按每秒积分线性累加，前台可展示 `4s / 5s / 10s / 15s` 等常用换算。

### 2.3 核心定价原则

- 对外按贵的稳定成本卖
- 图片卖标准化，视频卖受控规格 + 按秒扣费
- 不让高成本功能在低价套餐里被大量白嫖

### 4.1 前台套餐卡片表达策略

当前第 4 节里的「代表性用量」不是内部备注，而是统一积分套餐的默认前台表达策略。公开页优先采用：

```text
积分数值
+ 一句代表性用量换算
+ 一句共享积分 / 浮动消耗提示
```

这样做的原因：

- 用户看到 `400 Credits` 时感知仍然偏弱，补一句代表性用量更容易形成购买判断。
- 套餐卡片只讲 `Pro images`、`Fast videos` 这类产品化名称，比直接展开模型扣费表更容易转化。
- 用 `约`、`~`、`up to` 这类缓冲词表达代表性用量，可以保留不同模型、分辨率和 route 的浮动空间。

推荐卡片骨架：

```text
400 Credits
Good for ~20 Pro images or ~6 Fast 5s videos.

Access to all AI models
Shared credits for image and video
```

执行口径：

- 套餐卡片主句优先使用「积分数值 + 具象化换算」，不要只写抽象 Credits。
- FAQ / tooltip 再补充 `Credits are shared across all models. Higher-quality generations consume more credits.` 这类浮动消耗说明。
- 不在套餐卡片里承诺 `1 credit = 1 generation`。
- 企业档或大额积分包后续如需增强，可追加 calculator / slider；第一版静态套餐卡片不依赖该交互。

## 5. 执行边界

这部分必须写死，不然视频模型会把整套定价吃穿。

### 5.1 必须执行

- 免费用户默认只开放低成本图片
- `GPT Image 2` 即使走 KIE 低成本 route，也不进入免费额度；免费额度只覆盖 `nano-banana` 这类 Basic Image
- 所有高成本视频模型都要求登录后付费使用
- 高消耗视频请求只对付费用户开放，具体门槛和扣费按模型、场景、分辨率、输入口径和 `creditsPerSecond × durationSeconds` 计算
- 前台主展示 `12 积分/秒`、`24 积分/秒` 和常用时长换算，后台保留 with video input、更高分辨率、音频开关和高价 route 的每秒积分规则
- 新增模型先修改第 3 节「模型积分消耗表」的业务定价口径，再由 AI 同步 `src/config/ai/models.ts`，默认不改第 4 节「前台套餐表」

### 5.2 视频附加规则

为了避免视频成本失控，前台再加这几条硬规则：

- `图生视频`：如果供应商按 no video input 计费，可与 `text-to-video` 共用同一 `creditsPerSecond`；如果供应商单独抬价，则按对应 route 提升每秒积分。
- `视频转视频`：必须按 with video input 的独立 `creditsPerSecond` 计费，不得沿用 no video input 低价。
- `Seedance 2.0 Fast 480p with video input` 当前已开放，必须按 with video input 的独立 `creditsPerSecond` 和 `5s / 10s` 枚举扣费。
- `1080p / 原生音频`：当前可选状态以 `models.ts` 为准；成本风险不在是否开放，而在是否按 1080p、高价 route 和音频开关准确计费。
- `长时长`：不是禁止项，但必须出现在对应模型的服务端允许范围或枚举中，并按 `durationSeconds × creditsPerSecond` 扣费。Seedance 当前 `text-to-video` / `image-to-video` 为 `4-15s`，`video-to-video` 为 `5s / 10s`，其他模型不得默认复用。
- `极高成本 route`：不在前台开放，只做白名单或人工报价

这一步很重要。视频最怕的不是模型贵，而是：

- 同模型不同 route 差价极大
- 多 2-3 秒时长会线性抬高成本，因此必须让用户在前台看到清晰的 credits 变化
- 一旦把 `1080p / 音频 / 长时长` 作为低价固定生成次数承诺，毛利会瞬间塌

### 5.3 不建议做

- 不要做“视频不限量”
- 不要把所有视频 route 混进同一个月付里却不给差异化扣费
- 不要免费送 `Seedance 720p / Seedance Standard / 1080p / 音频视频` 这类高成本视频
- 不要在前台暴露太多视频细分规格，用户看不懂，你也难控毛利

## 7. 后台路由建议

### 7.1 图片

- `Nano Banana 基础版`：KIE.ai 优先，WaveSpeed / EvoLink 备选，Replicate 最后兜底
- `Nano Banana Pro`：KIE.ai 优先，EvoLink 次之，WaveSpeed 只在 route 明确时使用，Replicate 保底
- `Nano Banana 2`：WaveSpeed Fast 或 KIE 优先，EvoLink / Replicate 补位

### 7.2 视频

- `Seedance 2.0`：当前按 `models.ts` 开放 Fast / Standard 的多个分辨率，扣费通过 `pricing.byResolution` 和 `duration` 计算。
- `video-to-video`：后端必须传 `reference_video_urls`，并按 with video input 的独立 `creditsPerSecond` 和 `5s / 10s` 枚举扣费，不得沿用 no video input 价格。
- `generate_audio`：当前代码已开放开关，默认 `false`；代码未对音频设置单独加价维度，视频扣费仍按模型、场景、分辨率、输入口径和时长计算。KIE Seedance 2 / Seedance 2 Fast 文档支持 `generate_audio`、`reference_audio_urls`，但当前页面未给出清晰音频加价表；KIE Seedance 1.5 Pro 文档曾提示开启 `generate_audio` 会增加生成成本。上线后必须用 KIE 实际账单核验音频开关是否产生额外成本，如确认额外加价，应新增音频维度定价，或关闭前台 `generate_audio` 开关。
- `Veo / Sora / Wan` 等视频候选模型只看第 6.5 节归档，不进入当前默认路由。

后台原则还是一句话：

> 对外卖清晰的规格和时长选项，对内按最低稳定成本交付。

## 附录 A. 成本压力分析（内部参考）

这一节用于解决一个现实问题：如果最终只接一个供应商，当前套餐价格和积分是否还能扛住。

说明：

- 本节基于 `2.四平台对比成本价格.md` 中 2026-04-15 已整理的公开报价，不代表实时供应商报价。
- 这里不是新的执行方案，而是成本敏感性分析；最终执行仍以前台套餐表和模型积分消耗表为准。
- 表里的“建议积分”按图片 `4x`、视频 `5x` 计算后，再向上靠拢到标准档位；高波动 fallback 可按 `6x` 或人工报价处理。
- `0.035` 是本站前台积分价值锚点，不是任何一家供应商的 credit 单价。
- `Veo / Sora / Seedream / Wan` 等未上线候选模型只在本附录和第 6.5 节归档备查，不进入当前主模型扣费表。

### A.1 五套口径定义

| 口径 | 含义 | 用途 | 风险 |
| --- | --- | --- | --- |
| KIE 口径 | 假设后台优先走 KIE 的低价稳定 route | 判断最低成本交付下的利润空间 | 供应商不可用或 route 改价时会失真 |
| EvoLink 口径 | 假设后台优先走 EvoLink 当前公开 route | 判断统一路由平台下的中间成本 | EvoLink 页面口径有新旧价格差异 |
| WaveSpeed 口径 | 假设后台优先走 WaveSpeed 明确美元报价 route | 判断美元直显平台下的交付成本 | 同模型不同 route 差价很大 |
| Replicate 口径 | 假设后台走 Replicate 的公开模型 API | 判断开发者生态平台下的补位成本 | 视频整体偏贵，且多按运行时间计费 |
| 保守混合口径 | 在 KIE / EvoLink / WaveSpeed / Replicate 里取偏高但稳定的公开成本 | 做最终定价安全线 | 会牺牲部分转化和用量感知 |

建议使用方式：

- 对外定价参考 `保守混合口径`
- 对内交付优先走 `KIE` 或明确低价 route
- `Replicate` 更适合作为开发者生态、特殊模型或兜底补位，不适合默认承接低积分视频档
- 如果某个 route 只能走 `WaveSpeed` / `Replicate` 高价档，不应继续沿用低积分档

这里能解释一个很容易误判的点：

- 套餐表里的毛利率是按“平均积分成本”算的
- 单模型毛利率是按“某个 route 的真实 API 成本”算的
- 如果用户集中消耗高成本视频，实际毛利会明显低于套餐平均毛利
- `Replicate` 的图片成本不危险，但视频一旦按运行时间计费，很容易击穿低积分档

### A.5 对当前方案的影响

当前不建议改：

- 不建议改 `1 积分 = $0.035`
- 不建议改图片档位
- 不建议重做 9 个套餐价格

当前建议改：

- 图片继续按 `4x`，视频统一改为按 `5x` 靠档
- `GPT Image 2` 默认从 KIE 接入，但业务扣费按跨供应商安全线定为标准档 `10 积分`、4K `15 积分`，不要把 KIE 1K 低成本 route 直接做成公开 5 积分能力
- 把视频后台扣费从固定单次档位调整为 `creditsPerSecond × durationSeconds`，固定档位只作为前台常用秒数示例展示
- `240 / 360+` 这类高成本 route 不进公开价格页，只做白名单或人工报价
- 当前主视频以 `models.ts` 已开放的 `Seedance 2 Fast / Standard` 规格为准，其他视频候选先归档
- `Seedance 2.0` 必须按 `resolution + seconds + input type` 拆扣费
- `WaveSpeed` / `Replicate` 高价视频 route 不能作为低积分档 fallback
- `Veo / Sora / Seedream / Wan` 等候选模型进入主表前，必须先重核成本、补齐 `models.ts` 注册和扣费档位

一句话结论：

> 当前的 `0.035` 作为平台锚点可以继续保留；图片按 `4x` 保持转化，视频按 `5x` 提高安全线，真正需要加强的是“按供应商 route 映射每秒积分”，不要让 WaveSpeed、Replicate 或其他高价 fallback 吃掉低积分档的毛利。
