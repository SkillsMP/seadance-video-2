# 定价策略

定价口诀：统一单位，按贵定价，低价交付，留足利润，积分取整，免费从严，调价发新版。

## 使用前先记住这几个原则

### 原则 1：统一计价单位
先定义一个统一的积分价值，再用它去推导所有模型、套餐和赠送额度。这样用户容易理解，你自己也容易核算毛利。

当前执行建议：
- 先固定“1 积分值多少钱”，再反推各模型消耗多少积分

1 积分值多少钱 的本质不是成本，而是你为了让主销模型和整套梯度好看、好卖、好算，反推出来的统一计价单位

#### 补充：积分锚点价不等于所有套餐实际售价

`1 积分 = $0.035` 只是用于推导模型扣费档位的锚点价，不代表所有套餐都必须按这个价格售卖。

实际经营中需要同时维护三个价格：

| 价格口径 | 用途 |
| --- | --- |
| 积分锚点价 | 用于推导模型扣费档位，例如 $0.035 / 积分 |
| 套餐单积分售价 | 套餐售价 ÷ 套餐积分，用于判断套餐是否健康 |
| 折扣后单积分售价 | 扣除优惠券、Bonus、年付折扣后的真实单价，用于判断是否会被套利 |

所有高成本模型都必须用"最低可能单积分售价"做压力测试，避免年付、Bonus、优惠券叠加之后利润被打穿。

### 原则 2：按最坏成本定价，按最优成本交付
对外定价要参考你能接受的最高稳定成本，而不是只看最便宜的渠道；对内调用时，再优先走便宜且稳定的供应商。

当前执行建议：
- 即使某些渠道更便宜，定价时也优先参考高成本供应商
- 后台用程序做智能路由，优先走低价渠道，把中间差价留作利润和缓冲

通俗理解：
- 先看“这个模型最坏情况下我要花多少钱（美元）”
- 再乘上你希望保留的倍数
- 最后再除以你自己网站定义的“1 积分值多少钱”
- 不要直接拿供应商自己的 `credit` 当你前台的积分单位

计算公式：

```text
用户消耗积分 = ceil((最坏情况下的美元成本 × 目标倍数) ÷ 你自己每积分的美元价值)
```

例子：

```text
某主销图片模型成本：
- 低价稳定渠道 = $0.09
- 中间渠道 = $0.125
- 保守 fallback 渠道 = $0.15

如果按最坏成本 $0.15 计算
目标倍数 = 4x
你自己定义 1 积分 = $0.035

则：
建议积分 = ceil(($0.15 × 4) ÷ 0.035)
         = ceil(17.14)
         = 18

为了更好卖，可以人工调成 20 积分
```

### 原则 3：定价必须给渠道、投放和支付留空间
不能只够覆盖 API 成本。一个能长期跑的价格，必须同时覆盖分销佣金、支付手续费、广告投放和你的净利润。

当前执行建议：
- 普通场景至少按成本的 3 倍思考
- 如果要做分销或投放，优先按 4x-5x 设计
- 一个直观拆法是：1 份给供应商，1 份给分销，1 份给支付/广告，1 份留给自己

### 原则 4：积分必须整数化并向上取整
积分不是拿来追求数学精确的，而是拿来让用户快速理解和购买的。规则越整齐，越容易卖。

当前执行建议：
- 1 积分作为最小单位
- 计算结果一律向上取整
- 优先用 `1 / 2 / 5 / 10 / 25 / 50` 这类好记的数字

### 原则 5：免费额度只给低成本体验
拉新是为了让用户体验价值，不是为了给高成本能力做补贴。免费额度必须严格受控。

当前执行建议：
- 免费赠送优先给最低成本模型
- 高成本模型不要放进默认赠送
- 拉新成本最好控制在一个你能长期承受的固定上限内

### 原则 6：调价发新版本，不直接改老套餐
定价不是一次定死的，但也不能粗暴改老用户。更稳妥的方式是发布新套餐版本，让新老用户逐步迁移。

当前执行建议：
- 成本变化时优先创建 `Plan_V2`、`Plan_V3`
- 老用户保留原权益，新用户走新价格
- 通过升级引导，而不是强制改价


## 1. 定价的三个核心问题

在确定任何定价之前，必须先回答三个问题：

### 我的成本是多少？

每个 AI 模型的 API 调用成本不同，而且同一个模型在不同供应商、不同 route、不同分辨率和时长下都会变。

成本核算时至少记录：

- 供应商
- 模型 / route
- 生成类型：文生图、图生图、文生视频、图生视频等
- 规格：分辨率、时长、是否带音频
- 单次 API 成本
- 是否稳定可用，能否作为默认交付渠道

当前项目的具体供应商报价统一维护在 [2.四平台对比成本价格.md](./2.四平台对比成本价格.md)，最终扣费口径统一维护在 [3.本项目定价方案.md](./3.本项目定价方案.md)。  如果文件名或者路径不对，可能是其它文件路径的文件。

### 我想要多少利润？

建议大多数套餐目标毛利率控制在 50-70%。对于高成本、高波动、强客诉风险的模型，可以要求更高毛利率。

| 策略 | 目标毛利率 | 适用场景 |
| --- | ---: | --- |
| 高毛利策略 | 80-90% | 高端市场、强品牌、低价格敏感用户 |
| 平衡策略 | 50-70% | 推荐默认策略 |
| 增长策略 | 40-50% | 快速占领市场，但需要严格限制高成本模型 |

### 用户愿意付多少钱？

研究竞争对手的定价，了解用户的价值感知。一般图片生成用户对单次生成的心理价位可能在 $0.20-$0.50 之间，高质量图片、视频、商用场景可以更高。该区间只作为定价感知参考，最终仍以成本、竞品和转化数据为准。

## 2. 成本计算公式

### 基础公式

```text
建议积分 = ceil((保守参考成本 × 目标倍数) ÷ 积分锚点价)

其中：
- 积分锚点价：默认可用 $0.035
- 图片常用目标倍数：4x
- 视频常用目标倍数：5x
- 高波动 / fallback route：6x 或人工报价

单次模型毛利率 =
    (扣费积分 × 当前套餐单积分售价 - 实际供应商成本)
    ÷ (扣费积分 × 当前套餐单积分售价)

套餐毛利率 = (套餐售价 - 套餐成本) / 套餐售价 × 100%
```

> 附注：当目标倍数为 `4x` 且 `1 积分锚点价 = $0.035` 时，内部预算成本可粗略按 `$0.00875 / 积分` 估算。
> 但视频、年付、低价套餐和高波动 route 不能直接套用这个值，必须回到通用公式重新核算。

### 倍数选择

倍率决定了你的利润空间和抗波动能力：

| 安全倍数 | 说明 | 适用场景 |
| --- | --- | --- |
| 3x | 更激进，重增长 | 成本稳定、需要快速放量 |
| 4x | 推荐值 | 平衡获客、支付手续费和 fallback |
| 5x | 更保守 | 高波动、高失败率或高客诉模型 |

当前项目的执行版本不直接写在策略文档里。

策略层只保留计算方法：

- 图片优先按 `4x` 设计，兼顾转化和利润空间
- 视频优先按 `5x` 设计，给失败重试、route 波动和高成本 fallback 留缓冲
- 高波动 route / fallback 不进公开低档价格，可以按 `6x` 或人工报价处理
- `1 积分 = $0.035` 可以作为统一价值锚点，但它不是任何供应商的 credit 单价

## 3. 积分系统设计

### 基准模型选择

不要把某一个模型作为永久基准，而是统一用档位管理：

- 图片和视频共用同一套积分余额
- 套餐、扣费、利润率都按积分统一核算
- 模型升级、供应商切换或 route 成本变化时，只维护执行档位表
- 具体模型扣费表只放在项目执行方案里，避免策略文档和执行文档出现两套数字

### 积分消耗规则

具体模型扣费不写死在策略文档里，统一放到另一个文件维护。

策略层只保留这几个分档原则：

| 类型 | 定价逻辑 | 说明 |
| --- | --- | --- |
| 低成本图片 | 低积分档 | 用于拉新、免费体验和轻量试用 |
| 主销图片 | 中等积分档 | 承担主要转化和日常使用 |
| 高阶图片 | 更高积分档 | 覆盖 4K、高成本或高级能力 |
| 入门视频 | 独立视频档 | 只开放成本稳定、规格固定的能力 |
| 主销视频 | 按稳定成本 `5x` 定价 | 不按最低供应商成本定价 |
| 高阶视频 | 高积分档 / 人工报价 | 1080p、音频、长时长、高波动 route 不进低价档 |

### 价格梯度设计

价格梯度应该满足：

- 低档能让用户愿意尝试
- 中档是主推款，单位价格和价值感最均衡
- 高档给重度用户更低单价，但仍然限额，不做无限量
- 视频档位要比图片更保守，避免高成本 route 被低价套餐套利

### 模型权限分层

不是所有套餐都应该开放所有模型。高成本、高波动模型应通过套餐权限控制风险，而不是只靠积分扣费控制。

| 模型类型 | 免费用户 | 低档套餐 | 主推套餐 | 高档套餐 |
| --- | --- | --- | --- | --- |
| 低成本图片 | 可用 | 可用 | 可用 | 可用 |
| 主销图片 | 限制使用 | 可用 | 可用 | 可用 |
| 高阶图片 | 不开放 | 限制使用 | 可用 | 可用 |
| 入门视频 | 不默认开放 | 可少量开放 | 可用 | 可用 |
| 主销视频 | 不开放 | 限制使用 | 可用 | 可用 |
| 高阶视频 | 不开放 | 不开放 | 限制使用 | 可用 / 人工报价 |

原则：高成本能力不只靠积分扣费控制，也要靠套餐权限控制

## 4. 产品定价方案

具体 SKU、价格、积分和毛利率只维护在 具体的文件。

策略文档只保留产品线结构：

| 产品线 | 作用 | 定价原则 |
| --- | --- | --- |
| 一次性积分包 | 承接不想订阅、项目制补量和轻度尝鲜用户 | 单积分价格最高，保留足够毛利 |
| 月付订阅 | 承担主转化和持续使用 | 单积分价格低于积分包，Pro 档作为主推 |
| 年付订阅 | 提升现金流、留存和 LTV | 单积分价格最低，但仍然限额，不做无限量 |

### 套餐梯度原则

- 积分包单价 > 月付单价 > 年付单价
- Basic / Starter 承接首次付费，不要给过低单价
- Pro / Growth 承担主推和补量
- Ultimate / Scale 给重度用户更低单价，但必须控制高成本模型消耗
- 年付可以按“月付 × 10，给 12 个月积分”的方式表达，具体执行仍看最终方案

## 5. 毛利率分析

### 成本基础

毛利率不要只看“套餐平均”，还要看“单次模型压力”。

策略层保留三种口径：

| 口径 | 用途 | 公式 |
| --- | --- | --- |
| 标称毛利率 | 判断积分档位本身是否合理 | `(扣费积分 × 积分锚点价 - 供应商成本) ÷ (扣费积分 × 积分锚点价)` |
| 套餐平均毛利率 | 判断某个套餐整体是否健康 | `(套餐售价 - 套餐积分 × 内部积分成本) ÷ 套餐售价` |
| 单次模型毛利压力 | 判断用户集中消耗某个 route 时会不会亏 | `(扣费积分 × 套餐单积分售价 - 供应商成本) ÷ (扣费积分 × 套餐单积分售价)` |

### 目标毛利率

不同产品线可以接受不同毛利水平：

| 产品类型 | 建议毛利率 | 说明 |
| --- | ---: | --- |
| 一次性积分包 | 65% - 80% | 不订阅也能买，但不应该比订阅划算 |
| 月付订阅 | 55% - 70% | 主转化产品，要兼顾价值感和利润 |
| 年付订阅 | 45% - 60% | 单价最低，主要换现金流和长期留存 |
| 高成本视频 | 60% 以上 | 要额外覆盖失败重试、route 波动和客诉风险 |

### 分析原则

- 套餐平均毛利健康，不代表所有模型都安全
- 如果用户集中消耗高成本视频，必须看单次模型毛利压力
- 主推套餐要看正常转化口径，最低单价套餐要看极限压力口径
- 具体套餐毛利、供应商成本和 route 压力表统一维护在另外的文件

### 套餐压力测试

每个套餐上线前必须做极限压力测试，尤其是年付套餐、促销套餐和含 Bonus 的一次性积分包。

至少检查：

| 测试项 | 判断标准 |
| --- | --- |
| 最低单积分售价 | 是否低于预期安全线 |
| 用户只消耗主销图片 | 是否仍有合理毛利 |
| 用户只消耗主销视频 | 是否会亏损 |
| 用户只消耗最高成本 route | 是否需要限制或人工报价 |
| 折扣 + Bonus 叠加后 | 是否低于年付订阅单价 |
| 失败重试成本 | 是否已经计入视频模型成本 |

安全原则：

- 高成本视频不能只看套餐平均毛利
- 年付套餐必须用最低单积分售价测算
- 促销券、Bonus、订阅折扣不能无限叠加
- 如果某个模型在最低单价套餐下毛利为负，应提高扣费积分、限制使用，或只开放给高档套餐

## 6. 定价调整流程

### 监控阶段（上线 1-2 个月后）

关键指标：

- ✅ 实际 API 成本 vs 预期
- ✅ 用户模型使用分布
- ✅ 实际毛利率
- ✅ 订阅转化率

### 调整信号

| 情况 | 行动 |
| --- | --- |
| 实际毛利 < 目标 10% | 考虑涨价或调整积分消耗 |
| 用户流失率高 | 考虑降价或优化体验 |
| 某模型使用率低 | 调整积分消耗或推广 |
| 某产品滞销 | 调整价格或增加价值 |

### 成本变动触发机制

除了上面的常规信号外，当出现以下情况时，必须重新评估定价，不能等到月度复盘：

| 触发条件 | 处理方式 |
| --- | --- |
| 供应商成本上涨超过 15% | 重新计算模型扣费积分，必要时发布套餐新版本 |
| fallback route 使用率超过 20% | 提高扣费或更换默认 route，避免长期吃高成本 |
| 某模型失败率超过 10% | 暂停推广，重新评估定价倍数和重试策略 |
| 某套餐用户集中消耗高成本模型 | 限制模型权限或调整扣费 |
| 支付手续费 / 退款率明显上升 | 重新计算套餐毛利，必要时调整套餐结构 |
| 广告获客成本上升 | 调整首购优惠和套餐结构，避免免费额度被滥用 |

### 调整方法

⚠️ 重要：不要直接修改现有产品！

正确的调整流程：

- ✅ 创建 v2 产品（如 `pro_monthly_v2`）
- ✅ 新用户使用新产品
- ✅ 老用户可选升级
- ✅ 逐步迁移用户到新产品

## 7. 新用户策略

### 推荐原则

新用户赠送只用于验证产品价值，不用于补贴高成本模型。

⚠️ 重要：只赠送低成本图片，不默认送视频。

### 不同模型的赠送建议

- ✅ 低成本图片：可赠送
- ⚠️ 低成本入门视频：如后续一定要做免费视频体验，只能限次、限活动开放，具体扣费以执行方案为准
- ❌ 标准视频、主销视频和高阶视频：不赠送

高成本模型会让新用户赠送迅速变成营销成本黑洞。

### 成本考量

| 类型 | 成本特征 | 建议 |
| --- | --- | --- |
| 低成本图片 | 单次成本低、失败重试可控 | 可赠送 |
| 入门视频 | 单次成本和失败重试成本都更高 | 仅限活动、限次数 |
| 标准 / 主销视频 | 成本明显高于图片，且 route 波动更大 | 不默认赠送 |
| 高阶视频 | 分辨率、音频、时长都会放大成本 | 不赠送，只面向付费用户 |

### 目的

- ✅ 让用户体验核心功能
- ✅ 降低首次使用门槛
- ✅ 引导首次付费

## 8. 订阅积分、有效期与退款规则

订阅卖的是持续使用权，不是无限期储值卡。AI 生成产品又容易遇到失败、超时、违规等问题，因此积分发放、有效期和退款规则必须在上线前就明确。

### 8.1 订阅积分发放与有效期

| 规则 | 建议 |
| --- | --- |
| 月付积分 | 每个计费周期发放，当周期有效 |
| 年付积分 | 可按月发放，避免用户一次性消耗完后退款或流失 |
| 未用完积分 | 默认不无限滚存，可允许滚存 1 个周期或设置上限 |
| 取消订阅 | 当前周期权益保留，到期后停止发放 |
| 升级套餐 | 可立即补差价并发放差额积分 |
| 降级套餐 | 下个计费周期生效 |
| 一次性积分包 | 可设置较长有效期，例如 6-12 个月 |

原则：

- 年付订阅不要一次性把 12 个月积分全部发完，除非已有完善的风控和退款规则
- 积分滚存上限要写进套餐说明，避免用户预期混乱
- 升降级和过期规则必须在结算页和邮件提醒中清晰告知

### 8.2 退款、失败与重试规则

AI 生成失败会直接影响成本和用户体验，必须提前定义扣费规则，不能临时口头处理。

| 场景 | 建议处理 |
| --- | --- |
| API 明确失败且未产生成本 | 自动退还积分 |
| API 失败但供应商已收费 | 可按产品策略决定是否补偿，不能无上限重试 |
| 生成超时 | 优先重试一次，仍失败则退还积分或发放补偿 |
| 用户主观不满意 | 默认不退积分，可通过重新生成引导 |
| 内容违规被拦截 | 不生成则不扣费；已调用供应商则按实际情况处理 |
| 用户重复提交 | 正常扣费，需要前端做二次确认 |
| 高成本视频失败 | 必须限制自动重试次数 |

原则：

- 低成本图片可以适度宽松，自动重试 + 自动退积分
- 高成本视频必须从严，自动重试次数计入定价倍数
- 任何"宽松退款"都要在套餐说明里明确，避免成为套利入口

## 9. 优惠券、折扣与 Bonus Credits

优惠券和 Bonus 不是简单降价，而是会直接影响"折扣后单积分售价"。一旦多种优惠叠加，就可能跌穿年付主推套餐的安全线，是上线后最容易让利润失控的部分。

### 9.1 折扣与优惠券规则

建议规则：

- 优惠券默认只作用于首月或首单
- 年付折扣和大额 Bonus 不默认叠加
- 订阅折扣和一次性积分包 Bonus 分开管理
- 所有折扣后都必须重新计算最低单积分售价
- 折扣后单积分售价不能低于年付主推套餐的安全线
- 高成本视频用户不参与深度折扣活动，或需要限制使用额度

折扣上线前必须检查：

```text
折扣后单积分售价 = 实付金额 ÷ 实际到账积分
```

如果该值低于安全线，则需要减少 Bonus、提高扣费积分，或限制高成本模型使用。

### 9.2 Bonus Credits 策略

> 一句话：Bonus Credits 优先用于一次性充值包；订阅不叠加或只小额叠加。

适用阶段：初始阶段可暂不启用，等套餐结构和成本数据稳定后再开放。

设计要点：

- **差异化显示**：充值包页面突出"额外赠送"和"折后单价"；订阅页面突出"最低单积分价"和"长期价值感"，两条路径不要互相抢用户
- **防止套利**：一次性积分包加上 Bonus 后，单价必须不低于年付订阅的平均单价，否则老用户会放弃订阅去买充值包，月活和留存数据会下滑
- **订阅者特权充值**：可以给订阅用户提供专属 Bonus 充值通道（例如订阅者充值额外 +5%），用来增加订阅粘性，而不是给所有人发同样的 Bonus
- **可叠加范围明确化**：Bonus 与优惠券、年付折扣是否叠加，必须写死规则，不留运营临时口头空间

总体逻辑：一次性充值靠 Bonus 拉客单价，订阅靠低单价拉长留存，两条线分开做利润最大化。

## 10. 常见问题

### Q: 如何确定基准积分？

查询 API 成本后：`建议积分 = ceil((保守参考成本 × 4) ÷ 0.035)`，然后再向上归到标准档位。

例如：API 成本 $0.15 → `(0.15 × 4) ÷ 0.035 ≈ 17.1`，最终定到 `20 积分` 档。

### Q: 年付应该给多少折扣？

标准做法：年付 = 月付 × 10（买 10 送 2，省 2 个月）

也可以理解为：用户付 10 个月的钱，拿 12 个月的积分，折扣约 16.7%。具体月付价、年付价和积分发放以 [3.本项目定价方案.md](./3.本项目定价方案.md) 为准。

### Q: 积分包应该比订阅贵多少？

建议一次性积分包单价比对应月付贵 25-35%：

- 小额积分包：比订阅入口价更贵，承接尝鲜用户
- 中额积分包：适合项目制补量，但不要比主推订阅划算
- 大额积分包：可以接近月付高档单价，但不要低于年付主推单价

### Q: 如何处理免费用户？

- 新用户赠送只开放低成本图片
- 默认不送免费视频
- 一次性积分包可以直接购买，但订阅应保持更好的长期单价
