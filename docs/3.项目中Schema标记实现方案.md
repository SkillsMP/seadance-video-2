> v3 调整：BreadcrumbList 提升为 P0，与 WebSite 并列优先实施；Article Phase 取消前置数据建模，改为在 schema.ts 内容错解析日期。

## 现状分析

项目当前的 SEO 层只包含：
- `generateMetadata` → title / description / keywords / OG / Twitter Card / canonical / hreflang

**缺少 JSON-LD 结构化数据**，导致：
- Google 无法识别站点名称（Site Name）与品牌实体
- 博客文章缺失 Article 富摘要候选资格
- AI 工具页缺失 SoftwareApplication 评分/价格展示能力
- 面包屑无法在搜索结果中展示层级路径

---

## 优先级规划（修订版）

> **变更说明**：
> - `FAQPage` 从 P0 降至 P2：Google 自 2023-08 起将 FAQ 富摘要**仅对政府/权威健康类站点开放**，商业 AI 工具站点几乎不会获得该展示位。保留实现作为辅助，不作为主 ROI 项。
> - `SearchAction` 已**移除**：Google 于 2024-11-21 正式下线 sitelinks search box；项目亦无公开 `/search` 路由。
> - `WebSite` + `BreadcrumbList` 并列 **P0**：两者改动极小、全站受益、100% 稳定生效，合并至 Phase 1 优先实施。
> - `Organization` 随 Phase 1 一并实施（与 WebSite 共享注入点，零额外成本）。
> - `Article` 降为 P1（独立 Phase），**取消前置数据建模**：日期解析在 `schema.ts` 内完成，不修改现有模型文件。

| Schema 类型 | 应用范围 | 主要收益 | 优先级 |
|---|---|---|---|
| **WebSite** | 全站 | Site Name 品牌名在搜索结果稳定展示 | 🔴 P0 |
| **BreadcrumbList** | 所有页面 | 搜索结果面包屑路径，全站受益，改动极小 | 🔴 P0 |

## 核心设计原则

### 1. 数据单一来源
Schema 数据应从**已有 i18n JSON 自动生成**，而不是维护两套数据：

```
i18n JSON / envConfigs / DB (source of truth)
    ↓
自动转换为 JSON-LD Schema（构建函数层）
    ↓
注入到 <head> 的 <script type="application/ld+json">
```

**好处**：
- FAQ question/answer 已在 i18n JSON，无需重复维护
- 页面 title/description 已在 metadata，自动复用
- 单一改动点，保证一致性

### 2. 零 i18n JSON 改动
实现 schema 时**不需要修改现有 i18n JSON 格式**。所有 schema 由构建函数层自动生成。

**例外**：Article 需要在博客数据模型中补充 ISO 8601 格式的日期字段（见 Phase 2）。

### 3. 渐进式实施
从全站级 WebSite + Organization 开始（成本最低、收益最确定），再逐步扩展。

## 实现细节

### Layer 1：Schema 构建函数

**文件**：`src/shared/lib/schema.ts`

**核心示例**：

```typescript
// WebSite: 全站级 — 仅用于 Site Name，不含 SearchAction
// ⚠️ SearchAction / sitelinks search box 已于 2024-11-21 被 Google 下线，勿添加 potentialAction
export function buildWebSiteSchema(config: {
  name: string;
  url: string;
}) {
  return {
    '@context': 'https://schema.org',
    '@type': 'WebSite',
    name: config.name,
    url: config.url,
  };
}

// Organization: 品牌实体
// 最小集：name / url / logo；如有 sameAs（社媒主页）可补充以增强知识面板
export function buildOrganizationSchema(config: {
  name: string;
  url: string;
  logo: string;
  sameAs?: string[];
}) {
  return {
    '@context': 'https://schema.org',
    '@type': 'Organization',
    name: config.name,
    url: config.url,
    logo: config.logo,
    ...(config.sameAs?.length ? { sameAs: config.sameAs } : {}),
  };
}

// BreadcrumbList: 面包屑
export function buildBreadcrumbSchema(items: { name: string; url: string }[]) {
  return {
    '@context': 'https://schema.org',
    '@type': 'BreadcrumbList',
    itemListElement: items.map((item, index) => ({
      '@type': 'ListItem',
      position: index + 1,
      name: item.name,
      item: item.url,
    })),
  };
}

// Article: 博客文章
// ⚠️ 前提：post 必须提供 ISO 8601 格式的 datePublished（见 Phase 2 数据建模）
export function buildArticleSchema(post: {
  title: string;
  url: string;
  datePublished: string;   // ISO 8601, e.g. "2025-01-15T08:00:00Z"
  dateModified?: string;   // ISO 8601
  authorName: string;
  image?: string;
  description?: string;
}) {
  return {
    '@context': 'https://schema.org',
    '@type': 'Article',
    headline: post.title,
    url: post.url,
    datePublished: post.datePublished,
    ...(post.dateModified ? { dateModified: post.dateModified } : {}),
    author: { '@type': 'Person', name: post.authorName },
    ...(post.image ? { image: post.image } : {}),
    ...(post.description ? { description: post.description } : {}),
  };
}

// FAQPage: 辅助型结构化数据（P2）
// ⚠️ Google 自 2023-08 起仅对权威政府/健康站点开放 FAQ 富摘要；商业 AI 站点不保证获得展示位
// ⚠️ answer 字段可保留 HTML 内容（Google FAQ 文档允许）；只做空值过滤，不剥离标签
export function buildFaqSchema(
  items: Array<{ question?: string; answer?: string }>
) {
  const valid = items.filter(
    (item): item is { question: string; answer: string } =>
      Boolean(item.question) && Boolean(item.answer)
  );
  if (valid.length === 0) return null;

  return {
    '@context': 'https://schema.org',
    '@type': 'FAQPage',
    mainEntity: valid.map(item => ({
      '@type': 'Question',
      name: item.question,
      acceptedAnswer: {
        '@type': 'Answer',
        text: item.answer,  // 保留原始内容，包含 HTML 均可接受
      },
    })),
  };
}
```

### Layer 2：JsonLd 通用注入组件

**文件**：`src/shared/components/seo/json-ld.tsx`

```typescript
// 接受 null 以允许构建函数在数据不足时返回 null（如 FAQ 无有效条目）
export function JsonLd({ data }: { data: Record<string, unknown> | null }) {
  if (!data) return null;
  return (
    <script
      type="application/ld+json"
      dangerouslySetInnerHTML={{ __html: JSON.stringify(data) }}
    />
  );
}
```

### Layer 3：集成到页面

**方式 1：全站级** (`src/app/layout.tsx`)

> ✅ **正确注入点**：`src/app/layout.tsx`（根布局，L110-L148）。该文件有真正的手写 `<head>` 块，已注入 ads/analytics scripts，`envConfigs` 已 import，`getLocale()` 已调用。
>
> ⛔ **不要用** `src/app/[locale]/layout.tsx`：该文件的 `return` 只有 `NextIntlClientProvider / ThemeProvider / AppContextProvider` 三层 Provider 包裹，**没有 `<head>` 标签**。在此插入 `<JsonLd />` 会渲染到 `<body>` 内，Google 不接受 `<body>` 中的 JSON-LD。

```tsx
// src/app/layout.tsx — 在现有 <head> 块内，紧接 customerServiceHeadScripts 之后追加：

{/* inject site-wide JSON-LD structured data */}
<JsonLd data={buildWebSiteSchema({
  name: envConfigs.app_name,
  url: envConfigs.app_url,
})} />
<JsonLd data={buildOrganizationSchema({
  name: envConfigs.app_name,
  url: envConfigs.app_url,
  logo: `${envConfigs.app_url}/logo.png`,
})} />
```

**方式 2：动态页面 FAQ schema** (`src/themes/default/pages/dynamic-page.tsx`)

> ⚠️ `dynamic-page.tsx` 使用 `Object.keys(page.sections).map(key => ...)` 动态渲染 block，**不能**假设 `page.sections.faq` 固定存在。
>
> ⛔ **不要用** `sections.find(s => s.type === 'faq')`：`Section` 接口（`src/shared/types/blocks/landing.d.ts`）只有 `id?` 和 `block?` 字段，**没有 `type`**，该表达式永远为 `undefined`，导致 `faqSchema` 始终为 `null`。
>
> ✅ **正确做法**：用 `Object.entries` 同时拿到 key 和 section 对象，检查 `section.block`、`section.id` 或 key 名称。

```tsx
// 正确：通过 block / id / key 三重判断找到 faq section
const faqEntry = Object.entries(page.sections ?? {}).find(
  ([key, section]) =>
    section.block === 'faq' || section.id === 'faq' || key === 'faq'
);
const faqSchema = faqEntry?.[1]?.items
  ? buildFaqSchema(faqEntry[1].items)
  : null;

return (
  <>
    {faqSchema && <JsonLd data={faqSchema} />}
    {/* 原有 sections 渲染逻辑不变 */}
  </>
);
```

### Phase 2（P1）：Article — 博客富摘要

**日期处理说明**：`getPost()` / `getLocalPost()` 返回的 `created_at` 是已格式化的展示字符串（`"Apr 4, 2026"` 或 `"2026/04/04"`）。**不修改现有模型**，在 `buildArticleSchema()` 内部用 moment 容错解析：

```typescript
// schema.ts 内部辅助函数，不暴露到外部
function toISODate(dateStr: string): string {
  const parsed = moment(dateStr, ['MMM D, YYYY', 'YYYY/MM/DD', moment.ISO_8601]);
  return parsed.isValid() ? parsed.format('YYYY-MM-DD') : '';
}
```

**修改文件（1 处）**：
- `src/app/[locale]/(landing)/blog/[slug]/page.tsx`：在已有 `getPost()` 调用之后，构建 Article schema 并注入 `<JsonLd />`

**完成标志**：Google Rich Results Test 可在博客详情页识别 Article 类型，`datePublished` 为合法 ISO 日期

**预期收益**：博客文章获得 Article 富摘要候选资格，搜索结果可展示发布日期
