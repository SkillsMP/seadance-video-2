> 日期：2026-10-22（文档同步：同日末）  
> 状态：生产候选主题为 `flow`（`.env.development` 已切 `flow + dark`）。P0 / 大部分 P1 **已在 `src/themes/flow/` 落地**；§8 客户端与生产构建仍待实测。  
> 目标：把「半套 Flow + 半套本站」收成可接受的成品站，**不**追求整页克隆参考站，**不**改动登录 / 积分 / 支付 / `VideoGenerator` 内部逻辑。

**实施边界**：改动优先且默认仅限 `src/themes/flow/`；locale 中模型页 `examples` 的 `columns` 等与 Flow 展示一致时，可改 **en/zh `seedance-2-0.json`**（不为了 Flow 改 `index.json` 的 `show_sections` / `compact`）。不碰 `dynamic-page`、共用 generator 逻辑、core/theme。参考 videofly 结构时**禁止**跨主题 import。P2（token / 删 queue）默认不做，除非单独立项。

**工程平衡**：小 diff、主题内聚；能用 CSS / 现有 block 解决的，不新建抽象层。

## 1. 结论：选 Flow 对不对？

**对。** Flow 有独立的琥珀色 token、`.flow-*` 组件类、暗/浅双套样式，符合偏好简单组件与黄边的方向。实际性能需测量，不能仅凭组件或动效数量断言比 videofly 更快。

维护说明：`reference-notes` / 源码 diff 是**移植验收依据**，不是日常维护流程。定版后按普通主题改文案、颜色、间距即可；只有主动同步上游参考仓时才再对照。

当前半成品感主要来自**接缝**（多数已收口），不是「主题选错」：

- 真实生成器仍由 `page.tsx` 注入 → 已用 `#generator > section` 单列卡片壳衔接（**未**使用 `.flow-studio`）  
- 模型页 specs / model-faq / related 仍为 default 块 → 已用 `#specifications`、`#faq:not(.flow-section)`、`#related-resources` 等局部 CSS  
- 视频墙 → 已读 JSON `columns`；首页 2×2，模型页 `#examples` 为 **3 列** + 作用域样式（见 §3.2）  
- Hero 与生成器之间的氛围 → `.flow-main::before` 共享顶区光晕，`.flow-hero` 背景透明

## 2. 工程事实（改之前先记住）

| 事实 | 含义 |
|------|------|
| 渲染顺序 = `sections` **对象键顺序** | `Object.keys(page.sections)` |
| `show_sections` **只过滤显隐，不排序** | 改数组顺序**不会**改变页面区块顺序 |
| `index.json` / `seedance-2-0.json` **多主题共用** | 改 `sections` 键顺序会影响 default / video / videofly / flow |
| 首页 `sections` 键现状 | 已是 `hero → generator → showcases → …` |
| Showcase 素材 | 首页 `showcases`、模型页 `examples` 均为 **4 条** webm + poster |
| JSON `columns` | 首页 **`columns: 2`**；模型页 **`examples.columns: 3`**（en/zh 已同步）；`features` **`columns: 4`** |
| Flow 视频墙 | `showcases.tsx` 传 `columns` → `FlowShowcase`；`columns === 2` 时加 `flow-video-grid--cols-2`；否则桌面默认 **三列** |
| Hero / CTA 主按钮 | 类名 `flow-generate`，背景 **`--flow-gradient`（紫粉）**，不是 `--primary`；次按钮 **`flow-btn-outline`**（`flow-hero-actions`） |
| 模型 FAQ JSON-LD | 由 `/seedance-2-0/page.tsx` 注入 FAQPage；Flow block 只负责 `<details>` 展示，不改 schema |

完成线：

> 首页 + `/seedance-2-0`：Flow 外壳连贯；生成器不突兀；Use Cases 有卡片+关键词；specs/FAQ 不丑即可。  
> **不**要求整页像素级等同 flowaivideo.lol。

## 3. P0：立刻做（按顺序）

### 3.1 生成器衔接（最优先）— **已实现**

**问题**：Hero 只有标题+按钮；紧随其后的生成器使用 ShipAny 默认外观，需要协调两者的边框、背景与间距。

**做法——纯 CSS，零改 TSX**：`#generator` 在 `.flow-shell` 内，规则在 [`styles/flow.css`](styles/flow.css)。以下数值为当前实现，可在桌面和手机继续微调；不强制负边距，不覆盖生成器内部已有网格。

**Hero / 主内容氛围**（与生成器 sibling 关系）：

- `.flow-main::before`：Hero + 生成器上方共享紫粉 radial 光晕，向下 mask 淡出（在 Examples 前收束）  
- `.flow-hero`：`background: transparent`，避免与光晕叠两层  

DOM：

```text
#generator
  └── <section class="py-8 md:py-10 …">   ← 根是 section，不是 div
```

```css
.flow-shell #generator {
  width: 100%;
  max-width: var(--flow-shell-max);
  margin-inline: auto;
  margin-block: 0 3rem;
  padding-inline: 1rem;
}

@media (max-width: 640px) {
  .flow-shell #generator {
    padding-inline: 0.5rem;
  }
}

.flow-shell #generator > section {
  border: 1px solid var(--border);
  border-radius: var(--radius);
  background: color-mix(in oklab, var(--card) 92%, transparent);
  box-shadow: 0 24px 60px -40px rgba(0, 0, 0, 0.9);
  padding-top: 1.25rem;
  padding-bottom: 2rem;
}

.dark .flow-shell #generator > section {
  border-top-color: color-mix(in oklab, var(--flow-amber) 35%, var(--border));
  box-shadow:
    0 0 50px -20px color-mix(in oklab, var(--flow-amber) 15%, transparent),
    0 24px 60px -40px rgba(0, 0, 0, 0.9);
}
```

内层 `[data-slot='card']` 已去掉多余 border/shadow，避免「卡片套卡片」。

**壳级细节**：`.flow-shell` 使用 `scrollbar-width: thin` + 低对比 `scrollbar-color`（Firefox 等支持处生效）。

**禁止**（仍有效）：

- 给 `#generator` 添加或外包 **`.flow-studio`**：桌面是 **7:5 双列网格**，只放一个生成器会占左列、右侧空白。  
- 使用 `#generator > div`（选不中）。  
- 改 `VideoGenerator` 内部逻辑。

**仅 CSS 不够时**：先说明具体限制与所需修改范围，不直接修改 `page.tsx`。如确认需要增加外壳，也必须是**单列全宽**，不使用 `flow-studio`。

**做法（不补 6 条、不为 Flow 改首页 JSON 结构）**：

## 5. P2：配色与清理（不改善首屏时不必抢跑）

### 5.1 Token：区分 `--primary` 与主按钮渐变

**事实**：

- Hero / CTA 主按钮 → `.flow-generate` → **`background: var(--flow-gradient)`**（紫粉，原站设计）。  
- 改一行浅色 `--primary` **不会**把主 CTA 改成琥珀。  
- 浅色 `--primary` 仍是紫（277）时，会影响 Tailwind/shadcn 等用 `--color-primary` 的控件，并与 `--flow-amber`（序号、FAQ 等）可能不一致。

**默认策略（保原站）**：**保留 `--flow-gradient` 主按钮，也先保留现有浅色 `--primary`。** 紫色与琥珀色并存不直接视为 bug；先看浅色实际效果，再决定是否需要统一。

浅色配色调整（可选，需明确决定后再改，单独验收）：

- 若浅色实测确认需要统一非渐变控件：调整 `--primary`，同时核对 `--primary-foreground`、`--ring`、文字对比度和焦点状态。  
- 若要求 **主按钮也统一琥珀**：单独立项改 `.flow-generate` / `--flow-gradient`（及 hover/disabled），并检查文字、焦点和对比度；不能假设改 `--primary` 即可。

### 5.2 清理无用 queue CSS

先检索确认没有运行时引用，再按选择器清理无用的 `.flow-queue`、`.flow-queue-bar` 等 queue 样式，不按固定行号整段删除。未命中的 CSS 本身不会呈现假队列，此项仅是 P2 清理。**保留** `.flow-studio` / `.flow-card` / `.flow-generate` 定义；**不要**整段删 studio 区块（生成器仍禁止套用 studio 布局）。
